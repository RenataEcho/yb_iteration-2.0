# 右豹管理后台 - 迭代后台 PRD

## 1. 背景

右豹管理后台作为可持续迭代的统一后台，后续会继续加入其他业务功能。本期包含一级菜单“积分管理”“工具管理”“埋点统计”和“迭代需求”。积分管理承接用户端“积分中心”相关能力，包括积分余额展示、积分充值/兑换、兑换码兑换、积分明细、任务领奖励、钱包扣款支付等流程；工具管理承接工具入口配置、标签管理和工具数据统计；埋点统计承接首页、变现、项目入口、Banner、工具和冷启动链路的事件数据分析；迭代需求承接专项业务迭代，当前二级菜单包含“实名相关”和“导师优化”。

## 2. 产品目标

- 支持积分商品档位、价格、标签、购买人数、上下架与展示顺序配置。
- 支持兑换码批量生成、导入、发放、核销、冻结与追踪。
- 支持任务奖励规则配置，包括任务门槛、奖励积分、达标人数、启用/禁用状态。
- 支持用户积分账户查询、手动调账、冻结积分与余额校验。
- 支持积分流水、兑换订单、钱包扣款记录查询和对账。
- 支持钱包支付来源与组合支付展示配置；支付密码、失败次数、锁定策略等支付安全由后端逻辑处理，不在后台侧写入。
- 提供运营数据看板，帮助判断积分发放、消耗、转化与异常情况。
- 支持工具列表配置，包括工具名称、图标、平台、区域、赛道、标签、评分、热度、状态、可见范围、排序、跳转和使用门槛。
- 支持工具标签管理和工具数据统计，工具数据按今日、近 7 日、累计三个时间维度统计点击量、使用量、获得积分和变现。
- 支持埋点统计看板，帮助运营查看核心事件趋势、冷启动激活、页面事件表现、业务漏斗转化和埋点质量。
- 支持数据分析师按事件、页面、模块、用户类型、渠道、项目和工具维度进行筛选、导出和口径核查。
- 支持迭代需求沉淀专项业务改造，当前包含实名相关共存需求、流程跳转梳理和导师换绑优化。

## 3. 用户角色

- 运营：配置积分商品、任务奖励、兑换码活动、工具入口、工具标签、页面文案和活动状态。
- 数据分析师：查看埋点统计、核对事件口径、分析转化漏斗、发现缺参/重复/异常波动等数据质量问题。
- 客服：查询用户积分余额、流水、订单状态，处理补发、撤销、冻结等问题。
- 财务：查看支付金额、钱包扣款、退款、对账导出。
- 产品/运营：查看迭代需求、实名共存规则和审核结果页状态说明。
- 管理员：管理角色权限和系统开关。

## 4. 前端功能理解

### 4.1 积分中心

用户可看到当前“右豹积分”余额，选择不同积分档位进行兑换。档位中包含积分数量、售价、推荐标识。页面下方展示“完成任务得积分”，任务有门槛、奖励积分、领取/未完成状态。

### 4.2 兑换码弹窗

用户点击“兑换码”后弹出输入框，输入兑换码后可立即兑换。弹窗提供获取链接复制能力。

### 4.3 积分明细

用户可按“全部 / 消耗 / 获得”筛选积分流水。流水包含来源、时间、积分变动值，正数高亮，负数普通展示。

### 4.4 钱包扣款兑换

用户点击立即兑换后进入钱包扣款确认。用户选择扣款钱包，输入支付密码，完成扣款后获得积分。截图中可见钱包类型包括项目收益钱包、团队奖励钱包、分红奖励钱包和组合支付。

### 4.5 实名认证共存

用户实名支持个人实名与企业实名共存。用户在任一认证结果通过后，另一种实名结果仍可继续保留和补充。后台本期只承接流程跳转、结果页状态和展示口径，不设计选择认证方式页和资料填写页。

## 5. 管理后台功能范围

### 5.0 通用交互

- 后台命名为“右豹管理后台”。
- 侧边栏采用一级/二级菜单结构；本期包含一级菜单“积分管理”“工具管理”和“埋点统计”。
- 一级菜单支持展开/折叠操作，展开后展示二级菜单，折叠后隐藏二级菜单。
- 当前所有积分相关菜单均归属在“积分管理”下，作为二级菜单展示。
- “积分管理”下新增二级菜单“前后端交互需求”，用于说明用户端积分功能的前端规则、接口字段、状态流转和异常处理。
- “工具管理”下包含二级菜单“工具列表”“工具数据”和“前端交互需求”；其中“前端交互需求”用于展示工具使用门槛交互 demo。
- “埋点统计”下包含二级菜单“统计总览”“埋点事件需求”“冷启动分析”“页面事件分析”“转化漏斗”“事件质量”“经营分析”。
- “迭代需求”下包含二级菜单“实名相关”和“导师优化”，分别用于沉淀实名专项改造需求和导师换绑优化需求。
- 菜单结构需为后续增加其他一级业务模块预留扩展空间。
- 每个菜单标题旁展示“需求规则”入口。
- 点击“需求规则”后，通过右侧抽屉展示当前板块的规则说明。
- 规则抽屉内容随当前菜单变化，采用“需求梳理 / 编号标题 / bullet 列表”的形式，帮助运营、产品、研发快速确认该板块配置边界。

### 5.1 数据看板

- 展示核心指标：今日发放积分、今日消耗积分、累计发放积分、累计消耗积分、兑换收入、兑换码核销。
- 支持按日期、渠道、活动筛选。
- 提供近 7 日发放/消耗趋势和积分商品转化排行。

### 5.2 积分商品管理

- 新增、编辑、复制、上下架积分商品。
- 字段：商品名称、积分数量、售价、标签、购买人数、展示排序、总库存、状态。
- 标签可为空；可选值为“推荐”“上新”“限时活动”。
- 支持配置购买前协议勾选项。
- 支持预览用户端展示效果。

### 5.3 兑换码管理

- 支持批量生成兑换码。
- 支持导入外部兑换码。
- 字段：批次名称、码类型、面额积分、有效期、发放对象、使用次数、状态。
- 积分面额支持两种配置方式：选择积分商品批次，或自定义输入积分数额。
- 支持兑换限制开关。关闭时不限制单用户兑换次数；开启时需配置“每个用户可兑换 X 次”，表示该批次兑换码每个用户最多可兑换的次数。
- 支持单码查询、核销记录、冻结、作废。
- 支持导出兑换码及核销明细。
- 新增兑换码配置通过弹窗完成，不在页面右侧常驻表单。
- 兑换码后台不设置审批字段。

### 5.4 任务奖励管理

- 配置任务名称、任务说明、完成条件、阈值、单位、奖励积分、达标人数、状态。
- 完成条件固定为“有效拉新”和“项目出单”。
- 有效拉新单位为“人”；项目出单单位为“元”。
- 当完成条件选择“项目出单”时，必须选择项目。项目下拉来自品牌项目列表，当前 mock 数据为：番茄小说、红果短剧、红果漫剧、知乎故事、知乎知识。
- 任务状态只有“启用”和“禁用”，不设置审核相关状态。
- 达标人数表示当前满足该任务条件的用户人数。
- 支持任务启停、排序和人群范围。

### 5.5 用户积分账户

- 支持按用户 ID、手机号、昵称搜索。
- 展示可用积分、冻结积分、累计获得、累计消耗、最近变动时间。
- 支持人工调账：增加、扣减、冻结、解冻。
- 调账必须填写原因，较大金额需要审批。
- 支持查看该用户全部积分流水和兑换订单。

### 5.6 流水与订单

- 积分流水：获得、消耗、冻结、解冻、撤销。
- 兑换订单：订单号、用户、商品、积分数量、支付金额、钱包来源、状态、创建时间。
- 钱包扣款：扣款钱包、扣款金额、扣款状态、失败原因。支付密码校验结果属于后端支付安全逻辑，不在后台配置项中维护。
- 流水订单状态字段只展示“成功”和“失败”。
- 失败记录鼠标悬浮状态标签时展示失败原因。
- 支持导出、重试、退款、撤销发放等操作。

### 5.7 钱包与支付配置

- 配置可用于积分兑换的钱包类型。
- 配置扣款优先级：单钱包支付或组合支付。
- 支付密码校验开关、失败次数限制、锁定时长、扣款失败重试策略由后端逻辑统一处理，后台不提供写入入口。

### 5.8 前后端交互需求

- 该菜单用于沉淀用户端积分功能需求，包含前端页面需求、前后端接口契约、字段规则、状态规则、异常处理和幂等要求。
- 前端页面范围包括积分中心首页、兑换码弹窗、积分明细页、钱包扣款兑换弹窗和任务奖励列表。
- 积分中心首页展示页面标题、返回按钮、明细入口、规则入口、右豹积分余额、积分商品卡片、协议勾选、兑换码按钮、立即兑换按钮和任务奖励列表。
- 积分商品只展示上架状态；标签仅支持推荐、上新、限时活动，标签为空时用户端不展示。
- 兑换码弹窗包含兑换码输入、兑换码获取链接、取消和立即兑换；兑换失败时弹窗不关闭并展示后端失败原因。
- 积分明细支持全部、消耗、获得三类筛选；获得显示正数，消耗显示负数；失败流水默认不进入用户可见明细。
- 钱包扣款弹窗展示项目收益钱包、团队奖励钱包、分红奖励钱包和组合支付；余额不足或后台关闭的钱包不可选。
- 支付密码为 6 位数字输入；密码校验、失败次数、锁定和扣款重试由后端处理，前端不得保存或上报明文密码。
- 任务奖励仅展示启用状态任务；用户端领取状态由后端计算为可领取、未完成、已领取。
- 前端初始化需并行拉取用户积分账户、上架商品、启用任务和钱包概览。
- 核心接口包括账户查询、商品列表、任务列表、流水分页、兑换码兑换、创建兑换订单、订单支付和任务领取。
- 发放类接口必须支持幂等键，前端提交中禁止重复点击，成功后刷新余额、明细和当前业务对象状态。
- 扣款成功但积分发放失败时，前端展示处理中状态；后台流水订单中记录失败原因，便于客服追踪。

#### 5.8.1 重要规则：钱包收益明细

- 凡是在端内完成支付购买积分的订单，后端必须在对应扣款钱包的收益明细中增加一条记录。
- 单钱包支付时，收益明细标题固定为“积分购买”。
- 单钱包支付时，收益明细描述按购买积分数生成，例如“购买积分880”。
- 组合支付时，每个参与扣款的钱包都需要写入收益明细记录。
- 组合支付的收益明细描述需包含组合支付和参与钱包，例如“组合支付购买积分880,与项目收益钱包组合购买”。
- 收益明细记录需与积分购买订单、钱包扣款流水、积分入账流水保持同一业务关联编号，便于客服和财务追踪。
- 如果积分发放成功但钱包收益明细写入失败，后端需进入补偿队列并在流水订单中记录异常原因。

### 5.9 工具列表

- 支持工具查询、新增、编辑、删除、上下架和标签管理。
- 查询字段包含名称、区域、所属平台、赛道和状态。
- 列表字段包含序号、图标、名称、所属平台、区域、赛道、标签、评分、热度、状态、可见范围、排序、更新时间和操作。
- 工具新增/编辑弹窗参考截图，拆分为“基础信息”和“数据跳转”两个板块。
- 弹窗内文字输入、下拉选择、数字输入等基础组件宽高需保持一致，保证配置区视觉稳定。
- 基础信息用于维护工具基础配置，字段包含所属平台、工具名称、区域、一级赛道、状态、图标、排序、标签、金句、简介和详情。
- 标签字段为下拉选择组件，从已启用工具标签中选择。
- “金句”“简介”“详情”使用横向 Tab 切换配置，默认进入金句 Tab；每个 Tab 内只展示对应配置组件，不重复展示字段标题，切换 Tab 时保留当前已输入内容。
- “图标”字段为图片上传字段；建议上传 1:1 比例 PNG/JPG 图片，保存后在工具列表和工具数据中展示。
- 数据跳转字段包含评分、热度、NEW 角标、开发者、开发者等级、跳转类型、跳转链接、是否可见和使用门槛。
- “是否可见”支持多选配置，选择项包括全部、团等级、个人等级和指定用户 ID。
- 选择“全部”时表示全量用户可见，不需要继续配置等级。
- 选择“团等级”时支持 V1、V2、V3 多选。
- 选择“个人等级”时支持 L1、L2、L3、L4、L5、L6、L7 多选。
- 选择“指定用户 ID”时支持录入一个或多个用户 ID，多个 ID 用英文逗号分隔。
- 使用门槛包含“完全免费”和“积分使用”。选择“完全免费”时不需要配置消耗规则；选择“积分使用”时必须配置“每日可免费次数”和“单次消耗积分”。
- 每日可免费次数必须为大于等于 0 的整数；单次消耗积分必须为大于 0 的整数。
- 保存工具时需校验必填项和数字范围，保存成功后刷新工具列表，并同步刷新工具数据页中的工具名称、图标和统计行。
- 标签管理弹窗字段包含名称、排序、状态和操作，支持新增标签、编辑标签、删除标签。
- 状态包含上架和下架；上架工具可在用户端展示，下架工具不展示。
- 可见范围需在列表中展示最终生效值，如“全部”“团等级:V1、V2”“个人等级:L1、L3、L7”“指定用户ID:10001,10002”。

### 5.10 工具数据

- 工具数据用于按工具维度查看运营表现。
- 看板统计组件按时间维度平铺展示，包含今日、近 7 日、累计三个统计卡片，并自适应页面宽度。
- 今日和近 7 日统计卡片内合并展示点击量和使用量，展示格式为“点击量 / 使用量”。
- 累计统计卡片展示累计点击量、累计使用量、累计获得积分和累计变现。
- 表格字段包含工具名称、图标、今日点击量、今日使用量、近 7 日点击量、近 7 日使用量、累计点击量、累计使用量、累计获得积分和累计变现。
- 点击量表示用户点击工具入口次数。
- 使用量表示用户进入工具后完成一次有效使用的次数。
- 累计获得积分表示该工具因积分使用门槛、付费使用或活动消耗获得的积分总额。
- 累计变现表示该工具关联付费、积分购买或权益转化形成的人民币金额。
- 今日数据按当日自然日统计；近 7 日数据按最近 7 个自然日累计；累计数据为工具创建以来的历史总量。
- 统计口径按工具 ID 聚合，不按工具名称模糊聚合，避免工具重名导致数据混淆。
- 支持导出当前工具数据。
- “前端交互需求”菜单用于内嵌展示工具使用门槛交互原型 `tool-frontend-interaction-demo.html`，便于对齐前端交互流程。

### 5.11 埋点统计

#### 5.11.0 埋点事件需求

- 埋点事件需求页用于在后台内查看《右豹小程序首页-变现埋点需求.xlsx》的核心事件清单。
- 页面不提供编辑能力，只作为产品、前端、后端、测试和数据分析师联调时的事件索引。
- 埋点事件声明需要覆盖三个端口：小程序、安卓、iOS；表格增加“适用端口”字段，默认展示“小程序 / 安卓 / iOS”。
- 页面支持按事件总表、冷启动、首页、变现、项目详情、公共参数切换。
- 表格字段包含事件ID、事件中文名、适用端口、触发位置、事件类型、核心参数和分析用途。
- 长事件ID、英文参数和中文说明必须自动换行，不允许与相邻列重叠。
- 页面保留“查看 Excel 文件”入口，用于打开完整原始 Excel 交付物。
- 钱包相关事件、组合提词结果、官方任务台/钱包/其他复制事件、消息入口事件不进入埋点统计需求。
- 项目发布相关事件只保留项目详情页面曝光，其他项目发布过程事件不进入埋点统计需求。
- Banner 需增加位置埋点，字段包含 banner_id、banner_name、banner_position、banner_page；banner_position 支持 1号位、2号位、3号位等。
- 每个字段都需在需求规则抽屉中给出字段注释，说明字段来源、枚举和分析用途。

### 5.12 实名相关

- 该菜单用于承接实名认证专项迭代，核心目标是支持个人实名与企业实名共存。
- 当前用户仅支持个人或者对公认证方式，原限制为同一账号只能存在一种实名结果；本次迭代改为两种实名结果可同时存在。
- 后台不设计选择认证方式页和资料填写页，仅承接认证流程跳转、审核结果页和状态说明。
- 认证结果页需要覆盖个人已认证、企业审核中、企业已认证、个人与企业共存四类状态。
- 个人实名与企业实名相互独立，任一认证通过后都不能覆盖另一种认证结果。
- 企业认证审核中时，个人实名结果仍需保留展示，不得因为审核中而清空。
- 共存完成后，页面需要同时展示个人信息卡和企业信息卡，并支持分别跳转回对应认证结果页。
- 需求规则抽屉需说明共存规则、状态规则、跳转规则和结果页展示边界。

### 5.13 提现相关

- 该菜单用于承接提现链路中的前端交互规则，重点是绑定账户页的展示、切换、提交和信息保留口径。
- 提现相关前端交互页与实名相关采用同一种展示形式，左侧切换状态，右侧展示对应页面结果。
- 选择到账方式沿用底部浮层形式，仅在账户列表项展示一个认证标签，不再拆分额外信息块。
- 绑定账户页右上角固定展示“提交”按钮；选择到账方式浮层不展示提交按钮。
- 用户同时具备个人认证和对公认证时，绑定账户页顶部展示“个人账户 / 对公账户”切换 tab。
- 当用户只有个人认证或只有对公认证时，不展示上述切换 tab，页面直接展示当前唯一认证类型对应内容。
- 个人账户下账户类型始终支持银行卡、支付宝、微信，包含双认证和仅个人认证两种场景。
- 个人账户选择银行卡时，不展示“银行卡”字段标题，仅展示开户银行、银行卡号、预留手机号等现有提交字段。
- 个人账户选择支付宝或微信时，底部账户信息相关统一展示文案“保留现在的所有提交信息”。
- 对公账户下展示对公账户信息；对公类型字段只有个体户显示，企业认证默认企业账户。
- 企业认证只能绑定 1 个企业账户类型的对公结算账户；个体户可绑定 1 个企业账户和 1 个法人账户，不支持更多。
- 仅对公认证时，对公类型同样需要展示企业账户 / 法人账户选择；对公类型选择企业账户时，底部账户信息相关统一展示文案“保留现在的所有提交信息”。
- 对公结算账户需要从当前企业账户数据中迁出，新增独立数据表“对公结算账户”。
- 对公结算账户表字段包含用户ID、用户手机号、公司信息、对公账户类型、对公账户信息、对公协议、状态、创建时间和操作。
- 对公结算账户表支持按用户ID、公司名称、状态筛选；筛选 UI 需与后台现有搜索组件保持一致。
- 状态枚举包含正常、已释放。
- 公司信息聚合展示企业名称、社会编码、公司电话和“查看详情”文字按钮。
- 点击“查看详情”使用右侧抽屉展示实名详情，字段区域按法人信息、公司信息上下排列；法人信息展示姓名、身份证、手机号、地址，公司信息展示企业名称、社会编码、公司电话、公司地址。
- 对公账户类型枚举为企业账户、法人账户。
- 对公账户信息聚合展示收款账户名称、开户行名称、支行名称、收款银行账户、发票类型和发票税率。
- 发票类型枚举为普通发票、增值专用发票；发票税率支持 1%、3%、6%。
- 对公协议展示“查看”文字按钮和合同编号。
- 操作列支持编辑、释放、日志。
- 点击编辑打开弹窗，对公账户信息内全部字段均支持编辑。
- 点击释放需要二次确认，确认后状态更新为已释放，并保留历史记录。
- 点击日志使用右侧抽屉展示后台操作日志，包括但不限于创建、修改、释放等记录。
- 数据表内文字按钮需要与所在字段左对齐。
- 法人类型对公账户添加字段与用户添加银行卡字段一致，但必须校验法人姓名一致。
- 如果个人账户添加的银行卡与法人账户重复，则不支持添加。
- 对公账户被驳回时，重新提交需跳转到选择对公认证方式的页面，页面选择项为“企业认证”和“个体工商认证”。
- 页面标题统一命名为“绑定账户”或按具体交互结果页命名，组件域内不出现重复标题。

### 5.14 导师优化

- 该菜单用于承接导师换绑专项迭代，位于一级菜单“迭代需求”下。
- 页面包含横向 Tab：“换榜审核”和“前端交互”。
- “换榜审核”列表字段包含用户ID、当前绑定导师、换绑导师、换绑原因、状态、申请时间与飞书信息。
- “换榜审核”列表需增加当前已绑定导师的绑定时间和换绑原因展示。
- 换榜审核状态包含待审核、审核通过、已驳回。
- 待审核申请支持运营审核通过或驳回；审核通过后更新用户导师绑定关系，已驳回时保留原绑定导师。
- “前端交互”需基于现有导师绑定页补充换绑场景。
- 已绑定导师的用户进入页面时，需要展示当前已绑定导师信息，包括导师名称、已绑定社群和绑定时间。
- 新导师存在多个社群时，用户需要选择加入新导师对应的社群后才能申请换绑。
- 用户发起换绑前需要先校验是否已填写飞书信息；若未填写，则需先补齐飞书ID、飞书昵称、签约姓名、签约手机号、飞书主页截图后才能提交换绑申请。
- 用户点击“申请换绑”后进入待审核状态，按钮置为审核中，前端需支持状态切换演示，不同状态按钮文案随状态变化。
- 申请通过后，前端展示换绑成功状态，并将当前绑定导师刷新为新导师，展示新社群入口。
- 申请未通过后，前端展示未通过状态和后台驳回原因，用户可调整飞书信息、社群或申请原因后重新提交。
- 换绑申请需记录用户ID、当前导师、目标导师、目标社群、申请时间、审核状态和审核结果；飞书信息仅作为展示信息。
- 需求规则抽屉需说明审核字段、状态规则、前端展示规则和绑定关系更新边界。

#### 5.11.1 统计总览

- 统计总览作为埋点统计一级菜单的默认页，面向运营日常巡盘和数据分析师快速定位趋势变化。
- 筛选项包含日期范围、端口、端来源、用户类型、渠道和事件名称。
- 核心指标包含事件触发次数、触发用户数、新用户激活率和埋点成功率。
- 趋势区支持按曝光、点击、提交和完成事件切换。
- 事件排行展示事件名、事件中文名、所属模块、触发次数、触发用户数、人均次数和转化说明。
- 事件排行需增加对比趋势图，支持今日/昨日、本周/上周和日期筛选，用于分析核心事件的周期变化。
- 点击查询后刷新全部指标、图表和表格；点击导出后导出当前筛选条件下的汇总与明细数据。
- 需求规则抽屉必须写清每个统计值关联的事件ID和计算公式。
- 事件触发次数关联全部 yb_ 前缀事件，公式为 count(event_id)。
- 触发用户数关联全部 yb_ 前缀事件，公式为 count_distinct(user_id)。
- 新用户激活率公式为 count_distinct(user_id where event_id=yb_new_user_activation_complete) / count_distinct(user_id where event_id=yb_new_user_first_open)。
- 曝光趋势关联 yb_page_view、yb_module_exposure、yb_cold_start_page_view、yb_first_project_recommend_exposure、yb_project_entry_exposure、yb_banner_exposure。
- 点击趋势关联 yb_search_entry_click、yb_banner_click、yb_project_card_click、yb_tool_entry_click 等 click 事件。
- 完成趋势关联 yb_route_customization_complete、yb_tool_use_result、yb_new_user_activation_complete。

#### 5.11.2 冷启动分析

- 冷启动分析用于分析新用户从首次打开到激活完成的完整链路。
- 筛选项包含新用户周期、来源场景、用户目标、激活类型和项目。
- 冷启动归因维度固定为小程序码、服务号、小程序分享。
- 核心指标包含新用户首次打开数、路径定制完成率、首次项目点击率和新用户激活率。
- 漏斗节点包含首次打开、首页曝光、路径定制完成、首次项目点击、首次详情曝光和首次关键动作。
- 首个项目表现表按 first_project_id 聚合，展示曝光用户、首次点击用户、详情曝光用户、首次关键动作用户、激活完成用户、点击率和激活率。
- 首个项目表现需增加对比趋势图，支持今日/昨日、本周/上周和日期筛选，展示项目点击率、详情承接率和激活率变化。
- 轻激活口径建议为完成路径定制且进入至少 1 个项目详情；强激活口径建议为触发首次关键动作或新用户激活完成。
- 需求规则抽屉必须写清每个统计值关联的事件ID和计算公式。
- 新用户首次打开关联 yb_new_user_first_open，公式为 count_distinct(user_id)。
- 路径定制完成率公式为 count_distinct(user_id where event_id=yb_route_customization_complete) / count_distinct(user_id where event_id=yb_new_user_first_open)。
- 首次项目点击率公式为 count_distinct(user_id where event_id=yb_first_project_click) / count_distinct(user_id where event_id=yb_new_user_first_open)。
- 新用户激活率公式为 count_distinct(user_id where event_id=yb_new_user_activation_complete) / count_distinct(user_id where event_id=yb_new_user_first_open)。
- 首次详情承接率公式为 count_distinct(user_id where event_id=yb_first_project_detail_view) / count_distinct(user_id where event_id=yb_first_project_click)。

#### 5.11.3 页面事件分析

- 页面事件分析按页面、模块、事件类型查看曝光、点击、提交和完成事件表现。
- 筛选项包含页面、模块、事件类型、用户类型和关键词。
- 明细字段包含页面、模块、事件名、事件中文名、事件类型、触发次数、用户数、点击率/成功率和核心参数。
- 页面与模块事件明细需补充“变现-Banner”和“变现-项目赛道”两类模块。
- 变现-Banner 关联 yb_banner_exposure、yb_banner_click，条件 banner_page=monetize。
- 变现-项目赛道关联 yb_track_click，按 track_id、track_name 聚合。
- 页面与模块事件明细需增加对比趋势图，支持今日/昨日、本周/上周和日期筛选，用于分析页面模块的点击率和承接率变化。
- 点击率优先按点击用户数/曝光用户数计算；结果类事件展示成功率。
- 该页面用于判断首页、变现、项目详情、Banner 和工具入口的用户行为重心。
- 需求规则抽屉必须写清每个统计值关联的事件ID和计算公式。
- 页面曝光PV关联 yb_page_view、yb_cold_start_page_view、yb_route_question_view、yb_first_project_detail_view，公式为 count(event_id)。
- 模块曝光关联 yb_module_exposure、yb_banner_exposure、yb_project_entry_exposure、yb_first_project_recommend_exposure、yb_onboarding_popup_exposure，公式为 count(event_id)。
- 点击次数关联所有 event_type=click 的事件，公式为 count(event_id)。
- 点击转化率公式为点击事件去重用户数 / 对应页面或模块曝光去重用户数。

#### 5.11.4 转化漏斗

- 转化漏斗用于沉淀常用业务链路，帮助运营定位转化断点。
- 支持漏斗类型包含首页到项目、Banner位置转化、项目入口页对比、冷启动激活和工具使用。
- 日期范围支持今日、昨日、本周、上周、近7日、近30日和自定义。
- 转化漏斗需增加对比趋势模块，支持今日/昨日、本周/上周和日期筛选。
- 漏斗对比趋势需要展示每一步当前周期人数、对比周期人数、单步转化率差值和流失率差值。
- 首页到项目漏斗：首页曝光 → 搜索/项目入口点击 → 项目卡片点击 → 项目详情曝光 → 关键动作点击。
- Banner位置转化漏斗：Banner曝光 → Banner点击 → 目标页曝光 → 项目详情曝光。
- 项目入口页对比漏斗：入口页曝光 → 项目入口曝光 → 项目点击 → 项目详情曝光。
- 冷启动激活漏斗：首次打开 → 路径定制完成 → 首次项目点击 → 首次项目详情 → 激活完成。
- 工具使用漏斗：工具曝光 → 工具点击 → 使用开始 → 使用结果。
- 漏斗人数按 user_id 去重，同一用户在同一漏斗周期内每一步只计入一次。
- 步骤顺序需按事件 client_time 严格递增，乱序事件进入事件质量问题。
- 需求规则抽屉必须写清每个漏斗步骤关联的事件ID和计算公式。
- 首页到项目漏斗：首页曝光 yb_page_view(page_id=home) → 搜索/项目入口点击 yb_search_entry_click、yb_workbench_project_click、yb_track_click、yb_banner_click → 项目卡片点击 yb_project_card_click → 项目详情曝光 yb_project_detail_view 或 yb_page_view(page_id=project_detail) → 关键动作点击 yb_first_action_click。
- Banner位置转化按 banner_position 分组，公式为 yb_banner_click 去重用户数 / yb_banner_exposure 去重用户数。
- 项目入口页对比按 source_page/page_id 分组，公式为 yb_project_card_click 去重用户数 / yb_project_entry_exposure 去重用户数。
- 单步转化率=当前步骤去重用户数/上一步去重用户数。
- 整体转化率=最后一步去重用户数/第一步去重用户数。
- 流失率=1-下一步去重用户数/当前步骤去重用户数。
- 单步转化率差值=当前周期单步转化率-对比周期单步转化率。
- 流失扩大判断：当前周期流失率-对比周期流失率超过阈值时标记为断点风险。

#### 5.11.5 事件质量

- 事件质量用于监控埋点上报成功率、缺参、重复上报、异常波动和未上报。
- 筛选项包含日期范围、质量类型、影响等级、责任方和事件名。
- 核心指标包含上报成功率、缺参事件数、异常波动数和待修复问题数。
- 质量明细字段包含事件名、问题类型、影响字段、发生次数、影响等级、责任方和处理状态。
- 公共参数 user_id、session_id、client_time、app_version、platform 必须存在。
- 冷启动首访事件 yb_new_user_first_open 同一用户只能有一次。
- submit/click 后应在约定时间内产生完成事件或可解释的超时状态。
- event_type、result_status、source_scene 等枚举值必须在字典范围内。
- 需求规则抽屉必须写清每个质量统计值关联的事件ID和计算公式。
- 上报成功率关联全部 yb_ 事件接收日志和入库日志，公式为 success_ingest_count / received_count。
- 缺参事件关联全部 yb_ 事件，公式为 count(event_id where required_param is null or empty)。
- 首访事件去重关联 yb_new_user_first_open，公式为 max(count(event_id by user_id)) <= 1。
- 行为完成闭环关联 yb_search_submit、yb_prompt_combo_submit_click、yb_tool_use_start 以及 yb_route_customization_complete、yb_tool_use_result、yb_new_user_activation_complete 等完成事件，公式为 30 秒内存在完成事件或可解释状态的起点用户数 / 起点用户数。

#### 5.11.6 经营分析

- 经营分析参考“首页经营分析驾驶舱”结构，面向运营和数据分析师展示整体行为经营数据。
- 页面只展示访问、曝光、点击、详情、激活、工具使用等行为指标，不展示金额、订单、支付、钱包、兑换码和收益指标。
- 筛选项包含日期范围、端口、用户类型、入口页和项目。
- 核心指标包含访问UV、项目曝光UV、项目点击UV、项目详情UV、新用户激活UV和有效使用UV。
- 首页核心行为漏斗为访问UV → 项目曝光UV → 项目点击UV → 详情曝光UV → 关键动作UV → 激活UV。
- 7日行为趋势支持 UV、项目、激活三个维度切换。
- 项目入口页转化对比按入口页展示项目曝光UV、项目点击UV、项目点击率、详情曝光UV和详情承接率，用于判断哪个入口页转化更高。
- Banner位置效果分析按 1号位、2号位、3号位等展示曝光UV、点击UV、点击率、详情承接UV和详情承接率，用于判断哪个资源位点击率最高。
- 访问UV关联 yb_page_view，公式为 count_distinct(user_id)。
- 项目曝光UV关联 yb_project_entry_exposure、yb_workbench_project_exposure、yb_first_project_recommend_exposure，公式为 count_distinct(user_id)。
- 项目点击UV关联 yb_project_card_click、yb_workbench_project_click、yb_first_project_click，公式为 count_distinct(user_id)。
- 项目点击率=项目点击UV/项目曝光UV。
- 项目详情UV关联 yb_project_detail_view、yb_first_project_detail_view 或 yb_page_view(page_id=project_detail)，公式为 count_distinct(user_id)。
- 详情承接率=项目详情UV/项目点击UV。
- Banner点击率=count_distinct(user_id where event_id=yb_banner_click and banner_position=X) / count_distinct(user_id where event_id=yb_banner_exposure and banner_position=X)。
- 有效使用UV关联 yb_tool_use_result、yb_route_customization_complete、yb_first_action_click，公式为 count_distinct(user_id)。

## 6. 核心业务流程

### 6.1 积分商品兑换流程

1. 运营在后台配置积分商品并上架。
2. 用户端展示商品档位。
3. 用户选择档位并确认兑换。
4. 系统校验协议、钱包余额、商品状态和库存。
5. 钱包扣款成功后生成兑换订单。
6. 系统发放积分并写入积分流水。
7. 后台支持订单查询、对账和异常处理。

### 6.2 兑换码兑换流程

1. 运营创建兑换码批次。
2. 系统生成兑换码并记录批次信息。
3. 用户输入兑换码。
4. 系统校验有效期、状态、使用次数和用户范围。
5. 校验通过后发放积分。
6. 后台记录核销用户、时间、积分数量和流水编号。

### 6.3 任务领奖流程

1. 运营配置任务和奖励规则。
2. 用户端展示任务列表。
3. 系统判断用户任务完成状态。
4. 用户点击领取。
5. 系统校验是否重复领取。
6. 发放积分并记录任务奖励流水。

## 8. 权限要求

- 运营可管理商品、任务和兑换码活动。
- 客服可查看用户、流水和订单，可发起调账申请。
- 财务可查看支付记录、导出对账数据、处理退款。
- 管理员可配置系统参数。

## 9. 非功能要求

- 积分发放和扣减必须具备幂等能力。
- 钱包扣款和积分发放必须保持最终一致；异常订单需可追踪和补偿。
- 所有人工调账、作废兑换码、退款等操作必须写入审计日志。
- 关键列表查询需支持分页、筛选和导出。
- 后台核心操作需要二次确认，高风险操作需要审批。
- 实名相关页的跳转动作需可追踪，结果页状态需与后端认证结果保持一致。

## 10. 验收标准

- 可完成积分商品从配置到用户端展示的闭环。
- 可完成钱包扣款兑换积分并在后台查询订单和流水。
- 可批量生成兑换码，并完成兑换、核销和导出。
- 可配置任务奖励，并在用户完成任务后发放积分。
- 可对用户积分账户进行查询、冻结、调账和审计。
- 可查看异常订单并执行重试、退款或人工处理。
