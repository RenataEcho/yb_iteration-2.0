# 右豹迭代需求 · FR Demo 写入规范

> **状态**：已确认（2026-08-23）  
> **参考实现**：FR-001 · 代发分配 · `fr-opc-daifa-allocation.html`  
> **适用范围**：后续所有写入「右豹迭代需求记录」的 FR Demo 与需求规则抽屉

---

## 一、迭代需求 Demo 整体结构

1. **Sidebar 一级菜单** = 需求标题（如「代发分配」），不按模板类型拆菜单。
2. **页内横向 Tab** 默认三类（可按需求增减）：
   - **前端交互**（模板 B）— 场景切换 + iframe Mockup
   - **管理后台**（模板 A）— 数据表 + 筛选 + 详情抽屉
   - **业务流程** — SVG 流程图（研发对照）
3. **需求规则抽屉** 独立于页内 Tab，由 Page Header 右上角「需求规则」打开。
4. **需求规则抽屉内** 再分横向 Tab：
   - **前端需求**
   - **后台需求**
5. **规则内容只写当前 FR**，不写迭代平台通用规则（如 Sidebar 架构、页内 Tab 框架说明等）。
6. **版本标识**：Page Header 展示 `FR-xxx` + `vN 当前`；规则抽屉标题同步 FR 编号与版本。

---

## 二、前端交互（模板 B）

7. **先 HTML Demo 确认交互**，再定后台数据表；Demo 阶段不做真实接口/持久化。
8. **Mockup 仅页内 iframe 嵌入**，不提供「新窗口打开」入口。
9. **场景切换**：左侧场景列表 + 右侧手机框 Mockup；支持 `?embed=1&screen=xxx` 与 postMessage 切屏。
10. **C 端色彩**：沿用现有移动端橙色体系，不另起配色。
11. **抽屉/浮层**：分配详情浮层、导出等均为 **overlay 浮层**，不挤压、不折叠上级页面宽度。
12. **场景清单需覆盖**：主流程页面 + 补充页面（如发布帐号、成员详情 Tab 等），每个场景附简短说明。

---

## 三、管理后台（模板 A）

13. **二级 Tab**：按数据域拆分（如「发布帐号」「代发关键词」）。
14. **列表字段**：按 PRD 明确列定义，操作列含详情/编辑/日志等。
15. **筛选条件**：支持 ID、昵称、负责人/成员/工作室、平台、状态、时间范围等**可唯一或半唯一定位**的字段。
16. **详情抽屉**：关键词详情等用 overlay 抽屉展示合并 list，不挤压列表页。
17. **仅规则、不做 C 端原型的扩展**（如分配记录表新增字段）在**后台需求**中写明，不在 Mockup 体现。

---

## 四、业务流程 Tab

> 视觉基准与可点示例：`demo/iteration/component-spec-demo.html#sec-flow`  
> 参考实现：FR-001 代发分配 · FR-008 礼品中心 · FR-010 代理认证

18. **能闭环就只用一张图**：主路径、校验分支、驳回/失败回环能画进同一张 SVG 并接到起点，则只保留一个业务流程，不要预置流程 2。只有两条互不汇合的主链，或单图闭环后通道必然打架、线穿框、节点被裁切时，才启用第二张；多张时用**横向 Tab**切换，不要纵向堆叠。只有一张图时不要空挂「流程1」。
19. **流程图面向研发**：前后端交互 + 校验菱形节点 + 分支（是/否）。
20. **图例统一放面板底部**，各流程共用（前端蓝 / 后端绿 / 异步橙 / 校验黄菱形 / 阻断红 / 跳过灰）。
21. **呈现规范（实现要点）**：
    - SVG 分 **连线层**（`flow-edges`，下）+ **节点层**（`flow-nodes`，上），避免连线横穿线框
    - 正交折线（仅水平/垂直）、走节点间隙专用通道，禁止斜线穿框
    - 折线起止必须落在节点边；悬空端点视为断流
    - 驳回 / 失败 / 重提必须闭环接到起点**顶边**；回环走外侧通道，禁止贴画布边缘停住
    - 间距：相邻节点纵向 ≥24px；菱形与上下节点 ≥30px
    - **一菱形一问题**；判定公式、口径、比较符写进菱形或副文案，禁止把复合判定合成一步
    - 长文本用 `tspan` 换行（超 12 字），线框留足内边距；副文案 10px + muted
    - 分支标注：「是/通过」绿色，「否/驳回」红色，贴在对应折线旁
    - 每张 SVG 独立 `marker id`（如 `flow-arrow-1`），同页禁止复用
    - 可选 / 汇总 / 异步旁路用虚线 `stroke-dasharray="4 3"`
    - 画布写死 `width` + `viewBox`；面板 `max-height: 72vh` + `overflow: auto`
22. **需求规则里不写文字版全流程**；前端需求「业务流程」节仅**指向**页内「业务流程」Tab。

### 硬限制（做不到 / 不要做）

23. **手写绝对坐标，无布局引擎**：移动或加高一个节点，必须重算所有相连折线；改一处容易漏改边。
24. **无自动避让**：折线不会绕开节点，线穿框是最高频事故。先定节点框，再对端点。
25. **菱形是写死 polygon**：改文案必须重算四个顶点，不能只改 height。
26. **SVG 文本不自动折行**：超长必须手写 `tspan`。
27. **viewBox 写死**：加节点必须同步加大画布，否则被裁切。
28. **不做响应式重排**：窄屏只横向滚动。
29. **静态图**：节点不可点、不高亮当前态、不跟 Demo 表联动。
30. **拆图是例外**：优先扩画布、走外侧回环，把同一条业务画闭环。禁止因为「节点有点多」就先拆流程 2。
31. **不表达并发与时序**：没有泳道 / 甘特；并行、等待只用橙色节点或虚线示意。
32. **色值写死 hex**：未接 CSS 变量，无暗色主题。
33. **禁用 Mermaid / 流程图库**：颜色、正交通道、分层渲染、图例对不齐。
34. **不进抽屉、不进规则正文**：第二份图会和页内 Tab 漂移。
35. **不接真实状态机**：图是研发说明，不驱动后台表状态。

## 五、需求规则抽屉 · 内容结构

### 前端需求（建议章节）

| 节 | 内容 |
|----|------|
| 1 业务目标 | 本 FR C 端要解决什么 |
| 2 页面与入口 | 各页面/入口及核心展示字段 |
| 3 交互规则 | 浮层、标签、跳转复用、统计口径等 |
| 4 边界规则 | 不可撤回、可见范围、字段必填等 |
| 5 业务流程 | 仅指向页内流程图 Tab |

### 后台需求（建议章节）

| 节 | 内容 |
|----|------|
| 1 业务目标 | 数据面/运营排查目的 |
| 2 数据表与字段 | 各表字段 + 扩展字段（仅规则） |
| 3 列表与筛选 | 筛选项 + 详情展示方式 |
| 4 边界规则 | 删除保留、更新时间口径、枚举值等 |

### 通用原则

36. **打开规则抽屉时**，按当前页内 Tab 自动定位规则 Tab：前端交互 / 业务流程 → 前端需求；管理后台 → 后台需求。
37. **不写**：Sidebar 菜单规范、迭代后台全局交互、Swagger/权限等与当前 FR 无关的内容。

## 六、业务规则书写习惯（示例模式）

> 以下为 FR-001 代发分配沉淀的模式，新 FR 按同样粒度写「是什么 / 谁可见 / 边界」。

38. 成对概念须区分写清（如：**代发 vs 主动分配** → `分配行为` = 系统自动 / 负责人主动）。
39. 权限/生命周期差异单独成条（如：代发记录不可撤回；主动分配可撤回）。
40. 标签/标识仅适用于特定类型（如：「代发」标签仅系统自动分配）。
41. 可见范围写清主体（如：授权帐号仅代发成员；成员代发累计收益仅统计代发）。
42. 关键字段在哪些界面必须出现（如：分配时间在负责人浮层/导出/成员明细）。
43. 复用既有流程须标明（如：发布帐号添加复用右豹现有流程，本 FR 不重定义步骤）。
44. 数据留存与展示口径（如：已删除保留记录；累计类字段以数据更新时间为准）。

## 七、交付与文件约定

45. **主入口**：`demo/iteration/fr-{模块}-{需求}.html`（三 Tab 合一）。
46. **C 端 Mockup 独立文件**：支持 embed 参数，供 iframe 加载（如 `*-demo.html?embed=1&screen=xxx`）。
47. **与 UX mockups 同步**：`_bmad-output/planning-artifacts/ux-designs/.../mockups/` 保持副本一致。
48. **URL 深链**：`?tab=fe|admin|flow`；仅拆出多张流程图时再加 `&flow=1|2|3`。
49. **Sprint 概览**：`framework-shell.html`；旧分散入口改为跳转统一页 + Tab 参数。FR 状态：待开始 / 开发中 / 已上线 / 已暂停；「已上线」归入归档需求，「已暂停」归入废纸篓。

## 八、非目标（Anti-patterns）

50. 不做真实权限、审批、数据持久化。
51. 不在 Demo 里堆迭代平台/Global 规范说明。
52. 不在需求规则里重复流程图全文（流程图只在「业务流程」Tab）。
53. 不为单个 FR 改变全局 Sidebar/迭代框架结构。
54. 不用 Mermaid / 流程图库替代手写 SVG 业务流程图。

## 九、交互组件规范（Design System）

55. **组件样式基准页**：`demo/iteration/component-spec-demo.html`（Sidebar「组件规范」入口）。
56. **须复用的组件类型**：

| 类型 | Class / 模式 | 用途 |
|------|----------------|------|
| 主按钮 | `.btn .btn-primary` | 查询、保存、提交 |
| 次要按钮 | `.btn .btn-ghost` / `.btn-sm` | 取消、重置 |
| 需求规则 | `.btn .btn-rule` | Page Header 入口 |
| 危险按钮 | `.btn-danger` / `.btn-danger-ghost` | 确认弹窗内删除 |
| 文字链 | `.link` / `.link-muted` / `.link-danger` | 表格操作列 |
| 确认弹窗 | `.modal-overlay` + `.modal`（400px） | 删除、不可逆操作 |
| 编辑弹窗 | `.modal.modal-md`（480px） | 表单编辑 |
| 详情抽屉 | `.drawer-overlay` + `.drawer`（480px） | 只读长内容、关键词 list |
| Toast | `.toast` | Mock 提交反馈 |
| 状态 Tag | `.tag-ok` / `.tag-warn` / `.tag-del` | 表格业务状态 |
| 业务流程图 | `.flow-page` + SVG `flow-edges` / `flow-nodes` | 页内「业务流程」Tab |

57. **操作列顺序**：详情 → 编辑 → 日志（muted）→ 删除（danger + 确认弹窗）。
58. **详情用 Drawer、编辑用 Modal、删除用 Confirm**，三者不混用。
59. 新 FR Demo 须从组件规范页复制 class，不自定义按钮/弹窗/流程图样式。
