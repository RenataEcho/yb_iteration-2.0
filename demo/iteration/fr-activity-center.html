FR-006 · 需求规则 · v1

1业务目标

用户进入活动中心后，只看到系统判定为「显示」的活动：卡片沿用图1；始终看到浏览人数；参加人数与后图按后台是否配置决定显隐；点「查看」有跳转链接则跳配置地址，没有则进入活动详情页。

2页面与入口

  • 入口：个人中心 / 首页等既有入口；页头「活动中心」。
  • 置顶 Banner：最多 1 条；不在下方列表重复；不随筛选 Tab 隐藏。取消置顶后 Banner 立即消失。
  • 筛选：全部 / 进行中 / 已结束；只过滤列表卡片，不撤 Banner。空则「暂无符合条件的活动」。
  • 卡片结构（图1）：项目标签 → 灰色内容区（状态角标 + 图标 + 标题/副标题）→ 底部信息 +「查看」。按钮文案不因状态改变。
  • C 端状态角标：由系统按活动时间计算 待开始 / 进行中 / 已结束，不是后台「显示/隐藏」。

3展示判断

  • 浏览人数：始终展示「x人浏览」，取后台初始浏览量；前端不累加、不编造。
  • 参加人数：已配置 →「x人已参加」（虚拟值）；未配置 → 人数与后图整段不展示。
  • 后图：仅在已展示参加人数之后判断；已配置则跟在文案后，未配置不放占位图。只配后图、不配人数时仍不展示该图。
  • 跳转：点 Banner/卡片「查看」有链接则跳配置地址，没有则进入既有活动详情页（展示活动内容）。本 FR 不重做详情页样式。

4边界规则

  • 后台「隐藏」的活动不进入 C 端可见池，列表与 Banner 均不出现。

5业务流程

见页内 Tab 「业务流程」。

1业务目标

运营在后台完成「配置 → 保存」；系统负责校验、计算 C 端状态、组装下发字段。运营不直接改 C 端角标文案。

2作业与字段

  • 三栏页：左基础字段、中富文本、右预览；新增/编辑同一页，编辑回填。
  • 必填：活动标题（≤64）、开始时间、活动状态（显示/隐藏）。不通过则不保存，退回并提示缺失项。
  • 选填：平台、赛道、项目（先赛道后项目）、简介（≤200）、跳转链接、结束时间（空=长期；有值且早于开始则退回）、排序（默认 0，越大越前）、初始浏览量（默认 0）、参加人数（虚拟）、参加人数后图、活动内容。

3列表与筛选

  • 筛选项：活动标题、所属平台、所属赛道、活动状态（显示/隐藏）。重置只清空条件，不自动查询。
  • 列表：ID、标题、平台、赛道、项目、状态、浏览人数、参加人数、活动时间、排序、操作；等宽均分行高，超长省略。
  • 参加人数未配置在列表显示 -；操作仅「编辑」。

4边界规则

  • 项目下拉依赖赛道；未选赛道时禁用，占位「请先选择所属赛道」。
  • 状态=显示才进入 C 端可见池并按时间计算待开始/进行中/已结束；隐藏则写入但不下发。
  • 组装下发：浏览人数必带；参加人数、后图仅配置了才下发。未下发字段 C 端视为未配置。
  • 表单校验（必填、结束时间）留在编辑页，不画进主流程。
