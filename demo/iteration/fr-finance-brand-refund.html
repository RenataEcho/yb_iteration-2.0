新增品牌退款

FR-003 · 需求规则 · v2

1业务目标

品牌项目发生退款时，用户在 C 端订单列表与钱包收益明细中可看到对应扣减记录。本迭代仅定义卡片信息展示，不重做完整页面。

2展示入口与字段

订单列表（审核通过且已扣回后展示）：

  • 标题：固定「品牌退款」
  • 副标题：退款原因
  • 订单产生日期：退款订单日期
  • 订单更新日期：扣回完成时间（未扣回时不展示该条）
  • 扣减金额：负向展示，如 -128.50

钱包 · 收益明细（审核通过且已扣回后展示）：

  • 标题：{项目名称}「{关键词}」产生退款
  • 副标题：退款原因
  • 时间：扣回完成时间
  • 金额：负向展示
  • 状态：固定「已扣减」

3交互规则

  • 待审核、已驳回、已通过但未扣回的记录不在 C 端展示；仅扣回状态=已扣回时展示。
  • 订单列表与收益明细为既有页面新增记录类型，沿用现有列表卡片样式。
  • 金额为扣减方向，使用负号或红色样式（沿用现有扣减展示规范）。

4边界规则

  • 仅品牌项目支持本退款类型；非品牌项目不走此链路。
  • 删除后台退款记录后，C 端对应展示同步移除（若已展示）。
  • 编辑退款金额/原因后，C 端展示字段同步更新。

5业务流程

见页内 Tab 「业务流程」流程图。

1业务目标

在财务板块新增一级菜单「品牌退款」，供运营录入、审核、追踪品牌项目退款，并支撑对账与客诉排查。

2数据表与字段

品牌退款表：

  • 用户 ID
  • 关键词
  • 项目信息：项目 ID、项目名称
  • 退款订单日期
  • 退款金额
  • 退款原因
  • 审核状态：待审核 / 已通过 / 已驳回
  • 扣回状态：已扣回 / 待扣回（审核未通过时为空）
  • 操作：编辑、删除

3列表与筛选

筛选项：用户 ID、关键词、项目名称、扣回状态；默认折叠展示。

数据明细卡片：统计区下方，列表字段第 1 位（用户 ID）为卡片标题；Tag 展示审核状态；其余字段入内嵌灰色三列/四列区。

表头基础统计（随筛选结果联动）：

  • 退款总笔数、退款总金额
  • 已扣回金额 — 仅统计扣回状态=已扣回的记录；删除已扣回记录时相应减少
  • 待扣回金额 — 审核已通过但未扣回的金额合计
  • 待审核笔数

批量操作：

  • 批量导入 Excel 字段：关键词、项目 ID、退款金额、退款原因
  • 批量审核通过 / 驳回 / 删除：勾选后展示批量操作栏；确认弹窗展示已选数量 + 累计退款金额
  • 已扣回记录：不可勾选、不可编辑/删除，不参与批量审核与批量删除

4边界规则

  • 审核状态为已通过后，方可进入扣回流程；扣回成功后扣回状态变为「已扣回」。
  • 审核已驳回的记录不参与扣回，扣回状态为空。
  • 删除需二次确认；已扣回记录删除时同步撤销 C 端展示并回滚钱包（具体回滚策略由后端定义）。
  • 新增/编辑提交后刷新列表与表头统计。
