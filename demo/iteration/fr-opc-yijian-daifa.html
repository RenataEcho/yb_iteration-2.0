边界

门禁顺序、占用和停权不能改口

先停权，再次数，再资格，再占用，最后选词。次数不足不得打开选词浮层。一稿同时一人占用。超时不退次。终身未回填超过 3 次停权，只能后台恢复。

领取门禁（按这个顺序拦）

1 停权黑名单停权中：按钮「已被停权，无法领取」。
2 次数免费+已购=0：只开兑换浮层，不开选词。
3 资格审核/项目/剪辑手/素材任一不合格：当前不可领，不扣次。
4 占用占用中或已完成：领取失败，回广场。
5 选词必须点该项目已通过关键词，才能确认领取。
  • 禁用项目不可上传、不进广场。停用剪辑手或禁用素材的已通过空闲稿也不进广场。
  • 审核中 / 已驳回不进广场。已通过不可再驳回。
  • 领取后 7 天内可下载，超时未下不可再下。
  • 图集预览最多 3 张；角标仍显示真实张数。防截屏=禁右键/长按保存 + 用户水印 + 切后台模糊；真机系统截屏禁不掉。
  • 任何列表不展示金额。Demo 无真实 HTTP，数据在 localStorage 闭环。
不要对用户承诺「截不了屏」。规则只保证 Demo 级禁保存，真机截屏拦不住。
FAQ

先问卡在上传、领取、回填还是停权，再对状态

对用户不要讲 FR 编号。对研发指到对应端的「业务流程」和「前后端数据交互」。

Q1. 为什么广场看不到刚传的稿？
该剪辑手「稿件需要审核=是」时，PC 新稿默认审核中，后台通过且空闲才进广场。免审剪辑手上传后空闲即可进。占用中、已完成、已驳回、禁用项目、停用剪辑手、禁用素材都不可见。
Q2. 次数够了为什么还领不了？
还要选该项目已通过关键词，且稿件当时空闲。未选词、已被占用、未审核通过、项目禁用、已停权都会失败。
Q3. 超时了次数能退吗？
不退。记 1 次未回填，稿件回广场。原领取人未进黑名单可再领，再领再扣次。
Q4. 停权了怎么办？
终身未回填超过 3 次。只能后台黑名单手动恢复，没有自助解禁。
Q5. 图集详情为什么只能看 3 张？
预览上限 3 张，角标仍是真实张数。领取前预览不扣次、不能保存。完整稿领取后再下。演示预览用现有封面凑 3 张，不是书内页。
Q6. 用户能在 App 里当剪辑手上传吗？
不能。C 端只领取。上传只在 PC 创作者中心。广场招募帧只看海报。
Q7. 领取后怎么下载？水印必做吗？
底栏「下载稿件」7 天内有效。加水印可选，下载会先打当前水印再出文件。超时未下不能再下，但回填不受 7 天下载影响，只受 24h 回填窗影响。
Q8. 非剪辑手打开 PC「剪辑供稿」会怎样？
不跳走。招募 BN 仍在，点开抽屉可看海报。看板走缺省，上传入口不可用。
Q9. 用剪辑手稿件回填后，关键词收益怎么入账？
订单已结算时先判该词是不是代发。是则按分成拆成用户实结和剪辑手分账，两边都进项目收益明细，状态「已结算」。不是则全额给用户。对账看「前后端数据交互 → 用户收益入账」。

前端需求与前后端数据交互

基于 C 端广场/详情/领取、PC 上传和后台七页，对齐展示规则、字段校验、接口入参出参、状态流转与异常处理。下列路径是研发对照用的将落地契约。本 Demo 无真实 HTTP，C / PC / 后台共用 yijian-daifa-store.js 的 localStorage 逻辑闭环。

重要规则：领取门禁与广场可见性
  • 门禁顺序固定：停权 → 次数 → 选词浮层 → 资格/占用。
  • 次数不足只打开兑换浮层，不打开选词浮层，不扣次。
  • 广场只返回 plazaEligible 为真的稿：已通过 + 空闲 + 项目启用 + 剪辑手已录入 + 素材启用。
  • 领取成功必须同时写：占用中、扣次、领取记录未回填。三者同一业务关联编号（claimId）。
  • 任何列表响应不得带金额、收益、积分售价以外的收益字段。

1. 作品广场

  • 项目图标只列启用项目，按 sort 横滑直选；点图标即筛该项目。
  • 搜索在项目图标下方，按标题模糊匹配；下拉筛剪辑师 / 启用素材 / 图集或视频。
  • 封面必须是图片 URL，禁止纯色块。图集出示 imgs 张数角标，视频不出张数。
  • 广场 Banner 复用平台已有 0–5 条能力；本 FR 后台不单开配置。点招募帧进海报，不进申请表。
  • 空态：「没有可领取的稿件；占用中的稿件已对他人隐藏。」

2. 稿件详情与图集预览

  • 标题下展示标签；书籍名称下为书籍 ID。内容底、按钮上展示注意事项。
  • 未领取展示领取步骤；领取成功后改为作品发布技巧（发布标题 / 发布描述可复制）。
  • 未领底栏：剩余次数、快捷提词、领取。已领底栏：添加水印、下载稿件。
  • 图集可点开预览，最多 3 张，可左右切；imgs 角标仍是真实张数。预览不扣次、不占用、不能保存。
  • 预览禁右键/长按保存，叠用户水印，切后台模糊。规则写明真机系统截屏禁不掉。
  • 视频仍 5 秒试看，不进图集浮层。

3. 领取与选词浮层

  • 次数足够后才打开选词浮层，只列该项目已通过关键词，不进下级页。
  • 未选词点确认：Toast「请先选择该项目已通过的关键关键词」，浮层不关。
  • 确认后 loading：正在下载稿件 → 正在保存到相册 → 已保存到相册。成功停在详情。
  • 停权中按钮文案「已被停权，无法领取」，不打开浮层。

4. 兑换次数

  • 只展示 on=true 的档位，最多 4 档。下架/草稿不返回。
  • 选档后点「兑换」。Demo 不真扣积分；落地时以后端扣减结果为准。
  • 兑换成功关浮层、刷新剩余次数，不自动打开选词。

5. 我的领取与回填

  • 项目图标只展示有领取记录的项目。胶囊：未回填 / 已回填 / 已超时。
  • 卡片含关键词标题、封面、作品标题、项目、作者、领取时间、下载时间、7 天下载倒计时。
  • 立即回填始终高亮。已回填 toast「该稿件已回填」；已超时 toast「已超时，无法回填」。
  • 回填复用该项目已有回填页字段，提交后领取→已回填，稿件→已完成，不再回广场。

6. PC 上传

重要规则：关键词结算入账必须先判代发

  • 只在平台关键词订单已结算时落账；待结算只累计，不写明细。状态固定为「已结算」。必须带秒级时间戳与金额。

1. 背景与触发

1
回填完成用户领取剪辑手稿件并走该项目回填页提交。领取记录 → 已回填，稿件 → 已完成。此时还不入账。
2
关键词出单回填所用关键词产生平台订单收益。结算态沿用既有关键词订单：待结算 / 已结算。
3
入账前回检订单转为已结算时，后端先查该关键词是否绑定一条已回填的一键代发领取（claim.status=已回填，且 mid 为剪辑手稿件）。
4
按比例分账判定为代发后：应结算总额 × 分成比例 = 剪辑手分账；用户实结 = 应结算 − 剪辑手分账。同一结算事件原子写入用户账 + 剪辑手账。

2. 代发判定

条件结果入账
关键词绑定已回填的一键代发领取（用户用剪辑手稿件回填）代发关键词按分成比例拆用户实结 + 剪辑手分账；文案用本页模板
关键词无已回填代发领取，或领取已超时释放非代发既有全额用户入账；不写剪辑手分账
订单仍为待结算不入账只累计；明细不出现「已结算」记录

3. 分账口径

  • 应结算总额 = 该关键词本笔已结算订单收益。
  • 分成比例 = 领取稿件对应剪辑手录入时的 share（如 50%）。
  • 剪辑手分账 = 应结算总额 × 分成比例（代发作品分账）。
  • 用户实结 = 应结算总额 − 剪辑手分账。
  • 用户实结 + 剪辑手分账必须等于应结算总额。复用既有项目收益明细，不另建账本，不改 FR-002。

4. 入账文案（已结算）

两边都写既有「项目收益明细」。标题、描述、时间戳、金额、状态均必出。时间用 YYYY-MM-DD HH:mm:ss；标题里的时间加方括号。

侧字段模板
