FR-017 · v1 需求规则

1业务目标

让用户在作品广场看见代发值多少，并在同一页抢每天限时、名额有限的额外次数。试点全员，不做白名单。不单开首页。

2页面与入口

  • 本迭代作品广场：已登录出示代发收益池（只出一个展示收益）+ 右下盲盒浮标进今日盲盒 + 稿件宫格。卡片仍不展示金额。未登录隐藏收益池整模块，盲盒加锁提示先登录。
  • 限时领次页：从广场盲盒浮标进入。未开盒 / 可拆 / 已开出 / 拆完 / 已收官。可拆时正中一只会晃的盒，货架下一盒在闪，名单写谁刚拆走；拆中先开出 ×1，再出示今日第几盒与压过人数。售罄 = 名额为 0 或剩余每日发放量 < 每次发放的活动次数。领完回广场。
  • 历史广场 / 详情 / 领取：不改 fr-opc-yijian-daifa.html / yijian-daifa-demo.html。不单开首页。

3交互规则

  • 展示收益 = 虚拟配置 + 实际累计。C 端不拆、不加「含预估」。
  • 领取成功：活动剩余 +每次发放；可领名额 −1；每日发放量 −每次发放。并发不得超发。
  • 失败不扣任何桶。停权、未登录、当日已领过均失败。
  • 领取次数 = 免费 + 已购 + 活动。扣次：免费 → 活动 → 已购。不扣积分。

4边界

  • 代发收益池不是可提现，不是项目收益明细另一行。
  • 不改 fr-opc-yijian-daifa.html、yijian-daifa-demo.html、fr-activity-center.html。
  • 线上要接到真实历史广场时，另开变更。不单开首页。

5业务流程

见页内「业务流程」Tab。

1业务目标

运营只在本迭代新页配虚拟配置和一档限时领次。不改次数商品页。

2收益池

  • 字段：虚拟配置（≥0）、实际累计（只读）、展示收益（相加）。
  • 实际累计：已回填代发关键词上已结算应结算；待结算不计；不回溯先结算后回填。
  • 虚拟配置每次保存留审计：谁、何时、新旧值。

3限时领次

  • 时间窗、每日发放量、可领名额、每次发放的活动次数（默认 1）。试点同时 1 档。
  • 关停后已领活动剩余保留。
  • 保存后下一次打开本迭代作品广场 / 活动页必须生效。

4边界

  • 虚拟配置永不写入项目收益明细。
  • 超发事故必须为 0。库存不够一整份则拒领。
