扣税发生在后台打款入账，不在用户点提现时。只有云账户应税接口扣税成功，才写入实际到账，并同步增加可提现。

规则说明

1
后台操作打款运营对订单 / 收益批次发起打款。用户侧此时还不能把这笔钱提走。
2
录入已结算收益将该笔记入对应用户、对应钱包的已结算收益：收益金额=打款额，状态=扣税中，实际到账暂为 0。
3
调取云账户「钱包余额应税」接口用该笔已结算收益调应税接口，替换原提现扣税接口。税率与税额以接口返回为准。
4
扣税成功 → 写入实际到账实际到账金额 = 收益金额 − 接口返回税额。状态改为已到账。收益明细展示扣税文案。
5
同时增加可提现余额切点后：统一余额 += 实际到账金额；旧三钱包库存不回写。切点前历史库存保持冻结，只减不增。
×
扣税失败状态=到账失败，回写失败原因；不写实际到账；可提现不增加。用户可在收益卡片点说明 icon 看原因。

FR-016 · v1 需求规则

1业务目标

一个提现入口。收益分钱包入账不变；切点后余额只写统一字段，旧三余额冻结。可提现 = 冻结旧库存 + 统一余额。

2页面

  • 钱包首页：今日入账贴在总收入旁；三格为已提现、可提现、提现。三张卡去掉操作按钮，灰色字段为累计已结算 / 累计待入账。
  • 提现页：可提现为新钱包统一余额；文案「合并前可提现余额 xx.xx 元(项目:xx;团队:xx,活动:xx)，已全部合并进新钱包的可提现余额里」。待入账不计。
  • 提现明细：顶栏右侧进入；展示累计提现 / 实际到账（无预扣税额），记录含实际到账、提现ID、申请时间、打款时间；「提现记录」旁提示「以下数据为钱包合并提现后的新数据，旧数据仍在各个钱包的提现明细页面查看」。
  • 查看明细：收益明细顶部统计累计已结算 / 实际到账 / 预扣税额；卡片标题为项目名称 + 收益金额，其下为实际到账金额与状态（扣税中 / 已到账 / 到账失败，失败可点 icon 看原因）；描述保留并追加扣税文案；底部为时间戳与动账后收益。提现明细同现网记录页，标题旁提示「以下数据为合并提现前的钱包提现记录」。

3交互

  • 未选到账方式：点确定 Toast「请选择到账方式」，停留在提现页。
  • 金额为空或超合计：拦截，不提交。
  • 待入款不计入可提现。
  • 提现页提示：合并前可提现余额已全部并入新钱包可提现。
  • 提现不再扣税。

4收益打款入账

  • 后台操作打款 → 将用户收益录入已结算收益（状态扣税中）。
  • 调取云账户「钱包余额应税」接口；税额以返回为准。
  • 扣税成功：写入实际到账金额，同时可提现（统一余额）增加实际到账；禁止回写旧库存。
  • 扣税失败：到账失败并记原因，可提现不增加。

5业务流程

见页内「业务流程」Tab：流程1 收益打款入账、流程2 用户合并提现。
