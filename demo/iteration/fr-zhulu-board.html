FR-015 · v1 需求规则

1业务目标

中秋国庆「双节逐鹿狂欢」期间，给用户一张可刷的收益冲榜页：看见前 100 名和自己的名次，驱动项目有效收益。

2页面与字段

  • 入口：独立活动 H5（海报 / 站内信 / 运营投放）。不并入 OPC 经营榜，不按赛道拆 Tab。
  • 活动窗：2026-09-25 00:00:00 — 2026-10-09 23:59:59（以平台时区）。
  • 头图：活动名「双节逐鹿榜」、日期、最近快照时间（如「更新至 2026-09-17 15:00 · 每小时更新」）。
  • 列表只展示前 100 名，每行必含：排名、用户头像、脱敏昵称、活动期间收益（单位元，2 位小数）、口径标签「活动期」。
  • 脱敏：他人昵称保留最后一个字，其余以 **** 代替，如 ****山。底栏当前用户展示真实昵称。
  • 前三名：TOP 1 / 2 / 3 角标，收益用强调红；第 4 名起普通数字名次。
  • 底栏：当前用户头像、真实昵称、排名、活动期收益。未进前 100 仍展示真实名次（可 >100），列表不插入该用户。
  • 规则浮层：奖项表（海报 1–88 名）+ 统计口径 + 发奖风控文案。

3刷新与状态

  • H5 只读最近一次整点快照，不实时扫单。文案展示快照时刻。
  • 未开始：空态说明开榜时间，不展示假数据，隐藏底栏。
  • 进行中：每小时更新一次；用户下拉不强制刷新，下次打开或整点后再次进入才看到新快照。
  • 已结束：展示「最终榜」，快照定格为活动结束后第一次覆盖完整窗口的整点任务（10-10 00:00），之后不再滚动。
  • 无头像用默认色块 + 末字；收益为 0 且从未计入的用户不进榜，底栏仍可展示 0.00 与未上榜名次。

4统计口径（C 端展示必须与快照一致）

  • 项目范围：活动期间全部项目，版权分销除外。
  • 时间纬度：收益订单是否计入，看订单更新时间 updated_at 是否落在活动闭区间，不是下单时间 / 结算时间。
  • 用户维度对计入订单金额求和，保留 2 位小数后排名。
  • 同分：最近一笔计入订单的更新时间更早者靠前；仍相同按 user_id 升序。

5边界

  • 不做 7 日 / 30 日 / 日榜切换；不做平台项目榜 / OPC 经营榜双 Tab。
  • 发奖以审核后的最终榜为准，H5 冲榜数仅作过程展示。

1业务目标

运营查看整点快照、核对口径与发奖档，不在本 FR 做奖品物流履约（实物/现金走既有发放流程）。

2任务与字段

  • 小时任务：每整点跑一次。筛选 updated_at ∈ [活动开始, 活动结束] 的收益订单；项目类型 ≠ 版权分销；按用户求和、排名、写快照。
  • 快照：snapshot_at、Top 100（rank、user_id、avatar、masked_nick、amount）、全量名次索引（供底栏查询本人 rank）。
  • 后台列表：排名、UID、脱敏昵称、活动期收益、计入订单数、最近计入更新时间、发奖档（1 / 2 / 3 / 4-10 … / 未进奖）。
  • 活动结束后任务停跑，保留最终快照。

3与海报风控的关系

  • 需回填项目须当天回填，否则该笔不计入有效收益。
  • 违规、刷量、作弊订单不予结算，不进榜。
  • 发奖前允许运营按活动方案审核调档；H5 不以调档实时改榜，最终对外以审核榜公示（若需要另开公示页，本 FR 不做）。
