# C 端显隐规则

判定顺序从上到下。未下发字段 = 未配置。

## 1. 进入显示池

| 条件 | 结果 |
|---|---|
| `visible=隐藏` | Banner、全部/进行中/已结束/已参与列表、详情均不出现 |
| `visible=显示` | 进入显示池，角标按时间算 |

角标：`now < startAt` → 待开始；`now ≥ startAt` 且（`endAt` 空或 `now ≤ endAt`）→ 进行中；`endAt` 有值且 `now > endAt` → 已结束。

## 2. 首页列表

Tab：**全部 / 进行中 / 已结束 / 已参与**。只过滤卡片，不撤置顶 Banner。

| 表面 | 规则 |
|---|---|
| 置顶 Banner | `pinned=true` 且在显示池；最多 1 条；**不随任一筛选 Tab（含已参与）隐藏**；取消置顶立即消失；不在下方列表重复 |
| 全部 | 显示池全部卡片 |
| 进行中 | 角标=进行中 |
| 已结束 | 角标=已结束 |
| 已参与 | 显示池 ∩ 该登录用户已参与集合；空 →「暂无已参与的活动」；不按角标再滤；隐藏后从本 Tab 消失 |
| 待开始 | **无独立筛选 Tab**；只出现在「全部」 |
| 列表空（非已参与） | 「暂无符合条件的活动」 |
| 卡片结构 | 图1；「查看」文案不因状态改变；标题下灰字 = `description`，与 `tags[]` 分开 |
| 浏览人数 | 始终「x人浏览」= `initialViews` |
| 参加人数 | 已下发 →「x人已参加」；未下发 → 不展示；**列表不展示参加人数后图** |
| 后图 | 本增量列表关闭；详情也不展示后图 |
| 已参与结果角标 | 列表 **不展示**。详情展位只走 `showUserAward`，见 §4。 |

## 3. 列表「查看」vs 领取

| 表面 | 行为 | 已参与 |
|---|---|---|
| 列表 / Banner「查看」 | **一律进入详情**；不外跳 | 本动作不记 |
| 待开始 / 已结束点领取 | 不可点 | 不记 |
| 进行中、领取且需跳转、跳转成功 | 打开配置地址 | 记一次（去重） |
| 进行中、领取且需跳转、跳转失败 | 不打开或打开失败 | 不记 |
| 进行中、领取且不需跳转 | 按钮文案变为 `clickedLabel` | 记一次（去重） |

废止 `listOutboundUrl`。领取按钮不读写任何活动级外链字段。登录能力已存在，本 FR 不单开未登录分支。无填写信息按钮、无表单提交。

## 4. 详情顶栏

页头文案固定「活动详情」，不放活动标题。活动信息是独立卡片：已下发 `cover` 时左封面（88px）+ 右标题、活动时间、标签；未下发 `cover` 则无封面。标签与列表卡片外层一致：活动 `tags[]` + `项目·{projects[]}`（项目名橙色强调）。不展示 @ 账号，不展示收藏。

第 2 步奖励规则 `showUserAward=true` **且已下发 `awardStatus`** 时，卡片与 Tab 区之间展示本人结果展位：不依赖是否有榜单、不依赖活动是否结束。`won` 显示恭喜获奖（可带 `awardPrize`）；`not_won` 显示未获奖。开关关闭或未下发 `awardStatus` 不展示展位。无审核中。详情内容配置页不展示该样式。列表卡片不打获奖角标。

顶区同时展示浏览人数、参加人数（参加人数未下发则不展示）。

信息卡片与下方 Tab/正文卡片在视觉上分离（各自白底圆角，中间留白）。

## 5. 详情 Tab

顺序固定：介绍 → 案例 → 榜单。缺则跳过。默认**从左起第一个实际存在的 Tab**。

| Tab | 出现当且仅当 |
|---|---|
| 介绍 | 已下发 `introContent` |
| 案例 | 已下发完整 `cases[]`（每条含名称 + 组成附件）且长度 ≥ 1 |
| 榜单 | `leaderboardVisible=开启` |

- 未配置的 Tab 整段不渲染。
- 实际存在 Tab 不足 2 个：不展示 Tab 栏，正文仍在独立内容卡片中。
- 禁止「我的作品」。
- 案例视频可播放（HTML5 controls + Mock 地址）；图片点击放大、长按保存（Demo）；案例卡片两列平铺。
- 榜单为列表：脱敏昵称、无标签；`leaderboardLineDesc` / `leaderboardPeriodDesc` 为后台配置字段名，已配才展示且为灰色小字不高亮；昵称与 `value` 与头像垂直居中。排名列宽固定，第 4 名起与前三对齐。底栏 `self` 本人排名（脱敏）；不在 TOP 内仍展示底栏。无颁奖台。空名单仍出 Tab（若该 Tab 被配置），空态「暂无榜单数据」。

详情底栏领取按钮（**仅介绍 Tab**）：

| 配置 | 结果 |
|---|---|
| `needClaimButtons=false` | 无底栏，不配按钮 |
| 无介绍 Tab | 无底栏（即使领取已配） |
| 开关开且当前 Tab 不是介绍 | 不展示底栏 |
| 开关开且 0 个已配按钮 | 无底栏 |
| 待开始或已结束 | 已配按钮展示但不可点；不记已参与 |
| 进行中、需要跳转且文案+地址齐全 | 打开地址；**客户端成功调起才记**已参与（不要求落地页 200） |
| 进行中、不需要跳转且文案+变更文案齐全 | 点击后按钮文案变为配置值，并记已参与 |

最多 2 个。半填不下发。两个按钮点任一即同一条已参与。

## 6. 已参与记账

写入（已登录；随后去重）：

1. 进行中点击不需跳转的已配置领取按钮。
2. 进行中点击需跳转的已配置领取按钮 **且跳转成功**。

不记：列表或 Banner「查看」；待开始/已结束点击；跳转失败；隐藏活动；未登录会话（本 FR 不单开未登录页）。

去重：`(userId, activityId)` 已存在则保持原记录。无表单校验/提交路径。无获奖字段写入已参与表。

深链打开 `visible=隐藏` 的活动：当详情不存在，C 端停在列表。

闭合矩阵、能力入参出参见 `fe-be-contract.md`。
