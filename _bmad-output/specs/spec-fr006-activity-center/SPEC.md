# 活动中心（FR-006 v2）

## Why

**痛点 + 机会。** v1 只改了列表（Banner、浏览/参加人数、显示/隐藏），并写明不重做详情。运营要把详情做成可配置容器（介绍 / 案例 / 榜单），用领取按钮承接参与，用「已参与」记入领取点击，并在第 2 步配置奖励规则。列表/Banner「查看」只进详情，不外跳。榜单由后台开启/隐藏控制。本人已获奖/未获奖展位由第 2 步奖励规则开关 `showUserAward` 控制。列表合同保留。

## Capabilities

- **CAP-1**
  - **intent:** 运营配置活动基础信息、显示/隐藏与是否置顶；用户只看到显示池内活动的置顶 Banner 与图1卡片列表。
  - **success:** 隐藏活动不进 Banner、四个列表 Tab 与详情；显示活动必带「x人浏览」；参加人数按 `visibility-rules.md` 显隐；列表不展示参加人数后图。筛选「全部 / 进行中 / 已结束 / 已参与」只过滤卡片、不撤 Banner；无「待开始」筛选 Tab。置顶按 v1，显示池内最多 1 条。

- **CAP-2**
  - **intent:** 用户打开活动详情时，只看到后台已配置的 Tab，且落在第一个实际存在的 Tab。
  - **success:** Tab 只能是「介绍 / 案例 / 榜单」的已配置子集；介绍须有正文；案例须至少 1 条完整条目（名称 + 图片或视频组成）；图片可点放大、长按保存；视频须可播 Mock。榜单须 `leaderboardVisible=开启`；未配置的整 Tab 不出现；无「我的作品」。顶栏左侧封面来自后台「封面」；未下发则不展示封面。

- **CAP-3**
  - **intent:** 运营决定是否需要领取按钮，并配置最多 2 个（文案 + 跳转或点击后变更文案）。
  - **success:** `needClaimButtons=false` 或 0 条已配置则无底栏；半填不下发；需跳转则文案与地址都非空才下发；不需跳转则文案与点击后变更文案都非空才下发。待开始或已结束时按钮不可点。底栏领取**仅「介绍」Tab**展示，案例与榜单不展示。

- **CAP-4**
  - **intent:** 列表/Banner「查看」只进详情；详情底栏领取按钮独立配置，互不同步。
  - **success:** 「查看」一律进详情，不外跳、不因该点击记已参与；改领取按钮不得改写「查看」行为。废止活动级外链。

- **CAP-5**
  - **intent:** 已登录用户在首页「已参与」看到自己成功领取过的活动。
  - **success:** 不需跳转：点击领取即记一次。需跳转：仅跳转成功才记，失败不记。待开始/已结束的点击不记。同一用户同一活动只留一条；空态「暂无已参与的活动」；切到该 Tab 时置顶 Banner 仍展示；不得因列表/Banner「查看」出现记录。

- **CAP-6**
  - **intent:** 运营在第 2 步奖励规则决定是否展示本人获奖/未获奖信息；开启后详情在信息卡片与 Tab 之间展示展位。
  - **success:** 仅 `showUserAward=true` 且已下发 `awardStatus`（`won` / `not_won`）时展示展位；已获奖可带 `awardPrize`。不绑定榜单开关、不绑定活动是否结束。开关关闭或未下发 `awardStatus` 不得出现展位。详情内容配置不展示该样式。无审核中态。列表卡片无获奖角标。CAP-6 编号沿用。

- **CAP-7**
  - **intent:** 运营在第 1 步详情内容配置榜单：开启或隐藏；开启后填写 TOP 名单数（前 x 名）。C 端按固定格式展示后端返回的行。
  - **success:** 隐藏则无榜单 Tab。开启才下发 `leaderboardVisible` + `leaderboardLimit`，并出现榜单 Tab。能力「活动榜单」返回 `self` 与行：`rank`、`avatarUrl` 或头像初文、脱敏 `nicknameMasked`、`value`。禁止昵称旁标签。行描述 / 周期描述来自后台字段名 `leaderboardLineDesc` / `leaderboardPeriodDesc`，未填不展示；C 端为灰色小字不高亮。昵称与金额/奖品与头像垂直居中。排名列宽固定，第 4 名起与前三对齐。无颁奖台。不投影奖励管理五列。CAP-7 编号沿用。

- **CAP-8**
  - **intent:** （废止）本 FR 不交付报名表单字段配置与提交面。
  - **success:** 增量中不得出现表单控件表或表单提交记已参与；参与只走领取按钮；CAP-8 编号永不复用。

- **CAP-9**
  - **intent:** （废止）本 FR 不交付奖励管理的配置、写入或改表。
  - **success:** 增量中不得出现新的奖励管理页、写入接口或名单表结构；CAP-9 编号永不复用。

- **CAP-10**
  - **intent:** （废止）不再交付第 3 步奖励规则空态占位。
  - **success:** 不得再验收「三步向导且第 3 步不可填」；奖励规则改由 CAP-11 交付；CAP-10 编号永不复用。

- **CAP-11**
  - **intent:** 运营在第 2 步为本活动添加奖励规则（播放奖 / 全勤奖 / 累计项目收益奖）。
  - **success:** 可添加 0–N 条；不完整规则不下发；添加入口为「奖励规则」标题旁「添加规则」。播放奖 / 累计项目收益奖阶梯字段与控件同一行不换行（区间 x~y + 奖品类型，奖金/实物礼品选后出输入框）。累计项目收益奖参与范围为 `brandProjects[]` 与 `otherBizProjects[]`（两类至少一类）；禁止排除项目字段。完整性与命中顺序见 `fe-be-contract.md` §4。

## Constraints

- v2 推翻 v1「本 FR 不重做详情页」；详情必须按 CAP-2 装配。
- 详情 Tab 仅介绍/案例/榜单的已配置子集；禁止「我的作品」。
- 废止活动级外链；领取按钮独立，禁止把「查看」做成外跳或与领取按钮互为默认值。
- 已参与去重键为（用户, 活动）；重复成功领取不新增行。
- 新增/编辑必须两步：第1步=基础信息+介绍+案例+榜单；第2步=活动领取+奖励规则。禁止三步空态，禁止改回单页平铺三组。
- 领取按钮不是 `form` 类型；禁止恢复按条 `url|form`；禁止独立报名表单。
- 待开始或已结束禁止点领取；该点击不记已参与。
- 需跳转的领取：跳转失败不记已参与。
- 榜单行禁止投影奖励管理名单五列；禁止发明 HTTP 路径，能力名「活动榜单」。
- 本人获奖展位仅 `showUserAward=true` 时下发 `awardStatus`；禁止审核中态；禁止在详情内容配置页展示该样式。
- 禁止本 FR 新增/改造奖励管理页、写入接口、名单表，禁止发明其 HTTP 路径。
- 案例完整条目 = 名称非空且组成附件 ≥1；半填不下发。
- C 端生命周期角标由开始/结束时间计算，不是后台「显示/隐藏」。
- 浏览人数取后台初始浏览量；C 端不累加、不编造。
- 必填才能保存：活动标题（≤64）、开始时间、活动状态（显示/隐藏）；结束时间有值且早于开始则拒绝保存。
- 置顶：活动编辑「是否置顶」（v1）；显示且置顶的最多 1 条；冲突处理见 `admin-fields.md`。
- 交付形态遵循 `ITERATION-FR-GUIDE.md`。
- 登录不在本 FR 范围；站内可登录已存在。本 FR 不单开未登录分支。

## Non-goals

- 不下发审核中态。
- 不把列表「查看」改成可配文案。
- 不改礼品中心。
- 不把参加人数改成真报名人头。
- 不重做图1卡片结构。
- 不重做站内登录。
- 不把奖励管理后台列铺到 C 端。
- 不交付报名表单。

## Success signal

运营走两步保存：第1步配封面、写介绍、至少一条完整案例，可开启榜单并填前 x 名；第2步打开领取开关、配 1 个领取按钮，并添加至少一条完整奖励规则。C 端 Banner 固定在顶。详情信息卡片与 Tab 区分离。仅介绍时无 Tab 栏。开启榜单的活动有榜单列表（无颁奖台）及已获奖或未获奖展位。点「查看」进详情且不记已参与。进行中点不需跳转的领取进入已参与；需跳转且失败则不出现在已参与。待开始/已结束领取不可点。已参与空态为「暂无已参与的活动」，Banner 仍在。

## Assumptions

- 介绍 Tab 正文 = v1 活动内容富文本；无正文则介绍 Tab 未配置。
- 第1步基础信息含：标题、活动描述 `description`、标签、平台、赛道、项目、周期、浏览量、参加人数、显示/隐藏、置顶、封面 `cover`。描述与标签分开取值。
- `cover` 为图片；详情顶栏左侧按 88px 展示；未下发不展示封面；列表/Banner 不强制用封面。
- 已参与卡片沿用图1；只列出仍在显示池的活动。
- 已参与记账发生在已登录会话。
- 显示池内同时只能有 1 条置顶；不得同时存在两条显示中的置顶。
- 案例按条展示名称 + 图片或视频（视频 HTML5 controls）。
- `rewardRules` 仅完整规则下发；C 端不展示规则正文。
- 达标用户「奖励计算」按本活动已下发规则计算，不是新的奖励管理录入页。
- 后台列表「排序」列为展示，本 FR 不新增独立排序写入字段，沿用既有列表序。
- 能力「活动榜单」返回已按 `leaderboardLimit` 截断的行；`value` 已是展示串。行描述 / 周期描述由后台字段下发。Demo 用 Mock，不发起真实 HTTP。
- `awardStatus` 由后端按当前用户×活动×本活动 `rewardRules` 计算，不是后台编辑字段；仅 `showUserAward=true` 时下发。闭合边界见 `fe-be-contract.md`。
