# 一键代发 · 与现有模块的边界

- **不是 FR-001 代发分配。** 那是 OPC 协作结算里的关键词/帐号分配（已暂停）。本增量是稿件市场：剪辑手供稿、用户领取。
- **不是 FR-002 代发收益。** 那是代发成员收益管理（已上线）。本增量详情只展示分成比例，广场与领取列表禁止展示收益金额，不沿用代发成员收益页。
- **不改 FR-012 选书中心、FR-013 AI申词 文件。** 领取词=用户自主申请且状态为审核通过待发布或审核通过已回填的词；C 端只拉取现有申词结果并浮层选词，不重定义审核态。项目管理不维护已通过关键词，与项目新增无关。
- **剪辑手分账消费现有关键词订单收益。** 不另建收益账本，不改 FR-002 代发收益页（主子协议）。已结算/待结算沿用平台关键词订单结算态。代发绑定主键 `(keywordId, claimId)` 且已回填；分成读领取快照。写入既有项目收益明细是入账拆账的显式增量。
- **回填复用该项目已有回填页。** 本 FR 只接领取后的入口并做必要调整，不重列字段、不另做一套回填表单。后台领取记录「回填信息」列出示该页已有视频链接，不新造字段。
- **项目管理消费现有品牌项目。** 新增从品牌项目库列出全部项（已加入的仍列出），带出名称与 Logo；已添加则保存拦截。本 FR 不新建品牌项目主数据。
- **新独立 FR-014。** 主入口按 ITERATION-FR-GUIDE：`demo/iteration/fr-opc-yijian-daifa.html` 页内 Tab（业务解释 / 前端交互 / PC端 / 管理后台 / 前后端数据交互）+ 规则抽屉。PC 端是已有创作者中心上的剪辑供稿增量，不是新 PC 产品。完整且唯一的 FR 见 `requirements.md`。
- **交付约束（adopted：ITERATION-FR-GUIDE）：** C 端橙色；Mockup 只 iframe；本 FR 例外：用 localStorage 做 C/PC/后台逻辑闭环，不做真实接口；流程图手写 SVG，不用 Mermaid；不改 Sidebar 全局架构。各端另挂「开发提示词」，合同见 `impl-prompts.md`，渲染源 `demo/iteration/yijian-daifa-impl-prompts.js`。
- **现有 Demo 里的「剪辑手」字样**（FR-001 成员角色）不是本增量的客服招募/后台录入体系，禁止复用那套分配记录当供稿/领取。
