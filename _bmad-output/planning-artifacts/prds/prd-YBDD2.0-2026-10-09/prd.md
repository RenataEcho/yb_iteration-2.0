## 1. Vision

代发 1.0 的稿件只有一条领取路：用户自己选一个已通过关键词，再扣次下载。剪辑手档案上也只有一个分成比例。运营现在要把稿分成两种合作：任务协作仍由用户选词；帐号运营由剪辑手在上传时，把自己申请并通过、且属于这本书的一个关键词绑到稿上，用户领的时候不再选词。

同一名剪辑手可以同时做这两种，每种单独一个分成比例。用户领完后的回填不再只能填一次。下载过程从页面内的 loading 改成可中断的弹窗，保存成功后再提示去回填。海外故事和海外短剧进项目表，这两类的快捷题词去海外任务详情领口令。PC 上传按项目所属系列校验书籍 ID 或链接。

这一刀用新建页面交付。新页面先还原代发 1.0 的样子，再加本增量，这样和 1.0 对得上，又不会改动已经在用的 1.0 文件。迭代 2.0、迭代 3.0、收益池各自留在自己的页面上，不把它们的官方申词、任务池或收益池规则带进本增量。

## 2. Target User

### 2.1 Jobs To Be Done

- **用户**：在作品广场按运营模式分开找稿。领帐号运营稿时不选词；领任务协作稿时仍选自己已通过、且和这本书一致的关键词。下载时能看见进度并能中断。保存成功后知道要去回填，回填过一次之后还能再填。
- **剪辑手**：上传时先声明这条约稿是任务协作还是帐号运营。帐号运营必须选中一个自己申请并通过、且属于该书的关键词。上传前，字节系的书籍 ID、知乎系的书籍链接、海外系在海外任务库里的命中，要先过校验。之后能在 PC 上看到这条约稿的回填数据。
- **运营**：在剪辑手档案上勾选代运营合作模式，每个已选模式单独写分成比例。在领取记录里看到每一次回填，而不只是第一次。

### 2.2 Non-Users (v1)

- 要在本增量里走官方帐号批量申词、剪辑任务池、或收益池限时领次的人。那些留在 FR-020、FR-017。
- 要改创作者首页 2.0 的人。那是 FR-021。
- 要在产品里完成剪辑的人。剪辑仍在产品外。

### 2.3 Key User Journeys

`[ASSUMPTION: 主人公沿用既有一键代发称呼：林晓是领取用户，周凯是剪辑手，赵敏是运营。]`

- **UJ-1. 林晓切到帐号运营，不选词就领走一稿。**
  - **Persona + context:** 林晓会发抖音，自己不做片。她要领一条已经绑好关键词的稿。
  - **Entry state:** 已登录，打开代发 1.0 作品广场。
  - **Path:** 点运营模式 Tab「帐号运营」→ 进入一条帐号运营稿的详情 → 点领取 → 停权和次数通过后不再出现选词浮层 → 下载弹窗走完保存。
  - **Climax:** 相册里有成片，这次领取写下的关键词是剪辑手上传时选的那一个，不是她当场选的。
  - **Resolution:** 弹出回填提示。她可以去回填，也可以稍后从我的领取再去。
  - **Edge case:** 次数不够时仍进兑换，不扣次，不出现选词，也不出现下载弹窗。

- **UJ-2. 林晓领任务协作稿，仍要选和这本书一致的词。**
  - **Persona + context:** 同林晓。她自己有已经通过的关键词。
  - **Entry state:** 广场停在运营模式 Tab「任务协作」。
  - **Path:** 打开详情 → 领取 → 停权、次数通过后打开选词浮层 → 选一个与该稿书籍一致的已通过关键词 → 确认 → 下载弹窗保存成功 → 回填提示。
  - **Climax:** 领取记录上的关键词是她选的那一个。
  - **Resolution:** 停在已领取详情。24 小时回填时限从这次领取成功起算，规则仍按 FR-014。
  - **Edge case:** 词的书籍 ID 与稿件书籍 ID 不一致时不能确认，不扣次。

- **UJ-3. 林晓中断下载；已经回填过的稿她再填一次。**
  - **Persona + context:** 同林晓。一条任务协作或帐号运营稿都可能走到这里。
  - **Entry state:** 门禁已通过，下载弹窗还停在保存完成之前。
  - **Path:** 点中断下载，弹窗关闭 → 之后她从我的领取再次进入并下载成功 → 若这是本次领取的首次保存成功，再看到回填提示 → 提交回填 → 过一段时间再次打开回填并再提交一次。
  - **Climax:** 第二次回填提交成功，后台和周凯的 PC 上都能看到两条回填数据。
  - **Resolution:** 稿件仍不回到广场。占用保持已完成。次数不退。
  - **Edge case:** 从未回填且满 24 小时，仍按 FR-014 释放占用并记未回填。已回填之后不再走这条释放。

- **UJ-4. 林晓在海外短剧稿上点快捷题词，去领口令。**
  - **Persona + context:** 同林晓。稿件项目是海外短剧或海外故事。
  - **Entry state:** 未领取详情，底部仍有快捷题词。
  - **Path:** 点快捷题词 → 打开该书在海外任务库中的任务详情 → 在那个页面领取口令。
  - **Climax:** 她拿到口令。这次点击不领取稿件，不扣次。
  - **Resolution:** 回到稿件详情后，领取稿件仍走 UJ-1 或 UJ-2，看运营模式。
  - **Edge case:** 海外任务库没有这本书的任务时，提示无法跳转，不扣次。

- **UJ-5. 赵敏给周凯打开两种合作，并各写一个比例。**
  - **Persona + context:** 赵敏在右豹后台维护剪辑手。周凯两种稿都要传。
  - **Entry state:** 已登录后台，打开代发 1.0 的剪辑手管理。
  - **Path:** 编辑周凯 → 代运营合作模式勾选任务协作分成和帐号运营分成 → 两个比例分别填写 → 保存。
  - **Climax:** 列表和详情能看出他两种都开了，以及各自的比例。
  - **Resolution:** 之后他上传的任务协作稿，领取快照用任务协作分成比例；帐号运营稿用帐号运营分成比例。
  - **Edge case:** 只勾了一种时，另一种比例留空，他不能上传另一种稿。

- **UJ-6. 周凯上传一条帐号运营稿，先过书籍校验，再绑关键词。**
  - **Persona + context:** 周凯在剪辑手 PC 交稿。帐号运营分成已由赵敏勾选并写了比例。
  - **Entry state:** 已登录 PC，打开上传。
  - **Path:** 选项目、书、图集或视频 → 运营模式选帐号运营 → 按该项目系列校验书籍 ID 或链接 → 从自己申请并通过、且属于该书的关键词里选一个 → 提交审核。
  - **Climax:** 稿件带上运营模式和那个关键词，审核通过后只出现在广场的帐号运营 Tab。
  - **Resolution:** 用户领走并回填后，周凯在 PC 上看到回填数据。
  - **Edge case:** 校验不通过，或这本书上没有周凯自己申请并通过的关键词，提交不出去。别人申请的词即使已通过，也不出现在他的候选里。

## 3. Glossary

下游必须用这些词。FR-014 已定义且本文件没改写的词，含义不变。

- **一键代发** — 剪辑手供稿、用户领取后发布变现。本增量在代发 1.0 页面上增加运营模式、分模式分成、可重复回填、下载弹窗和海外题词跳转。
- **运营模式** — 一条约稿的合作方式。只有两个值：任务协作、帐号运营。一条约稿只有一个，上传时选定。
- **任务协作** — 运营模式之一。用户领取时自己选择已通过关键词。剪辑手上传这种稿时不选关键词。
- **帐号运营** — 运营模式之一。剪辑手上传时选定一个已通过关键词：申请人是这名剪辑手，且关键词所属书籍就是这本。只选一个。用户领取时不出现选词。
- **代运营合作模式** — 剪辑手档案上的多选字段。选项是任务协作分成、帐号运营分成。勾上哪一项，这名剪辑手才能上传对应运营模式的稿，并使用那一项自己的分成比例。
- **任务协作分成** — 代运营合作模式的选项，对应任务协作。勾选后必须填写任务协作分成比例。
- **帐号运营分成** — 代运营合作模式的选项，对应帐号运营。勾选后必须填写帐号运营分成比例。
- **任务协作分成比例** — 挂在剪辑手档案上的百分比。任务协作稿领取成功时写入分成快照。
- **帐号运营分成比例** — 挂在剪辑手档案上的百分比。帐号运营稿领取成功时写入分成快照。
- **已通过关键词** — 该书、该项目下，申词状态为审核通过待发布或审核通过已回填的关键词。口径沿用 FR-014 领取可选词，不新造词状态。
- **作品广场** — 代发 1.0 用户端宫格。本增量在原有项目图标和筛选之上增加运营模式 Tab。
- **快捷题词** — 未领取稿件详情底部的入口。沿用 FR-014：不领取、不扣次。海外故事与海外短剧改为跳到该书的海外任务详情。
- **海外任务库** — 已有的海外任务数据。本增量只拿它做上传校验，并提供任务详情页领取口令。不新造任务库。
- **海外任务详情** — 海外任务库里某一条任务的详情页。快捷题词跳到与该书对应的那一条。
- **口令** — 用户在海外任务详情上领取的代码。它不是已通过关键词，也不代替领取稿件时的选词。
- **回填数据** — 某次领取上的一条回填提交。字段沿用该项目已有回填表单，并带提交时间。一条领取可以有多条回填数据。
- **下载弹窗** — 领取确认后的进度层。承接原来的三态：正在下载稿件、正在保存到相册、已保存到相册。上面有中断下载。
- **回填提示** — 本次领取第一次保存成功后的弹窗。去回填，或稍后。
- **字节系** — 项目表上归为字节系列的项目。上传时校验书籍 ID。
- **知乎系** — 项目表上归为知乎系列的项目。上传时校验书籍链接。
- **海外系** — 项目表上归为海外系列的项目。本增量至少包括海外故事、海外短剧。上传时校验海外任务库。
- **分成快照** — 领取成功时写下的剪辑手 ID 和当时的对应模式分成比例。之后改档案比例，不重算已经写下的快照。沿用 FR-014 的快照时点。
- **历史增量页** — FR-017 收益池、FR-018 迭代 2.0、FR-020 迭代 3.0、FR-021 创作者首页。本增量不改这些页面，也不采纳它们的规则。

## 4. Features

### 4.1 运营模式

**Description:** 每条约稿在上传时带一个运营模式。作品广场用 Tab 分开看。任务协作仍走 FR-014 的选词领取。帐号运营跳过选词，关键词用上传时绑上的那一个。实现 UJ-1、UJ-2。

`[ASSUMPTION: 运营模式在提交上传后不能改。审核驳回后重新提交可以改。]`
`[ASSUMPTION: 广场默认停在任务协作 Tab，因为那是 1.0 现有领取方式。]`
`[ASSUMPTION: Tab 放在项目图标上方。切换 Tab 不重置当前项目和其余筛选，只隐藏另一个运营模式的稿。]`

**Functional Requirements:**

#### FR-1: 稿件绑定一个运营模式

剪辑手上传的右豹稿必须有且只有一个运营模式。

**Consequences (testable):**
- 值只能是任务协作或帐号运营。
- 未选择不能提交。
- 审核通过并进入广场后，稿件详情能看出它属于哪一个运营模式。
- 站外稿不增加运营模式。`[ASSUMPTION: 站外稿仍按 FR-014-30，不进广场，也不走本增量的选词和分成。]`

#### FR-2: 广场按运营模式分 Tab

用户在作品广场用 Tab 切换任务协作和帐号运营。实现 UJ-1、UJ-2。

**Consequences (testable):**
- 两个 Tab 都沿用 1.0 的项目图标、剪辑师、素材、图集或视频筛选，以及原有的进广场条件。
- 任务协作 Tab 只列出运营模式为任务协作的稿。帐号运营 Tab 只列出运营模式为帐号运营的稿。
- 切换 Tab 后空列表仍用 1.0 的空态，不另做一套。

#### FR-3: 帐号运营领取不选词

用户领取帐号运营稿时跳过选词。实现 UJ-1。

**Consequences (testable):**
- 门禁顺序改为：停权 → 剩余次数 → 资格 / 占用。不打开选词浮层。
- 停权、次数不足、资格失败、被占用时的提示和「不扣次」沿用 FR-014-11。
- 通过后仍扣 1 次，先免费后已购。占用、未回填、分成快照仍在同一笔里写下。失败整笔回滚。
- 这次领取的关键词等于上传时绑上的那一个已通过关键词。该词的申请人是上传这条约稿的剪辑手，所属书籍与稿件相同。用户不能改。
- 详情不再要求用户先选词才能点领取。

**Out of Scope:**
- 不改停权次数门槛、免费次数和积分档位。

#### FR-4: 任务协作领取仍选词

用户领取任务协作稿时，选词门禁保持 FR-014-11。实现 UJ-2。

**Consequences (testable):**
- 顺序仍是：停权 → 剩余次数 → 选词 → 资格 / 占用。
- 可选词仍是该用户在该项目的已通过关键词。词带书籍 ID 时必须与稿件书籍 ID 一致。
- 未选词不能确认，不扣次。

**Notes:**
- `[NOTE FOR PM]` 海外项目的任务协作是否改为领口令而不选关键词，见 §8。

### 4.2 回填可以再填

**Description:** 1.0 在回填成功后不允许再进回填页。本增量拿掉这道限制。首次回填仍把占用写成已完成，稿件不回广场。之后的回填只追加回填数据。后台领取记录和剪辑手 PC 都能看到这些数据。实现 UJ-3、UJ-6。

`[ASSUMPTION: 再次回填是追加一条，不覆盖上一题。已回填状态保持已回填。不退次数，不把稿件放回广场，不把占用从已完成改回占用中。]`
`[ASSUMPTION: 24 小时未回填释放、终身未回填超过 3 次停权，只针对还没有任何一条回填数据的领取。已有回填数据之后，不再记未回填，也不再释放。]`

**Functional Requirements:**

#### FR-5: 已回填领取可以继续回填

领取人在首次回填成功后，仍可再次提交回填。实现 UJ-3。

**Consequences (testable):**
- 我的领取里，已回填记录的「立即回填」进入该项目已有回填页，并带上原来的 claimId。不再 toast「该稿件已回填」。
- 再次提交不得修改领取时的项目、书籍、关键词。字段仍是该项目已有回填表单。
- 每次成功追加一条回填数据，含提交时间。
- 已超时且从未回填的记录仍不能回填，toast 沿用 FR-014。
- 首次回填成功时：领取变为已回填，占用变为已完成，写下首次回填时间。这些效果不因后来的再次回填而撤销。

#### FR-6: 后台和剪辑手能看到回填数据

运营在领取记录、剪辑手在 PC 上查看回填数据。实现 UJ-3、UJ-6。

**Consequences (testable):**
- 后台领取记录的回填信息不再只表示有或没有。没有回填数据时仍是「—」。有则能看到每一条的提交时间和回填表单内容，含作品链接。
- 剪辑手 PC 只出示自己上传的稿所关联的回填数据。字段与后台相同。
- `[ASSUMPTION: 列表上先给出最近一条的提交时间和作品链接，点开再看全部回填数据。]`
- 用户端广场、详情、领取列表仍不展示收益金额。

### 4.3 分模式分成

**Description:** 剪辑手档案上的单一分成比例，改成代运营合作模式多选，每个已选模式各一个比例。领取快照取这条约稿所属模式的比例。入账公式仍是 FR-014-27，只是快照里的比例换成对应模式的那一个。实现 UJ-5。

`[ASSUMPTION: 比例是 0 到 100 的整数百分比。两个比例互不影响，不要求相加不超过 100。]`
`[ASSUMPTION: 入账仍是剪辑手分账 = 四舍五入（应结算 × 该次分成快照）；用户实结 = 应结算 − 分账。不在本增量另设一个用户分成比例。]`
`[ASSUMPTION: 存量剪辑手迁移为只勾选任务协作分成，任务协作分成比例等于原来的分成比例；帐号运营分成不勾选，比例为空。]`

**Functional Requirements:**

#### FR-7: 剪辑手档案按模式设比例

运营在剪辑手管理里维护代运营合作模式。实现 UJ-5。

**Consequences (testable):**
- 字段为多选：任务协作分成、帐号运营分成。至少勾选一个才能保存。
- 勾选的每一项必须填写自己的分成比例。未勾选的比例留空，保存时不要求填写。
- 未勾选任务协作分成的剪辑手，不能把运营模式选成任务协作并提交。未勾选帐号运营分成的，不能提交帐号运营稿。
- 两个都不勾选时，PC 上传不能提交右豹稿。
- 改今天的比例，不改已经领取成功的分成快照，不重算已经入账的明细。

**Out of Scope:**
- 不改停用、删除、发布平台、可上传项目这些既有字段的规则。

#### FR-8: 领取快照使用对应模式的比例

领取成功时，分成快照取该稿运营模式对应的比例。

**Consequences (testable):**
- 任务协作稿的快照比例 = 领取当时该剪辑手的任务协作分成比例。
- 帐号运营稿的快照比例 = 领取当时该剪辑手的帐号运营分成比例。
- 详情上的分成比例只显示这一个快照值，不并列两个比例。`[ASSUMPTION: 未领取详情显示剪辑手当前的对应比例；领取成功后显示快照，不再跟着档案改。]`
- 结算仍要求该领取至少有一条回填数据，其余时点沿用 FR-014-27。一词多条已回填绑定时，仍取首次回填时间最近的那条领取。再次回填不改变「最近首次回填」的比较键。

### 4.4 下载弹窗与回填提示

**Description:** 领取确认且门禁通过后，原来的页内 loading 改为下载弹窗，可中断下载。本次领取第一次保存成功后，增加回填提示。两种运营模式都适用。实现 UJ-1、UJ-2、UJ-3。

`[ASSUMPTION: 中断下载只关闭未完成的下载和保存，不退还已经扣掉的次数，不解除占用，不删除未回填记录。用户从我的领取可以再次下载。]`
`[ASSUMPTION: 回填提示只在该次领取第一次保存成功时出现。从我的领取再次下载成功不再出现。中断未保存成功时不出现。]`

**Functional Requirements:**

#### FR-9: 下载过程使用可中断弹窗

领取确认后的下载和保存发生在下载弹窗里。实现 UJ-3。

**Consequences (testable):**
- 弹窗在门禁通过、次数已扣、占用已写下之后出现。
- 文案顺序仍是：正在下载稿件 → 正在保存到相册 → 已保存到相册。
- 保存完成之前提供中断下载。点中断后弹窗关闭，不拉起抖音。
- 保存成功后的抖音拉起仍按 FR-014-28。中断不拉起。
- 我的领取里的再次下载使用同一个弹窗，也可以中断。中断不改变这条领取记录的回填状态。
- 3 天下载窗、过期 toast、云端失效 toast 仍按 FR-014-19。那些情况下不打开下载弹窗。

#### FR-10: 首次保存成功后提示回填

下载弹窗第一次保存成功后，出示回填提示。实现 UJ-1、UJ-2。

**Consequences (testable):**
- 主按钮「去回填」打开该项目已有回填页，并带上本次 claimId。
- 次按钮「稍后」关闭提示，停在已领取详情。
- 提示不自动提交回填，也不延长或缩短 24 小时时限。
- 24 小时的起算点仍是领取成功写下未回填记录的时刻，不是用户关掉提示的时刻。

### 4.5 海外故事与海外短剧

**Description:** 一键代发项目增加海外故事、海外短剧。这两类稿件详情上的快捷题词，改为跳到对应海外任务详情领取口令。其它项目的快捷题词仍去该项目题词页。实现 UJ-4。

`[ASSUMPTION: 两个项目从既有品牌项目库加入代发项目表，名称和 Logo 由项目库带出。本增量不新造项目主数据字段。]`
`[ASSUMPTION: 口令的生成、占用和失效沿用海外任务详情已有规则。本增量只负责跳进该书对应的那一条。]`

**Functional Requirements:**

#### FR-11: 项目表收入海外故事和海外短剧

运营可以把海外故事、海外短剧加进一键代发项目并启用。

**Consequences (testable):**
- 加入后的启用、禁用、排序沿用 FR-014-24。
- 启用后，剪辑手可在 PC 选择该项目上传，用户可在广场按项目图标筛到它。
- 禁用后不可新上传，也不进广场。规则沿用 FR-014-24。

#### FR-12: 海外项目的快捷题词去领口令

海外故事、海外短剧的未领取详情，快捷题词打开对应海外任务详情。实现 UJ-4。

**Consequences (testable):**
- 跳转不领取稿件、不扣次、不占用。
- 落地页是该书在海外任务库中的海外任务详情，用户在该页领取口令。
- 找不到对应任务时提示无法跳转，详情留在原地，不扣次。
- 任务协作和帐号运营只要项目是这两类，快捷题词都走这条。其它项目仍跳该项目题词页。
- 领取稿件的选词或跳过选词，仍只看运营模式，不看是不是海外项目。

### 4.6 PC 上传校验

**Description:** 上传右豹稿时增加运营模式。帐号运营必须从剪辑手本人申请、已经通过、且属于当前这本书的关键词里单选一个。书籍 ID 和书籍链接按系列做存在性校验：字节系校验 ID，知乎系校验链接，海外系校验海外任务库。实现 UJ-6。

`[ASSUMPTION: 一次上传仍是一个项目、一本书、一种稿件类型、一个运营模式。]`
`[ASSUMPTION: 书籍名称、书籍 ID、书籍链接三个字段都仍然必填。系列校验是在必填之外的命中校验。]`
`[ASSUMPTION: 系列归属读项目表上的系列，不在本文件写死番茄、红果或其它品牌名单。]`
`[ASSUMPTION: 校验调用已有书库或海外任务库。本增量不新造这三套库，也不定义对方接口的字段。命中失败则不能提交，并指出是书籍 ID、书籍链接还是海外任务库没有命中。]`

**Functional Requirements:**

#### FR-13: 上传时选择运营模式并在帐号运营绑定关键词

剪辑手在 PC 上传右豹稿时选择运营模式。帐号运营必须绑定一个已通过关键词，申请人是这名剪辑手，且属于当前这本书。只选一个。实现 UJ-6。

**Consequences (testable):**
- 运营模式为必填，选项只有任务协作、帐号运营。选项受 FR-7 的勾选限制。
- 选择任务协作时不出现关键词选择。
- 选择帐号运营时，候选只有同时满足这三件事的关键词：申词状态是已通过关键词，申请人是当前这名剪辑手，关键词上的书籍 ID 等于当前书籍 ID。必须且只能选一个。未选不能提交。
- 别人申请的词、不带这本书书籍 ID 的词、待审核或已驳回的词，都不出现在候选里。
- 候选为空时不能提交。
- 换项目或换书之后，已选关键词清空，要重选。
- 审核通过后，该关键词随稿件进入帐号运营 Tab，供 FR-3 在领取时使用。

#### FR-14: 按系列校验书籍 ID 或链接

PC 上传提交前，按项目系列校验书籍。实现 UJ-6。

**Consequences (testable):**
- 字节系：书籍 ID 必须在该项目书库命中。未命中不能提交。
- 知乎系：书籍链接必须在该项目书库命中。未命中不能提交。
- 海外系：当前书籍必须在海外任务库命中一条任务。未命中不能提交。海外故事、海外短剧属于海外系。
- 三个字段的空值校验先于命中校验。空值不能靠另一项已经填写而通过。
- 站外稿不走这三项命中校验。

**Notes:**
- `[NOTE FOR PM]` 一个项目若同时被标成两个系列，或没有系列，见 §8。提交前不能靠猜系列放行。

## 6. MVP Scope

### 6.1 In Scope

- 广场运营模式 Tab，以及两种领取路径。
- 已回填可继续回填；后台与剪辑手 PC 展示回填数据。
- 剪辑手档案的代运营合作模式，以及按模式快照分成。
- 下载弹窗、中断下载、首次保存成功后的回填提示。
- 海外故事、海外短剧进项目表；这两类快捷题词跳海外任务详情领口令。
- PC 上传的运营模式、帐号运营绑词、三类系列校验。
- 上述界面落在代发 1.0 的三份页面上。

### 6.2 Out of Scope for MVP

- 从迭代 2.0 / 3.0 / 收益池页合并视觉或规则。原因：用户要求避免页面再分叉。
- 中断下载时自动退次。原因：1.0 的扣次发生在下载完成之前；是否退次仍见 §8。
- 为海外项目取消任务协作的选词。原因：口令和关键词在本文件里是两件事。
- 站外稿的运营模式、绑词和系列校验。

## 7. Success Metrics

**Primary**

- **SM-1**: 帐号运营领取路径上，选词浮层出现次数为 0，且成功领取仍扣 1 次并保存到相册。Validates FR-3、FR-9。
- **SM-2**: 已有回填数据的领取可以再次提交成功；后台和该稿剪辑手的 PC 都能看到新的一条回填数据。Validates FR-5、FR-6。
- **SM-3**: 未勾选的代运营合作模式不能被用来提交对应稿件；已勾选模式的领取快照等于提交当时的那个比例。Validates FR-7、FR-8。
- **SM-4**: 书籍 ID、书籍链接或海外任务库未命中时，上传不能进入审核。Validates FR-14。

**Secondary**

- **SM-5**: 海外故事、海外短剧的快捷题词点击不扣次；有对应任务时打开海外任务详情，没有时留在详情并提示。Validates FR-12。

**Counter-metrics (do not optimize)**

- **SM-C1**: 不要为了让帐号运营少一步，而跳过停权或次数。对冲 SM-1。
- **SM-C2**: 不要为了让回填可以再填，而把已完成稿放回广场或退还次数。对冲 SM-2。

## 8. Open Questions

1. 中断下载时，已经扣掉的次数和占用要不要回滚？本文按不回滚写。若要回滚，FR-9 和 UJ-3 要改。
2. 再次回填是追加，还是覆盖最后一条？本文按追加写。若覆盖，FR-5、FR-6 的「每一条」要改成「当前这一条」。
3. 两个分成比例是否仍只表示剪辑手从应结算里拿走的比例，用户拿剩余？本文按 FR-014-27 写。若帐号运营要改成剪辑手、用户各一个比例，FR-7、FR-8 要改。
4. 存量剪辑手是否只继承任务协作分成？本文按这个迁移写。若两种都继承原比例，FR-7 的迁移假设要改。
5. 海外项目的任务协作，领取时还要不要选关键词，还是只领口令？本文按「口令归快捷题词，选词仍看运营模式」写。
6. 项目没有系列，或同时属于两个系列时，上传校验以哪一条为准？在有明确系列之前不能提交。

## 11. Integration

- **字节系书库**：上传时用书籍 ID 做命中校验。
