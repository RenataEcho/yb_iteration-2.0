# PRD: 一键代发迭代 3.0

本文件只覆盖一键代发这一刀增量。不并入 AI 工作台 PRD，也不改写 FR-014、FR-017、FR-018 的已有合同。

## 0. Document Purpose

给产品、UX、架构和后续 SPEC / Epic 使用。词汇以 §3 为准。本文 **FR-n** 只表示本增量第 n 条，不是全库全局编号。迭代需求页是 `demo/iteration/fr-yijian-daifa-iter3.html`，编号 **FR-020**。

底座合同是 `_bmad-output/specs/spec-fr014-yijian-daifa/`。本 PRD 不重写那份合同。用户侧仍是这条链路：用户点领取平台关键词稿件时按剪辑手收费方式扣费、下载并保存到相册，然后再由系统下发关键词；用户领走且订单已结算之后，按这条稿件剪辑手的分成比例切分：剪辑手拿走应结算乘以该比例，用户拿走剩下的。

2026-10-09 改本迭代页的两侧表面。管理后台不再验收官方帐号、剪辑任务、任务稿件。剪辑手 PC 不再验收剪辑任务和任务稿件。2026-10-10 在这个后台补上三处：剪辑手新增和编辑里，代运营合作模式改为多选，每个选中的模式单独填比例；增加稿件收费方式，跟随平台或定制，定制再填单次积分；再复刻一键代发 1.0 的稿件管理，并增加回填作品数量。

交付沿用增量：新开本迭代页，不回改历史迭代页。验收与溯源只认本迭代页。

## 1. Vision

一键代发现在的词是用户自己去申的。官方若要拿一批书、一批词，再交给剪辑手做稿、交给用户领，中间没有一条从官方帐号出发的链路。

用户侧把这条链路补上。一个关键词一条任务、一条稿件，帐号运营不会有稿件包。用户在作品广场用下拉筛选。代发运营模式的选项是全部、任务协作、帐号运营。帐号运营稿件不用自己提词、不用自己选词。稿件详情标题旁显示项目名称、运营模式、稿件类型。书籍信息显示书籍名称、书籍 ID、书籍链接、书籍类型，前三项可复制，不显示项目名称。分成显示供稿者分成和用户分成。帐号运营点领取稿件直接领取这一条，按剪辑手收费方式扣费，先下载稿件并保存到相册，再下发关键词。保存成功后提示回到已领列表回填。下载进度在保存完成前可以中断下载。任务协作领取时要选择关键词，选项里固定有「暂无关键词,先领稿件稍后申请词」。选了这项只能先领取，不能直接下载；领取时按剪辑手收费方式扣次数或积分，释放后次数和积分都不退。领取成功后弹窗提示尽快申请关键词；1 小时内没有填写关键词，该稿件过期释放，领取记录该字段改为「超时未填写关键词」。1 小时内字段显示「填写关键词」，点开底部浮层，选择这名用户这本书的关键词。选了具体关键词的，仍下载保存，关键词就是所选的那一个。

本迭代页的管理后台不登记官方帐号，不下发剪辑任务，也不看任务稿件。后台复刻 1.0 的剪辑手管理和稿件管理。剪辑手新增和编辑时，代运营合作模式是多选，每个选中的模式单独填比例。稿件收费方式是跟随平台或定制，定制再填单次积分。稿件管理在 1.0 字段外增加回填作品数量，点数字看到的列表与剪辑手 PC 相同。剪辑手 PC 不放剪辑任务，也不放任务稿件。上传 list 里已有的右豹稿件和站外稿件留着。

剪辑手领到任务的当下没有分成。用户领走稿件、这个关键词订单已结算之后，才按这条稿件剪辑手的分成比例切分。剪辑手分成是应结算乘以领取时的比例快照，用户分成是应结算减去剪辑手分成。不再按官方帐号上的两份比例切，也不再给官方留一份。

`[ASSUMPTION: 这是要上线的产品增量，严谨度对齐既有一键代发合同，不是内部备忘。]`

## 2. Target User

### 2.1 Jobs To Be Done

- **运营**：在本迭代管理后台维护剪辑手，并查看稿件。剪辑手页复刻 1.0，新增和编辑时用多选配置代运营合作模式。稿件页复刻 1.0，并看出每条稿件的回填作品数量。本轮不在这页登记官方帐号，也不下发剪辑任务。
- **剪辑手**：本轮剪辑手 PC 不提供剪辑任务，也不提供任务稿件。上传 list 仍有右豹稿件和站外稿件。分成仍要等用户领走且订单产出之后。
- **用户**：在作品广场筛出稿件。帐号运营领取时不用选词，点领取后按剪辑手收费方式扣费，下载并保存到相册，成功后拿到下发的关键词。任务协作领取时要选择关键词；选「暂无关键词,先领稿件稍后申请词」只能先领，不能直接下载。帐号运营没有稿件包。
- **官方帐号**：本轮不参与入账切分。稿件详情展示供稿者分成和用户分成。结算不按官方帐号的两份比例留一份。

### 2.2 Non-Users (v1)

- 要在剪辑手刚领到任务时就拿到分成的人。
- 要在本轮管理后台继续使用官方帐号、剪辑任务、任务稿件的人。
- 要在本轮剪辑手 PC 领取剪辑任务或查看任务稿件的人。
- 要改 FR-014 / FR-017 / FR-018 历史页的人。
- 要在本增量里做线上剪辑工具的人。线下剪辑留在产品外。

### 2.3 Key User Journeys

主人公沿用既有称呼，不单独立人设文档。林晓是领取用户，赵敏是运营。剪辑手用周凯。

- **UJ-1. 赵敏在本迭代后台维护剪辑手。**
  - **Persona + context:** 赵敏，运营。她要在这一轮的管理后台录入和查看剪辑手，并勾选这名剪辑手开通的合作模式。
  - **Entry state:** 已登录右豹后台，打开的是本迭代页的管理后台，不是 FR-014 历史后台文件。
  - **Path:** 打开剪辑手管理 → 新增或编辑 → 代运营合作模式里多选任务协作、帐号运营 → 每个勾上的模式填自己的比例 → 稿件收费方式选跟随平台或定制，定制再填单次积分 → 保存。
  - **Climax:** 合作模式是多选。没勾上的模式不出现比例。勾上之后，两个模式的比例分开填。
  - **Resolution:** 这页没有官方帐号、剪辑任务、任务稿件。她不在这里申词，也不在这里下发任务。列表和详情能看出已选模式和各自的比例，以及稿件收费方式。定制时能看出单次积分。
  - **Edge case:** 缺 1.0 必录项时不能保存。停用规则与 FR-014-20 相同。两个模式都没选时也不能保存。

- **UJ-6. 赵敏在稿件管理里看回填作品数量。**
  - **Persona + context:** 赵敏，运营。她要核对本迭代后台里一条稿件回填了多少作品。
  - **Entry state:** 已登录本迭代管理后台，打开稿件管理。
  - **Path:** 在右豹稿件或站外稿件里找到这一行 → 看到回填作品这一列的数量 → 点这个数字。
  - **Climax:** 打开的列表与剪辑手 PC 相同，能看到媒体平台、帐号 ID、帐号昵称、作品链接、发布时间和回填时间。
  - **Resolution:** 数量就是列表里的条数。没有回填时数字是 0，点开后列表为空。
  - **Edge case:** 这一列不写已删除。稿件被删时，稿件状态仍是已删除，回填作品数量单独保留。

- **UJ-2. 周凯打开剪辑手 PC，看不到剪辑任务和任务稿件。**
  - **Persona + context:** 周凯，剪辑手。他自己做片，不在产品里剪。
  - **Entry state:** 已登录剪辑手 PC，打开本迭代页。
  - **Path:** 进入剪辑供稿 → 上传 list 里看右豹稿件和站外稿件。
  - **Climax:** 页上没有剪辑任务，上传 list 里也没有任务稿件。
  - **Resolution:** 他不在这一轮的 PC 上领取书，也不按任务上传稿件。分成规则仍等用户领走且订单产出，不在这一页操作。
  - **Edge case:** 右豹稿件和站外稿件仍按去掉这两项之前已经在的列表展示，本轮不改它们的字段。

- **UJ-3. 林晓筛出帐号运营稿件，点领取后先保存稿件，再拿到词，再到已领列表回填。**
  - **Persona + context:** 林晓，26 岁，会发抖音，自己不做片。她要领官方已经备好词的稿。
  - **Entry state:** 已登录；打开本迭代作品广场。
  - **Path:** 代发运营模式下拉选「帐号运营」→ 进入稿件详情，看到供稿者分成和用户分成 → 领取时不选词 → 点领取稿件 → 按剪辑手收费方式扣费 → 下载稿件并保存到相册 → 然后拿到下发的关键词 → 看到回填提示 → 到已领列表点立即回填。
  - **Climax:** 她拿到的是系统下发的关键词，不是她当场填的词。关键词出现在下载保存之后。保存成功的同时，提示她回到已领列表回填。
  - **Resolution:** 人可以离开领取页。之后从已领列表点开这张卡片，仍能进入稿件详情，再次下载不再扣次。回填过后，同一张卡片的按钮变成追加回填，并显示回填作品数量。
  - **Edge case:** 她改筛「任务协作」时不走这条。任务协作要选关键词，先领后填见 UJ-7。选「全部」时，两类稿件都在。保存完成前点中断下载，进度关闭，不下发关键词，也不出现回填提示。第一次保存成功才出现回填提示，可以稍后留下或去回填。

- **UJ-7. 林晓领任务协作稿，先选「暂无关键词」，稍后再填词。**
  - **Persona + context:** 林晓。她要领一条任务协作稿，但这本书上还没有能直接用的关键词。
  - **Entry state:** 已登录，停在任务协作稿件详情，这一条还没领。
  - **Path:** 在选择关键词里点「暂无关键词,先领稿件稍后申请词」→ 点领取稿件 → 按剪辑手收费方式扣次数或积分，只完成领取，不下载 → 看到尽快申请关键词的弹窗 → 到领取记录，关键词处是「填写关键词」→ 点开底部浮层，选这本书上的一个关键词。
  - **Climax:** 没填词之前，点下载只提示去领取记录填写关键词，稿件不下到相册。次数或积分已经扣掉。
  - **Resolution:** 填上关键词之后，这条不再被 1 小时释放。再下载不再被这句提示拦住。
  - **Edge case:** 领取成功后满 1 小时仍没填写，稿件过期释放，她不再占用。领取记录该字段改为「超时未填写关键词」。已扣次数和积分都不退。选了具体关键词再领取的，不走这条，仍下载保存。帐号运营详情不出现这个选项。

- **UJ-4. 林晓点领取稿件，领走这一条。**
  - **Persona + context:** 同林晓。帐号运营稿件详情。一个任务一个关键词一条稿件，没有稿件包。
  - **Entry state:** 已登录，停在该稿件详情，这一条还没领。
  - **Path:** 若这条稿是定制收费，标题下方先看到积分价格 → 点领取稿件 → 有免费次数直接扣 1 次；没有免费次数、当前余额够扣且是定制收费时，先确认应扣积分和当前余额 → 下载稿件并保存到相册 → 领取成功后拿到关键词。
  - **Climax:** 只领这一条。有免费次数先扣 1 次；没有免费次数时，平台规则用积分兑换次数，定制在余额够扣并确认后才扣该剪辑手配置的积分。确认弹窗标题和确认按钮都是「确认兑换」，只写出应扣积分和当前余额。余额不够时不弹确认兑换，改为弹出积分不足，可以从那里去购买积分。不出现领取方式浮层，也不出现包内素材。
  - **Resolution:** 领完后底部与 1.0 相同：添加水印、下载并发布到抖音。帐号运营不能添加水印。
  - **Edge case:** 这一条已经领走之后不能再领。再次进入不另占词。

- **UJ-5. 订单结算后，周凯按自己的分成比例拿走一份，林晓拿走剩下的。**
  - **Persona + context:** 林晓已经领走周凯上传的那条稿，下发的关键词订单已经结算。
  - **Entry state:** 关键词订单已结算。用户还没领走稿件时，不进入这条。
  - **Path:** 领取成功时写下周凯当时的分成比例 → 订单已结算后，用这个快照切分这笔应结算。
  - **Climax:** 周凯拿到应结算乘以快照。林晓拿到应结算减去这一份。两份加起来等于应结算。同一个词只切一次。
  - **Resolution:** 用户还没领稿、订单还没结算时，两边分成都是 0。之后改周凯在剪辑手管理里的比例，不重算这笔。
  - **Edge case:** 只有订单、没有用户领取，不切。只有用户领取、订单还没结算，不切。

## 3. Glossary

下游必须用这些词。FR-014 已定义且本文件沿用的词，含义不变。

- **一键代发** — 剪辑手供稿、用户领取后发布变现。本增量在用户侧保留官方供词链路。本轮管理后台和剪辑手 PC 不操作这条供给。
- **剪辑手管理** — 本迭代管理后台的菜单之一。信息结构复刻一键代发 1.0，字段以 FR-014-20、FR-014-29 为准，并增加代运营合作模式。不是官方帐号，也不是剪辑任务。
- **代运营合作模式** — 剪辑手新增和编辑弹窗里的多选。选项是任务协作、帐号运营。勾选后才出现该模式的比例，0 到 100，两个模式分开填。未勾选的模式不显示、不保存比例。
- **稿件收费方式** — 剪辑手新增和编辑弹窗里的单选。选项是跟随平台、定制。跟随平台不填积分。定制时出现单次积分，写成单次 x 积分，须是大于 0 的整数。
- **稿件管理** — 本迭代管理后台的另一个菜单。信息结构复刻一键代发 1.0 稿件管理，字段以 FR-014-21 为准，并增加回填作品数量。不是任务稿件。
- **回填作品** — 一条稿件上已经回填的作品条数。管理后台稿件管理与剪辑手 PC 的展示相同：格内是数量，点数量打开列表。不是回填状态，格内也不写已删除。
- **官方帐号** — 本轮管理后台不登记、不列出。入账不读它上面的比例，也不给它留一份。
- **授权项目** — 官方帐号允许执行批量申词的项目范围，从项目表勾选。
- **批量申词** — 官方帐号对授权项目内的书籍提交关键词申请，一次可以多条。
- **剪辑任务** — 关键词申请通过并下发之后的任务。一个关键词一条任务，任务绑定该书与该词。本轮剪辑手 PC 和管理后台都不出现这个入口。领取规则留在 `.memlog.md`，不作为本页构建合同。
- **平台关键词** — 本链路里，官方帐号申请并通过、随剪辑任务落到稿件上的词。用户领取这类稿件时不自己选词。
- **自有关键词** — 用户自己的词，挂在任务协作稿件上。任务协作领取时要选择。其中一个固定选项是「暂无关键词,先领稿件稍后申请词」。
- **代发运营模式** — 作品广场的一个下拉。选项是全部、任务协作、帐号运营。全部同时列出两类稿件。帐号运营对应平台关键词稿件，领取不出现选择关键词。任务协作对应自有关键词稿件，领取要选择关键词。覆盖原「作品模式」和「运营模式」。
- **帐号运营** — 代发运营模式的一个选项。对应官方帐号平台关键词稿件。用户领取时不自己选词。曾称账号运营分成、帐号代发。本轮先领后填不作用于它。
- **任务协作** — 代发运营模式的一个选项。对应用户自有关键词稿件。领取时要选择关键词，选项里固定有「暂无关键词,先领稿件稍后申请词」。曾称任务协作分成、关键词领取。用户亦称代发任务模式，本文只用任务协作。
- **作品广场** — 用户浏览还没领取的稿件。已经领取的稿件不在这里，从已领列表进入。素材类型、代发运营模式、剪辑师、稿件类型都是底部浮层，点确定后才生效。广场是宫格。视频素材按一个项目、一本书、一名剪辑手显示成一个包，进入详情后再选单条稿件领取。
- **供稿者分成** — 稿件详情里和用户分成并排的一份比例。
- **稿件详情** — 单条稿件页。标题旁是项目名称、运营模式、稿件类型。定制收费稿件在标题正下方显示积分价格。书籍信息是书籍名称、书籍 ID、书籍链接、书籍类型。分成是供稿者分成和用户分成。
- **定制收费** — 剪辑手的一种收费方式。不走平台积分档位。领取 1 次扣该剪辑手配置的积分。
- **平台积分规则** — 剪辑手的另一种收费方式。优先扣 1 次免费次数；次数不够按平台档位用积分兑换次数。
- **积分价格** — 定制收费稿件在标题正下方显示的数。等于这一次的应扣积分。
- **应扣积分** — 扣积分确认里要扣的积分数。等于该稿件的积分价格。
- **当前余额** — 扣积分确认里这名用户现在的积分余额。不是金额。
- **免费次数** — 全平台共用的领取次数。有剩余时，定制收费和平台积分规则都先扣 1 次，不弹扣积分确认。
- **快捷提词** — 稿件详情底部与 1.0 相同的入口。还没领完时显示，点击跳到对应项目的题词页。帐号运营的领取过程不出现选择关键词。任务协作的领取要出现选择关键词，快捷提词不代替这个选择。
- **下发关键词** — 帐号运营：用户点领取稿件、扣过费、并且稿件已下载保存到相册之后，系统把该剪辑任务上的关键词交给这一名用户。一个平台关键词只下发一次占用。用户在这次领取里不填写、不挑选关键词。任务协作不走这条下发。
- **稿件** — 剪辑手按某条已领取的剪辑任务上传的内容。一个任务一个关键词一条稿件。帐号运营没有稿件包。
- **分成比例** — 剪辑手管理里，每个已选代运营合作模式各有一个百分比。领取成功时，按这条稿件所属模式写入那一份快照。已结算的切分只读这份快照。稿件详情不展示这一列，详情展示供稿者分成和用户分成。
- **剪辑手分成比例** — 曾挂在官方帐号上的百分比。本轮入账不读它。稿件详情里对应的展示字段是供稿者分成。
- **用户分成比例** — 曾挂在官方帐号上的百分比。本轮入账不读它。稿件详情里对应的展示字段是用户分成。
- **已领列表** — 用户端底栏「已领」里的列表，也就是领取记录。本增量改这张列表上的按钮和回填作品数量。任务协作里选了「暂无关键词,先领稿件稍后申请词」且还在 1 小时内、还没填词的行，关键词字段显示「填写关键词」。满 1 小时仍未填写，该字段改为「超时未填写关键词」。
- **领取记录** — 与已领列表是同一张列表。点击卡片进入对应稿件详情。先领后填的关键词不在卡片上填，点「填写关键词」打开底部浮层。点「超时未填写关键词」不打开浮层。
- **应结算** — 这笔关键词订单进入结算时的金额。剪辑手分成和用户分成都从这里切，切完不留官方一份。
- **剪辑手分成** — 应结算 × 领取时写入的剪辑手分成比例快照，四舍五入到分。记给这条稿件的剪辑手。一个词只切一次。触发点是这一名用户已领走并下载，且该关键词订单已结算。
- **用户分成** — 应结算 − 剪辑手分成。记给领走并下载该词稿件的那一名用户。触发点与剪辑手分成相同。一个词只切一次。
- **历史页面** — 本增量开始前已经存在的迭代页，包括 FR-014 一键代发、FR-017 收益池与限时领次、FR-018 一键代发迭代 2.0。
- **本迭代页** — 为本增量新开的迭代需求记录页（FR-020）及其前端交互、管理后台、业务流程。不回改历史页面。

**Consequences (testable):**
- 点领取稿件即开始领取，不先选领取方式。
- 领取按这条稿件的剪辑手收费方式扣费。免费次数全平台共用。剪辑手按平台积分规则收费时，优先扣 1 次免费次数；次数不够则按平台档位用积分兑换次数，兑换并扣掉这次次数之后才开始下载。积分仍不够这次兑换时，购买积分后回到兑换；仍然不够就不下载，也不打开定制扣积分确认。剪辑手按定制收费时，不走平台档位。有免费次数时本次仍扣 1 次免费次数，不弹扣积分确认。没有免费次数且当前余额够扣时，先弹出扣积分确认，用户确认后才扣该剪辑手配置的积分并开始领取。这个弹窗只属于定制收费且没有免费次数、余额够扣的这条路径。它只做二次确认：标题和确认按钮都是「确认兑换」，写出应扣积分和当前余额。应扣积分等于标题下的积分价格，等于该剪辑手为领取 1 次配置的积分。当前余额是这名用户的积分余额。弹窗不写定制收费，不写剪辑手是谁。取消则不扣积分、不领取、不写已领。当前余额低于应扣积分时，不弹出确认兑换，改为弹出积分不足。弹窗写出这次需要的积分、当前余额和还差多少，并给出去购买积分。点去购买积分打开购买积分。买够这次应扣之后回到确认兑换。买完仍不够，留在积分不足。取消购买回到积分不足。这两步都不扣积分、不下载、不写已领，也不打开平台档位兑换。
- 以下三种情况才开始下载：免费次数扣成功；平台档位兑换并扣掉这次次数成功；用户在定制扣积分确认里点了确认。接着显示正在下载稿件，再显示正在保存到相册，然后显示已保存到相册。保存完成后才下发关键词。已扣的次数或积分不退。
- 到达「已保存到相册」之前，下载进度上有「中断下载」。点它之后进度关闭，不弹出回填提示，也不下发关键词。
- 中断下载不退还已经扣掉的次数或积分。稿件进入已领列表。之后从已领列表再次下载不再扣次。某一次保存到相册成功后，才下发关键词。
- 这一次领取第一次保存到相册成功后，弹出「稿件已保存到相册」。说明是本次领取的第一次保存成功，可以现在去回填，也可以留在详情稍后从已领列表再回填。「稍后」留在详情。「去回填」进入现有回填。已经提示过的，再次保存成功不再弹。点了中断下载的这一次不弹。
- 稿件详情标题旁是项目名称、运营模式、稿件类型三个标签。定制收费稿件在稿件标题正下方显示积分价格。积分价格等于弹窗里的应扣积分，也就是该剪辑手为领取 1 次配置的积分。平台积分规则稿件不显示这条价格。这里不写「定制收费」。抬头把稿件作者、关键词、供稿者分成、用户分成放在同一行。上传时间用灰色小号字写在标签下方。书籍信息去掉项目名称，显示书籍名称、书籍 ID、书籍链接、书籍类型。书籍名称、书籍 ID、书籍链接可以复制。任务协作在领取成功前，关键词固定显示「未领取」；选了具体关键词并领取成功后，显示所选关键词。选了「暂无关键词,先领稿件稍后申请词」且还没填写时，领取记录的关键词字段显示「填写关键词」；稿件详情抬头在这一状态下显示哪几个字，见 §11。填写之后，详情和领取记录都显示所选关键词。帐号运营在领取成功前关键词脱敏，领取成功后显示完整关键词。不再单独放「已下发关键词」。领取步骤旁边有「剪辑师提醒」。切过去显示剪辑师上传这条稿件时写的提示语和推荐文案。
- 这一条领走之后不能再领。底部与 1.0 相同：添加水印、下载并发布到抖音。帐号运营点添加水印时提示不支持添加水印。下载并发布到抖音不再扣次。任务协作先领后填且还没填词时，点这个下载只提示「请先到领取记录页面填写关键词」，不保存、不发布。
- 帐号运营领取成功用的是该剪辑任务上的同一个平台关键词。不另占一个词，不另记一份用户分成。任务协作的词是用户选的，不走这句下发。

### 4.5 已领列表

**Description:** 帐号运营，以及任务协作里选了具体关键词的，第一次下载发生在点领取的过程里：先按剪辑手收费方式扣费，再保存到相册，然后才拿到关键词。任务协作先领后填不在点领取时下载，见 FR-8。已领列表用来再次进入已领取的稿件详情，也用来回填，也用来给先领后填填写关键词。实现 UJ-3、UJ-7。

**Functional Requirements:**

#### FR-11: 已领列表进入详情并下载

用户从已领列表点开已领取的卡片，进入稿件详情，可以再次下载，不再扣次。实现 UJ-3。

**Consequences (testable):**
- 未点领取时，稿件详情不提供单独的下载。帐号运营，以及任务协作里选了具体关键词的，下载从点领取这一下开始。
- 任务协作选了「暂无关键词,先领稿件稍后申请词」的，领取不开始下载。扣次数或积分仍按 FR-8。还在 1 小时内且未填写关键词时，详情和领取记录上的下载都只提示「请先到领取记录页面填写关键词」。填写之后再下载，不再出现这句。字段已是「超时未填写关键词」时，点下载不保存稿件。
- 已领列表中，点击一张已领取的卡片，进入这条领取对应的稿件详情。点「填写关键词」打开的是选词浮层，不是进详情。点「超时未填写关键词」不打开浮层。
- 从这张详情可以再次下载已领取的内容，不再扣次。关键词已经下发过的，不再下发一次。帐号运营里关键词还没下发的，要等这一次保存到相册成功后才下发，并按 FR-10 弹出回填提示。任务协作先领后填的下载，不被这句下发规则改成系统下发关键词。
- 已领列表仍是现有的领取记录，呈现在本迭代页上。
- 历史页面文件不因这条路径被修改。

#### FR-14: 已领列表的回填入口和回填作品数量

已领列表去掉「复制链接」。未回填时主按钮是「立即回填」。已经回填之后，主按钮改为「追加回填」，并显示回填作品数量。点这个数量不新建列表，弹窗说明开发规则：打开现有的该关键词作品列表即可。

**Consequences (testable):**
- 已领列表每一行都不再出现「复制链接」。下载按钮仍在。
- 任务协作里选了「暂无关键词,先领稿件稍后申请词」、且还在 1 小时内、关键词还没填写的行，关键词字段显示「填写关键词」。点它打开底部浮层，不进入稿件详情。下载按钮点下去只出现 FR-8 的那句提示。已经填上关键词的行，字段显示所选关键词，下载不再被这句拦住。满 1 小时仍未填写的行，字段改为「超时未填写关键词」，点它不打开浮层，点下载不保存稿件。已扣次数和积分都不退。
- 回填状态是未回填时，主按钮文案是「立即回填」。点它进入现有回填，不在本迭代另做回填页。
- 回填状态变成已回填之后，同一位置的主按钮文案改为「追加回填」。点它仍进入现有回填，用来再补一条。再补成功后，按钮仍是「追加回填」。
- 已回填的稿件显示回填作品数量。未回填不显示这个数量。
- 点回填作品数量，弹出开发规则：打开现有的该关键词作品列表即可。不在本迭代新建作品列表。
- 回填作品数量只计从代发入口回填的作品。从其它入口回填的作品不计入。
- 已超时的行不改成「追加回填」。本条不把已超时改成可以回填。
- 历史页面上的「复制链接」和「立即回填」不因本条被修改。

### 4.6 按剪辑手比例切分

**Description:** 用户领走稿件且关键词订单已结算之后，按这条稿件剪辑手的分成比例切分应结算。剪辑手拿走乘出来的一份，用户拿走剩下的。实现 UJ-5。

**Functional Requirements:**

#### FR-12: 订单结算后按剪辑手比例切分

系统用领取时写下的剪辑手分成比例，把这笔应结算切成剪辑手分成和用户分成。实现 UJ-5。

**Consequences (testable):**
- 比例来自这条稿件的剪辑手，取剪辑手管理里这条稿件所属模式的那一份分成比例。不读官方帐号上的剪辑手分成比例或用户分成比例。
- 用户还没领走稿件：剪辑手分成为 0，用户分成为 0。
- 用户已领走稿件、该关键词订单尚未结算：两份分成仍为 0。
- 这一名用户已领走并下载，且该关键词订单已结算：剪辑手分成 = 应结算 × 领取成功时的分成比例快照，四舍五入到分。用户分成 = 应结算 − 剪辑手分成。一个词只切这一次。
- 剪辑手分成记给这条稿件的剪辑手。用户分成记给领走并下载该词稿件的那一名用户。
- 同一关键词只由一名用户领走这一条稿件，不按稿件条数、不按领取次数再乘一份。
- 剪辑手分成 + 用户分成 = 这笔应结算。不再给官方留一份。
- 只有已结算的订单才切。待结算不切。
- 用户领取成功时，按这条稿件的剪辑手当时的分成比例写入快照。之后改剪辑手管理里的比例，不重算已经切出的分成。
- 不另建收益账本，不改 FR-002 代发收益页。已结算时，用户侧和剪辑手侧同时写入既有项目收益明细。
- 用户侧描述：「{项目名称}-{关键词}」(作品稿件「{稿件ID}」)于{时间}获得代发作品分账{用户分成}元。金额是用户分成。
- 剪辑手侧描述：「{项目名称}-{关键词}」(作品稿件「{稿件ID}」)于{时间}获得代发作品分账{剪辑手分成}元。金额是剪辑手分成。
- 时间精确到秒，状态为已结算。同一笔订单只写一次。待结算不写明细。广场、稿件详情、领取记录仍不展示金额。

**Out of Scope:**
- 按官方帐号上的两份比例切分，或给官方留一份。
- 领任务即打款。
- 用户未领取时，把订单收益分给剪辑手。

### 4.7 收益页

**Description:** 用户在底部查看自己的代发分成。顶部只展示已结算的代发总收入，下面是收益日历。点某一天查看这一天的项目关键词入账。实现 UJ-5 的用户侧可见结果。

**Functional Requirements:**

#### FR-13: 查看代发收益

用户打开收益，看到已结算的代发总收入和收益日历。点开有收益的日期，看到项目-关键词、代发收益入账金额、时间戳和入账金额。

**Consequences (testable):**
- 底部有收益。顶部统计只展示已结算的代发总收入，不展示未结算。没有进度条，也没有提现。
- 已结算是已经写入项目收益明细的用户分成。未结算不在这个页面展示。
- 统计下方是收益日历。还没到的日期不写金额。点开某一天进入详情。
- 详情卡片标题是「{项目}-{关键词}」，描述是「代发收益入账{金额}元」，并展示时间戳和入账金额。没有拆到项目关键词的日期，只展示这一天的入账金额。
- 广场、稿件详情、领取记录仍不展示金额。

## 6. MVP Scope

### 6.1 In Scope

- 后台：复刻一键代发 1.0 的剪辑手管理和稿件管理。去掉官方帐号、剪辑任务、任务稿件。剪辑手新增和编辑用多选配置代运营合作模式，已选模式各自填比例。稿件收费方式是跟随平台或定制，定制再填单次积分。稿件管理增加回填作品数量，点数字打开的列表与剪辑手 PC 相同。
- 剪辑手 PC：去掉剪辑任务和任务稿件。上传 list 保留右豹稿件、站外稿件。
- 用户：作品广场筛选都是下拉，代发运营模式为全部 / 任务协作 / 帐号运营。稿件详情显示供稿者分成和用户分成。定制收费稿件在标题正下方显示积分价格。只有定制收费、没有免费次数且余额够扣时，扣积分确认只显示应扣积分和当前余额。平台积分规则次数不够时仍走档位兑换，不走这个弹窗。帐号运营是一个任务一个关键词一条稿件，没有稿件包。帐号运营点领取稿件按剪辑手收费方式扣费，下载并保存到相册，然后下发关键词。保存完成前可以中断下载。保存成功后提示回到已领列表回填。任务协作领取要选择关键词；选「暂无关键词,先领稿件稍后申请词」只能先领，不能直接下载，领取时扣次数或积分，释放后次数和积分都不退。1 小时内领取记录显示「填写关键词」，超时改为「超时未填写关键词」。还没领完时底部含快捷提词。收益页展示已结算的代发总收入和收益日历。点日期查看项目-关键词的入账详情。
- 已领列表点击卡片进入稿件详情，可再次下载，不再扣次。先领后填且还在 1 小时内的行，点「填写关键词」打开选词浮层，点下载只提示去领取记录填写关键词。满 1 小时未填写，字段改为「超时未填写关键词」。列表去掉复制链接。未回填是立即回填，已回填改为追加回填，并显示回填作品数量。点数量弹出开发规则：打开现有的该关键词作品列表即可。
- 分成按稿件剪辑手的分成比例从应结算切出，触发点是用户已领走且订单已结算。剪辑手拿走乘出来的一份，用户拿走剩下的。已结算后写入双方项目收益明细，描述为「项目名称-关键词」(作品稿件「稿件ID」)于结算时间获得代发作品分账。

### 6.2 Out of Scope for MVP

- 改历史广场、历史领取记录、历史剪辑手 PC 的文件本身。
- 线上剪辑、指定剪辑手、领任务即分成。
- 把分成比例做成全站统一配置，或写死在本文里。比例在剪辑手管理里按人填写。

## 7. Success Metrics

试点先观察，不设奖金式目标。

**Primary**

- **SM-1**：平台关键词稿件的成功领取里，用户没有自选关键词、且领取结果里出现下发关键词的比例。目标是全部成功领取都满足。验证 FR-7。
- **SM-2**：剪辑手分成与用户分成的入账笔数里，发生在「用户已领走且关键词订单已结算」之前的笔数。目标是 0。验证 FR-12。本轮剪辑手 PC 没有领取动作，不在该页上观察这一条。

**Secondary**

- **SM-3**：帐号运营详情出现稿件包、包内素材或领取方式浮层的次数。目标是 0。验证 FR-9、FR-10。定制剪辑手按配置积分扣费，不算偏离。
- **SM-4**：剪辑手分成 + 用户分成不等于应结算的订单数。目标是 0。验证 FR-12。

**Counter-metrics（不要拿去冲指标）**

- **SM-C1**：把一条稿件拆成多条素材，做成稿件包再按条扣次。对冲「一个任务一条稿件、领取消耗 1 次」。
- **SM-C2**：在用户尚未领稿时，把待结算订单提前切给剪辑手。对冲 SM-2。

## 8. Ledger Boundaries

本增量不新开账本。切分读剪辑手管理里的分成比例，不读官方帐号上的两份比例。

| 账 | 何时写入 | 谁拿到 | 本增量 |
| --- | --- | --- | --- |
| 应结算 | 关键词订单进入结算 | 被切的那一笔 | 剪辑手分成和用户分成把它分完 |
| 剪辑手分成 | 这一名用户已领走并下载，且订单已结算之后 | 这条稿件的剪辑手 | 应结算 × 领取时的分成比例快照，四舍五入到分 |
| 用户分成 | 与剪辑手分成同一时点 | 领走并下载该词稿件的那一名用户 | 应结算 − 剪辑手分成 |
| 领任务 | 剪辑手领取剪辑任务成功 | 无金额 | 不入账 |

1. 剪辑手分成和用户分成都从这笔应结算里切。两者之和等于应结算。
2. 不按官方帐号留一份。
3. 还没被用户领稿、还没结算，都不产生分成。
4. 已结算才切，待结算不切。不改 FR-002。
5. 领取成功时写入这条稿件剪辑手当时的分成比例。之后改剪辑手管理里的比例，不重算已经切出的分成。

## 9. Constraints and Guardrails

- **溯源：** 规则和验收落在本迭代页。历史页面保持原样。
