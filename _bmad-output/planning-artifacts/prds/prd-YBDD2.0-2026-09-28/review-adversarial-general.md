- **Lens:** `bmad-review/references/lens-adversarial.md`

- **Focus pressure:** 2026-09-30 合同（一书一剪辑手 / 一词一任务一稿件 / 抽屉一次领已下发词 / PC 仅已领 / 后台全量含未领 / 下载用户一词一 ID / 按词在领走+订单后切分）
- **Verdict:** **FAIL** — 2026-09-30 书级领取与词级生命周期、后发词归属、双端状态机、占用时点与切分触发条件互相打架；按本文实现会把「后下发关键词」与「删行释锁」做成无主或双占死胡同。

## Findings（可读列表）

### F1. 书已领死后，后下发关键词无领取路径

- **location:** §11 Open Questions（2026-09-30）; FR-4 Consequences; FR-3; Vision §1
- **trigger_condition:** 合同规定抽屉领取「该书已下发的关键词任务全部归他」「还没下发的词不在这次领取里」；同时「领走之后其他人仍能看见这本书，但不能再领」。运营可继续对同一书「下发只作用于这一条关键词」（FR-2/FR-3）。领取后新增的已发布词既不自动归已领剪辑手，也无法被第二人按书领取。
- **guard_snippet:** 显式二选一并写成可测后果：(A) 后下发词自动并入该书已领剪辑手且进入其 PC 任务稿件；(B) 禁止对已领取书籍再下发，或允许按词/按书二次领取。禁止留空。
- **potential_consequence:** 后发词永久无主：PC 不显示、无人可领、后台「全部关键词任务」挂着未领行却无释放路径；运营批量申词越多，死任务越多。

### F2. Vision 把「领书=该书全部关键词任务」写成无条件句，与 FR-4「仅已下发」冲突

- **location:** §1 Vision; §2.1 剪辑手 JTBD; UJ-2 Path; FR-4
- **trigger_condition:** Vision / JTBD 写「领走后这些关键词任务都归他」「这本书下每个已下发关键词任务都归他」混用；§1 甚至省略「已下发」限定。下游若以 Vision 实现，会把未通过/未下发词也算进领取集合，违反 Glossary「未通过、未下发的词不是任务」与 FR-4 抽屉边界。
- **guard_snippet:** 全文统一为：「领取成功 = 领取时刻该书状态为已发布且尚未归属的关键词任务全集」；Vision/UJ/FR/§11 用同一句子，禁止无限定「这些关键词」。
- **potential_consequence:** SPEC/前端按 Vision 一次领光所有申词行（含待发布），或按 FR 漏领后发词——两边验收无法对齐，Bug 会被双方用不同段落辩护。

### F3. 「可领」不是任务状态机成员，书级可领条件无法验收

- **location:** FR-4 首句「状态为可领的一本书」; FR-2 任务状态枚举（待发布/已发布/已领取未上传稿件/已上传稿件/已完成）
- **trigger_condition:** FR-2 只给出词/行级状态；FR-4 引入书级「可领」却不定义推导规则（是否要求 ≥1 条已发布未归属？0 条已下发的书是否出卡片？已领取卡片是否仍显示领取入口？）。
- **guard_snippet:** 增加书级派生状态表：未领取 ∧ 存在≥1 条已发布未归属任务 ⇒ 可领；否则不可领。并规定卡片「已领取/未领取」与抽屉领取按钮的启用条件。
- **potential_consequence:** 任务池出现空关键词书卡、已领书仍可点领取、或已发布词因「书不可领」无法进入领取——2026-09-30 抽屉原子领取无从测起。

### F4. 词级状态机与 PC「未完成/已完成」双轨，书领成功后行状态跳变未定义

- **location:** FR-2 任务状态; FR-5「任务状态只有未完成和已完成」; FR-4 领取成功后果
- **trigger_condition:** 后台剪辑任务用五态；剪辑手 PC 任务稿件只用未完成/已完成。书级一次领取 N 条时，每条从「已发布」如何变成「已领取未上传稿件」、PC 如何映射为「未完成」，本文无原子后果。统计项「已领取未上传」与 PC「未完成」的等价关系未写死。
- **guard_snippet:** 写清领取事务：抽屉确认成功 ⇒ 该书本次纳入的每条任务状态 := 已领取未上传稿件；PC 视图映射：已回填⇒已完成，其余已领任务⇒未完成。给出状态对照表。
- **potential_consequence:** 后台统计、PC 列表、运营详情三处同一任务显示三种生命周期；「已领取未上传」指标与 PC 未完成对不上，SM 无法取数。

### F5. 删除任务稿件行是否释放「一书一剪辑手」与「一词一剪辑手」锁，全文沉默

- **location:** FR-5「操作可以删除这一行，删除后不再出现在任务稿件里」; FR-4「一名剪辑手只领取一本书」「一个平台关键词只被这一名剪辑手领走」
- **trigger_condition:** 允许剪辑手/后台删除任务稿件行，但不声明：书级名额是否释放、该词能否被他人再领、已上传稿件与用户侧占用如何回滚、后台「全部含未领」是否重新出现该行。
- **guard_snippet:** 为删除写后果矩阵：删行是否解除书锁/词锁；是否允许二次领取；若已有用户领取/下发关键词则禁止删除或级联作废规则。
- **potential_consequence:** 实现任选一边都会破坏 2026-09-30 合同——要么删行变相多领多本书，要么删行制造永久不可领孤儿词。

### F6. 并发双开抽屉领取同一本书，无唯一赢家与幂等规则

- **location:** FR-4; UJ-2 Edge case; §9 Constraints
- **trigger_condition:** 「所有人可见」「只有剪辑手可以领取」「领走之后其他人不能再领」只描述终态，不规定两人同时点抽屉领取时的冲突、重试、错误文案与任务归属原子性（一书多词需同一事务）。
- **guard_snippet:** 规定以服务端书级锁/版本号领取；成功者获得领取时刻全部已下发未归属任务；失败者整单失败且零任务写入；禁止部分词成功部分失败。
- **potential_consequence:** 一词两主或一书词集被拆给两人，直接击穿「一个平台关键词只被这一名剪辑手领走」与「抽屉一次领齐」。

### F7. 后台「任务稿件=全部关键词任务」与 Glossary「未下发不是任务」边界含糊

- **location:** Glossary「剪辑任务」; FR-5 管理后台任务稿件行范围; FR-2 剪辑任务列表（含待发布）
- **trigger_condition:** Glossary：未下发不是任务。FR-5：后台列出全部关键词任务（含未领取）。未说明「全部」是否包含待发布/审核未通过，或仅已下发（已发布及之后）。剪辑任务表与任务稿件表是否同一行集合未钉死。
- **guard_snippet:** 写死：任务稿件行 = 已下发（任务状态 ∈ {已发布, 已领取未上传稿件, 已上传稿件, 已完成}）的关键词任务全集；待发布/未通过不得出现在任务稿件。与剪辑任务列表的差集写明。
- **potential_consequence:** 后台「含未领」被实现成含未下发，验收时与 2026-09-30「PC 只显示已领 / 后台显示全部关键词任务」各执一词；未下发行出现上传/编辑入口。

### F8. 下载用户「一个用户 ID 一个平台关键词」是终身锁还是进行中锁，未定义释放

- **location:** FR-7; §11; Assumptions Index §12
- **trigger_condition:** 「已经领走并下载过一个词的用户，不能再领另一个平台关键词的稿件」无时间界、无项目界、无失败回滚。领取成功但下载失败、次数已扣、关键词已下发时，是否已占用唯一名额，未写。
- **guard_snippet:** 定义占用写入时点（领取成功 / 下载成功 / 下发关键词成功）与唯一失败补偿；定义是否终身、是否可运营解绑；与「再次进入不另占词」（UJ-4）对齐。
- **potential_consequence:** 一次失败领取或未完成下载即可永久封死该用户后续帐号代发；或相反——未占锁导致同一用户多词，击穿 §11 已确认合同。

### F9. 「领走」与「领走并下载」在占用、切分、UJ 之间三套口径

- **location:** FR-7; FR-12; UJ-5; Glossary「剪辑手分成/用户分成」; §8 Ledger; SM-2
- **trigger_condition:** FR-7 有时写「领走并下载」才排他，有时写「领取成功后下发关键词」。FR-12/UJ-5 切分要求「已领走并下载 + 订单」。SM-2/§8 又写「用户已领走且订单已结算」，常漏「下载」。占用、下发、切分三个事件的必要条件不一致。
- **guard_snippet:** 拆成三张时序表：关键词占用、稿件下载许可、收益切分；每张表列出必需前置状态；SM-2 与 FR-12 用同一谓词。
- **potential_consequence:** 只领不下载的用户占词却永不触发切分，或未下载就切分；剪辑手有稿无分成纠纷；指标 SM-2 与账本 §8 对不上。

### F10. 「一个词只切一次」与多笔已结算订单下的「该词官方关键词收益」金额基线未定义

- **location:** FR-12; §8; SM-4; UJ-5「同一个词只切一次」
- **trigger_condition:** 合同坚持按词切一次，但「官方关键词收益」若随多笔订单累加，未说明切分基数是首笔结算额、累计额，还是切分触发那一刻的快照额；若词生命周期内多笔已结算订单，禁止二次切分后增量收益归属谁。
- **guard_snippet:** 定义切分触发订单选择规则（首次已结算且满足领取下载条件的那笔）及金额字段；写明后续订单收益 100% 留官方或另行规则；SM-4 按同一公式验收。
- **potential_consequence:** 同词多订单时官方/剪辑手/用户账对不齐；SM-4「四者对不上」必然报警或被实现用静默吞增量绕过。

### F11. 继承 1.0「部分领取」占用态，与「一词一稿一件、无稿件包」自相矛盾

- **location:** FR-5「占用是空闲、占用中、部分领取」; FR-9; §9「一条稿件」; §11 2026-09-29 确认
- **trigger_condition:** 明确无稿件包、一任务一稿、一名用户领走一条，却原样搬入「部分领取」。该态在本增量无合法迁移路径。
- **guard_snippet:** 帐号代发稿件占用态收敛为 {空闲, 占用中}（或等价二元）；删除「部分领取」或声明本链路永不进入并加测试断言。
- **potential_consequence:** 前端/后台筛选项与统计出现不可达态；实现为凑 1.0 兼容再次引入包内分次领取，直接打脸 FR-9/SM-3/SM-C1。

### F12. 快捷提词与「领取过程不选词 / 不新建题词页」并置，未界定提词是否可制造第二套词占用

- **location:** FR-7; FR-10; Non-Goals §5; Glossary「快捷提词」
- **trigger_condition:** 一边禁止领取流程选词/新建题词页，一边保留未领完时「快捷提词→项目题词页」。未说明题词页产出是否可变成该用户的平台关键词占用、是否绕过「一个用户 ID 一个平台关键词」、是否改变稿件上已绑定词。
- **guard_snippet:** 写死：快捷提词不得改写本条帐号代发稿件的平台关键词，不得额外占用「一个用户 ID 一个平台关键词」名额；或未领完态对帐号代发隐藏快捷提词。
- **potential_consequence:** 用户经题词页另占词后回来领取，造成双词占用或领取时词被替换，破坏平台关键词下发合同与唯一 ID 约束。

### F13. 剪辑手分成接收人依赖「领取该词任务的剪辑手」，但后发无主词与删行后无接收人

- **location:** FR-12; Glossary「剪辑手分成」; FR-4; FR-5
- **trigger_condition:** 切分记给「领取该词对应任务的那一名剪辑手」。在 F1/F5 场景下任务可能无领取人或领取人已删行消失；FR-12 未定义无领取人时订单收益是否切剪辑手、切 0、还是阻塞结算。
- **guard_snippet:** 规定：无有效领取剪辑手则剪辑手分成 = 0 且不得阻塞官方入账与用户分成；或禁止无主任务上架到作品广场。
- **potential_consequence:** 结算任务空指针/挂起；或把分成写给错误账号；官方与用户账已动、剪辑手侧缺失，对账失败。

### F14. 「同一本书多个关键词算一次领取」与任务池「关键词数量」在领取后变化时无刷新语义

- **location:** FR-4 卡片字段「关键词数量」; UJ-2; §11
- **trigger_condition:** 关键词数量 = 已下发可供领取数。书被领后若数量因后下发增加，卡片仍标「已领取」时该数字是领取快照、当前已下发总数，还是「已归属/未归属」混合，未定义；PC 任务稿件是否应出现新增行亦未定义（回指 F1）。
- **guard_snippet:** 规定已领书卡的关键词数量展示规则（快照 vs 实时）及未归属增量的角标/运营警示；与 F1 归属策略绑定。
- **potential_consequence:** 剪辑手以为数量即自己的任务数，实际 PC 更少；运营以为已领书消化了全部词，后台未领行仍在堆积。
