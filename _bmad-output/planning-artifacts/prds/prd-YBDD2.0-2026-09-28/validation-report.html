决策就绪

adequate

取舍写得直白：Non-Users 点名不要「领任务即分成」「指定任务」「改历史页」「线上剪辑」；§9 用禁止句钉死钱与词的时点；§11 关闭了比例填写与稿件包领法两项。对内部门户增量而言，决策者能判断「做 / 不做这条链路」和「钱何时切」。弱在：若干实现必答项（任务领取池规则、结算快照、一用户 ID 一条官方帐号、一通过词一条任务）仍落在假设上，却没有对应的 [NOTE FOR PM] 张力标注；§11「无阶段阻塞项」语气偏满，异议方会觉得异议被收进假设而不是摆上台面。

high

Open Questions 与假设负载不一致

§11 / §12 / FR-4 / FR-12
§11 写「无阶段阻塞项……其余推断留在 §12，不挡住体验稿」，但 FR-4 领取资格与互斥、FR-12「已结算才切」与比例快照都是成单规则，不是体验稿可绕开的装饰。
Fix: 把钱与任务领取的关键假设升为已拍板决策，或在 §11 显式列为「实现前必须确认」；在真实张力处加 [NOTE FOR PM]。
medium

取舍有结果、少写「放弃了什么」

§1 / §2.2
Non-Users 列举了被排除的人，但未写成「相对指定派单 / 领任务预付，本刀选择自领池 + 延后切分，代价是……」。
Fix: 用一两句补上选定方案的代价（例如自领导致冷门书任务无人领、延后切分影响剪辑手积极性）。

实质

strong

Vision 钉的是具体缺口（「官方若要拿一批书、一批词……中间没有一条从官方帐号出发的链路」），换成别的代发产品就站不住。JTBD 与 UJ 直接驱动 FR 分组；Constraints / Ledger 是产品特有时点，不是套话。SM 带反指标（SM-C1 / SM-C2）。三人称谓嵌在旅程里，没有多余人设章节。

low

「官方帐号」列在 Target User

§2.1
正文把它写成挂账主体（「关键词收益记在这个帐号上」），不是可作业的人。
Fix: 挪到 Glossary / Ledger，Jobs 只保留运营 / 剪辑手 / 用户。

战略连贯

strong

全篇押在一条增量论题上：官方供词链路补齐，且收益「先归官方、领走+订单后再切」。FR-1…FR-12 按运营 → 剪辑 → 领取 → 包 → 下载 → 切分排成一条弧。MVP（§6）与 Non-Goals（§5）同向。Primary SM 验证「不下发自选词」「不提前切分」，对准论题。

完成度

thin

多数 FR 带可测 Consequences。一旦进入「一关键词 / 一任务 → 多稿件 → 多用户领取 / 分次多次下发 → 一笔订单」，FR-12 的对象与守恒式不够用；关键词是否可被多次下发给多人，也与既有一键代发词唯一性未对齐。若干关键行为仅以假设句出现，验收口径仍飘。

critical

一订单多领取时切分对象与守恒冲突

FR-12 / UJ-5 / §8
FR-12 要求「剪辑手分成 + 用户分成 + 留在官方帐号的剩余 = 这笔官方关键词收益」，同时又写「用户分成记给领走该稿件的用户」「剪辑手分成记给上传并被领走的那条稿件的剪辑手」。同一剪辑任务可多稿件（FR-5），分次可多次下发同一平台关键词（FR-10）。多人领走或多稿被领后，若各按「官方关键词收益 × 比例」各记一笔，守恒式必然破；若只切一次，则「记给谁」未定义。
Fix: 明确切分粒度（按订单一次 / 按领取事件 / 按稿件），并写清多领取并存时的入账人与是否拆分基数。
high

「下发关键词」与词可复用次数未闭合

FR-7 / FR-10 / §3
FR-7「用户得到的关键词等于该稿件所属剪辑任务上的那个平台关键词」；FR-10「每一次成功领取各下发 1 次关键词……仍是……同一个平台关键词」。未说明同一词可否同时挂在多名用户名下、分次多次下发是幂等授予还是多次占用，以及与 FR-014 既有词占用规则如何衔接。
Fix: 写明下发的库存语义（共享只读 / 每次占用 / 幂等），并引用底座合同中不可破坏的约束。
high

领取池关键规则仅以假设充当验收

FR-4
「可领的剪辑手 = …」「一条剪辑任务同时只能被一名剪辑手领取」整段标 [ASSUMPTION]，却是 UJ-2 / SM 可测行为的前提。
Fix: 确认为合同条款并去掉假设标签，或列入 §11 阻塞项。
medium

稿件包部分领取后的下载边界

FR-11 / FR-10
FR-11「从这张详情可以下载已领取的内容」未定义分次场景下详情展示未领素材还是仅已领素材、下载按钮范围。
Fix: 为分次领取补一条可测后果（仅已领素材可下；未领素材不可下）。
medium

批量申词的提交单元过粗

FR-2
「一次提交可以包含多条书籍关键词申请」未给出每条申请必含字段、书籍如何被选入、与现有审核流的衔接（谁点「通过」）。
Fix: 补最小字段集与「沿用现有关键词审核态机」的显式引用。
