## Findings by severity

### Critical (1)

**[完成度]** — 一订单多领取时切分对象与守恒冲突（FR-12 / UJ-5 / §8）
FR-12 要求「剪辑手分成 + 用户分成 + 留在官方帐号的剩余 = 这笔官方关键词收益」，同时又写「用户分成记给领走该稿件的用户」「剪辑手分成记给上传并被领走的那条稿件的剪辑手」。同一剪辑任务可多稿件（FR-5），分次可多次下发同一平台关键词（FR-10）。多人领走或多稿被领后，若各按「官方关键词收益 × 比例」各记一笔，守恒式必然破；若只切一次，则「记给谁」未定义。
Fix: 明确切分粒度（按订单一次 / 按领取事件 / 按稿件），并写清多领取并存时的入账人与是否拆分基数。

### High (3)

**[完成度]** — 「下发关键词」与词可复用次数未闭合（FR-7 / FR-10 / §3）
未说明同一词可否同时挂在多名用户名下、分次多次下发是幂等授予还是多次占用，以及与 FR-014 既有词占用规则如何衔接。
Fix: 写明下发的库存语义（共享只读 / 每次占用 / 幂等），并引用底座合同中不可破坏的约束。

**[完成度]** — 领取池关键规则仅以假设充当验收（FR-4）
「可领的剪辑手」与「一条剪辑任务同时只能被一名剪辑手领取」整段标 `[ASSUMPTION]`，却是 UJ-2 / SM 可测行为的前提。
Fix: 确认为合同条款并去掉假设标签，或列入 §11 阻塞项。

**[决策就绪]** — Open Questions 与假设负载不一致（§11 / §12 / FR-4 / FR-12）
§11 写「无阶段阻塞项」，但领取资格、已结算才切、比例快照都是成单规则。
Fix: 把钱与任务领取的关键假设升为已拍板决策，或在 §11 显式列为「实现前必须确认」。

### Medium (6)

**[完成度]** — 稿件包部分领取后的下载边界（FR-11 / FR-10）
分次场景下详情展示范围和下载按钮范围未定义。
Fix: 仅已领素材可下；未领素材不可下。

**[完成度]** — 批量申词的提交单元过粗（FR-2）
一次多条申请的字段、选书方式、谁点通过未写清。
Fix: 补最小字段集，并写明沿用现有关键词审核态机。

**[范围诚实]** — 裸 `[ASSUMPTION]` 无陈述（§2.3 UJ-3 / §5）
句末只有标签，正文还原不出假设内容。
Fix: 写成完整 `[ASSUMPTION: …]`，与 §12 逐字对应。

**[范围诚实]** — 「不挡住体验稿」掩盖实现阻塞（§11）
工程读者会把「无阶段阻塞项」读成合同已齐。
