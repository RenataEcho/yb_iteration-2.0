## Gaps（信号有、FR 结构丢掉 / 收窄 / 倒置的点）

1. **「接单」定性被换成「领取」书/任务链，list 的过滤主语从“接了单的任务”收成“领了书之后归他的关键词行”。** 信号说的是接单任务才进 list；FR-5 以书级领取结果灌进任务稿件，没有单独的「接单」动作落在任务稿件上。
2. **「没接任务的不显示」的定性边界在 FR 里被拆成 PC vs 后台两套行范围。** 信号只点名剪辑手 PC；FR-5 另写「后台列出全部关键词任务，包含还没有剪辑手领取的」——这是 PRD 对范围的补全，不是信号句子本身。若把「后台也应隐藏未接」当成漏写用户句，记为 **inference（非用户原句）**。
3. **接单后仍可能从 list 消失（删除行）。** 信号定性是「接了的才显示」；FR-5 「操作可以删除这一行，删除后不再出现在任务稿件里」把已接行从 list 拿掉，收窄了“已接单 = 一直在 list 里可见”。
4. **信号未要求上传闸门 / 统计 / Tab 保留，但 FR 把 list 规则绑进上传与查询恢复。** 「没出现在他任务稿件里的任务不能上传」等是后果扩展；信号里的定性意图只是 list 数据可见性，未被单独保留为一条纯展示合同。
5. **若「接任务」按词理解，与书级一次归入存在定性落差。** 信号可读成按任务接单过滤；FR-4/5 是领书后已下发词整批进 list，「还没下发的词不在这次领取里」——把“未接单不显示”实现成“未随该书领取归入则不显示”。把“必须逐词接单才显示”当成用户原句 = **inference**。
