# Addendum（不进 PRD 正文）

## 已否决的口径

| 选项 | 否决原因 |
|------|----------|
| Case 1 按人排，全站只出 3 个用户 | 运营更正为「每个项目的前三名」；「项目名称」列在按人合计时语义不清。 |
| Case 2 无关系时铺整条祖先链 | 运营明确真正上级只有一个用户（默认上级），不需要爷爷/团长整链。 |
| Case 2 假设全站单根树、任意两人必有直属/间属 | 「有默认上级」推不出「任意两人有关系」。已锁定：分叉时回退各自默认上级。 |
| v1 同时做 AI 代操作 | 与只读查询的权限、验收、风险不是同一产品；先验证「一句话换一张对的表」。 |

## 机制与选型（留给架构）

- 意图识别：规则/槽位 vs 小模型分类 vs 受约束 function-calling — PRD 只要求两类意图，不锁实现。
- 排名与关系必须走确定性查询或既有领域服务，禁止 LLM 自算 Top N 或自造链路。
- 审计存提问+意图即可，是否存结果快照由存储与隐私成本决定。

## 竞品形态（Discovery 摘要）

- Adobe Experience Cloud AI Assistant：既有右栏聊天，也有全屏沉浸；复杂消费面用全屏。本工作台 v1 选独立全屏双栏，因运营要盯表。
- C3 GenAI side panel：看复杂网格时用 fully-expanded。对应本 PRD「结果区必须够宽读三列」。
- Tellius / Sigma 等 conversational analytics：数字必须绑回受治数据，不能让模型口算。写入 PRD §9.1 正确性。

## 未纳入的运营上下文

- 问询频率未知，不据此做容量设计；先做金标准正确性。
- 现有迭代 UX（礼品中心、活动中心等）与本工作台无界面继承关系。
