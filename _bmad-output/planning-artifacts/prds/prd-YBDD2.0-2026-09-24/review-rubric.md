# PRD Quality Review — 一键代发增量 — 收益池露出与限时领次

## Overall verdict
作为试点增量（非全量上线），这份 PRD 站得住：论点清楚（进广场前要让人看见「代发在赚钱」，再用限时领次把人拉回），弃选和账本边界写得硬，功能几乎都能测。风险在两处会改合同的未决口径（合成话术 vs 造假反指标、试点是否全员），以及 FR-8 把「人数名额」和「次数库存」绑在同一个扣减短语上——默认每次发 1 次时碰巧能过，配置一旦不是 1，下游会写出超发或错扣的故事。

## Decision-readiness — strong
决策是按决策写的，不是「综合考虑」。§1 把这一刀钉死为两件事（「代发收益池」「限时领次」）并点名都挂在作品广场、不单开首页、不改历史广场文件、不把金额写进卡片；§5 / §6.2 / addendum「弃选」把单开首页、卡片露金额、把抢次并进免费桶、复用活动中心、更新 AI 工作台 PRD 写成放弃，而不是中性「后续可考虑」。§8 六条关系（池子不是入账汇总、虚拟配置永不进明细、活动次数不是免费也不是商品）让反对「再记一笔账 / 和积分兑次混用」的人能对上号。`[NOTE FOR PM]` 只出现在 §6.2 真张力处：「当天不用作废」与黏性目标冲突。Open Questions 多数带「当前按…写」，不是下一句已答完的修辞题；addendum 把合成方式的 A–D 弃留摊开，比正文更利于拍板。

尚不能一次会开完的，是会改 FR 字面的两题：§12 Q9 与 FR-4 / SM-C4 对撞，以及 §12 Q7 白名单没有任何假设（见下）。按试点 stakes，这不把维度打成 thin，但决策者还不能把合同冻死。

### Findings
- **medium** 不披露合成方式与「造假」反指标互相锁死（§12 Q9 / FR-4 / SM-C4） — FR-4 写「试点不对用户披露合成方式」，Q9 又问要不要 C 端「含预估」话术，SM-C4 要压「因虚拟配置被指『造假』的公开投诉」。三处不能同时成立。 *Fix:* 试点二选一写进合同：维持不披露并接受 SM-C2 咨询量，或允许一句非承诺话术并改掉 FR-4 假设；不要既假设不披露又把话术留作开放题。

## Substance over theater — strong
家具很少。§2.1 JTBD 和两条具名人设（林晓领稿 / 赵敏配池）直接驱动 UJ-1…4 和 FR-1…10，没有第四个人设充篇幅。§1 Vision 换成别的「增长活动 PRD」会立刻穿帮（「卡片、详情、领取列表按合同不展示金额」「池子和活动都挂广场、不单开首页」）。NFR 不是「要可扩展 / 要安全」：§11 给了超发 = 0、实际累计最长 15 分钟陈旧、配置「下一次打开」必须生效、禁止客户端自报领取成功。addendum「可比做法」承认 Discovery 未跑完检索，且点明「种子数 + 真实累加」并不新——没有创新剧场。§7 指标「只作观察，不设奖」避免了假精度。

## Strategic coherence — strong
有论点，不是能力清单。§1 / §6 的试点检验句是「说得清、抢得成、账不算乱」：FR-1…5 服务「说得清」，FR-6…10 服务「抢得成且账不乱」，FR-11…12 服务「旧页不动」。SM-1（池子曝光后进广场占比）验露出，SM-2（领满率 / 耗时）验抢次，SM-3（24h 内真领稿）挡住「只抢不领」，SM-4（历史页 diff = 0）验溯源；反指标 SM-C1…C4 对准猛发次数、把展示收益当余额、超发、虚拟拉满冲曝光。MVP 形态是问题求解 + 营销体验，范围逻辑与论点一致，不是「好做的先做」。

## Done-ness clarity — adequate
多数 FR 带可测后果，形容词很少。FR-2 计入 / 排除集合清楚（已回填、已结算、不回溯、站外稿不计）；FR-3 三数 + 审计；FR-4 公式与「不得小于实际累计」；FR-6 三桶公式与跨日不重置；FR-9 五个状态具名；FR-11 点名历史文件零 diff。§11 给了界限而不是「合理性能」。工程师在默认路径（每次发放 = 1、全员、相加）上知道 done 长什么样。

一旦 FR-7 允许「每次发放的活动次数」> 1，FR-8 的成功后果就不够写故事。§4.2 没有「剩余发放量 < 单次发放量」的失败态，而 SM-C3 要求超发事故必须为 0——这是本维度未到 strong 的原因。

### Findings
- **high** 可领名额与每日发放量被写成同口径扣减（§4.2 FR-8） — 成功后果写「可领名额与每日发放量按实际发出量扣减」。可领名额是「最多多少名用户」（§3），每日发放量是次数总量。每次发放默认 1 时两者碰巧同减 1；配置为 3 时，按字面会人数名额和次数库存一起减 3，或一起减 1。 *Fix:* 写明成功时：该用户当日已领；活动剩余 +每次发放的活动次数；可领名额 −1；每日发放量 −本次实际发出次数。两条上限仍独立：成功人数 ≤ 可领名额，发出次数总和 ≤ 每日发放量。
- **medium** 库存不够发一整份时未定义（§4.2 FR-8） — 领取条件是「仍有可领名额且仍有每日发放量」，没有「剩余每日发放量 ≥ 每次发放的活动次数」。剩余 1、每次发 3 时，不知道拒领、发 1，还是超发。 *Fix:* 前置条件改为剩余每日发放量 ≥ 本次发放量，否则走已有失败清单（不扣任何桶、不记已领）。

## Scope honesty — strong
省略是写明的，不是靠读者推断。§5 Non-Goals 做了真功（不改广场金额禁令、不改免费/商品规则、不并 FR-001/002、不扣积分、Demo 不真支付）。§4.1 与 §6.2 把按人拆池、多档并行、对用户披露虚拟、待结算入池、活动次数跨日作废标成非目标；§6.2 对作废还留了 `[NOTE FOR PM]`。13 条 `[ASSUMPTION]` 都在 §13 有回指，密度相对试点 stakes 可接受。唯一会让实施静默默认的，是全员范围。

### Findings
- **medium** 试点是否全员没有假设，正文却按全员写（§12 Q7 / FR-1 / FR-8） — FR-1 标题是「全员可见」，后果是「任意两个已登录用户同一时刻看到的展示收益相同」；FR-8 对「已登录用户」给领取成功条件。Q7 问「还是后台另做白名单」且未打 `[ASSUMPTION]`。实施会按全员做；若拍板改白名单，FR-1、SM-1 分母、§2.2 Non-Users 都要改。 *Fix:* 要么假设「试点全员、不做白名单」并收入 §13，要么把白名单收进 FR-7 配置并从 Non-Users 划出未入白名单的人。

## Downstream usability — adequate
本文件明确喂给 UX / 架构 / SPEC / Epic（§0），可抽取性整体够用：§3 词汇在 FR / UJ / SM / §8 账表里同一套（代发收益池 ≠ 用户收益入账，活动次数 ≠ 免费次数，展示收益 ≠ 实际累计）；UJ-1/2/4 有具名主人公；FR-1…12、UJ-1…4、SM-1…4 / SM-C1…C4 连续无重号；底座路径 `_bmad-output/specs/spec-fr014-yijian-daifa/` 与历史页文件名对得上现存仓库。单节抽出时主要靠 Glossary，不是「见上文」。

会绊住开 story 的是编号合同：§0 自称「FR 全局编号」，正文却从 FR-1 重起，§10 又假设迭代页叫 FR-017。UJ-3 标题有林晓，块里没有 Persona。

### Findings
- **medium** 三套「FR」编号叠在同一份合同（§0 / §4 / §10） — §0：「功能按组展开，FR 全局编号。」§4 使用 FR-1…FR-12。§10：「新开 FR-017（014 一键代发、015 逐鹿、016 钱包已占用）。」下游无法判断「FR-1」是本增量第一条、历史其他 FR-1，还是 FR-017-01；迭代页文件名也会飘。 *Fix:* 正文改称 FR-017-01…12，或在 §0 写死「本文 FR-n 仅指本增量第 n 条，迭代页编号为 FR-017」；不要再说「全局编号」。
- **low** UJ-3 缺主人公块（§2.3 UJ-3） — 标题为「林晓来晚了，或活动未开」，Entry state 直接开始，无 Persona + context。单独抽 UJ 时会变成漂浮场景。 *Fix:* 补与 UJ-2 相同的 Persona + context，并写入口仍是本迭代限时领次页。

## Shape fit — strong
形态匹配产品：C 端营销增量 + 运营配置，多干系人，UJ 有负载（林晓三条路径覆盖看见 / 抢到 / 失败可解释，赵敏一条覆盖只改新页）。棕地区分清楚——新 UJ 全在「本迭代页」，既有广场 / 详情 / 领取 / 次数商品 / 活动中心被写成不改；点名的 `fr-opc-yijian-daifa.html`、`fr-activity-center.html`、`fr-opc-daifa-allocation.html`、`fr-opc-daifa-revenue.html` 与 FR-014 合同在仓库里存在。链顶（还要喂 UX → 架构 → 故事）所以要 UJ / Glossary / 账表，但没有为单操作者工具堆出过量旅程。试点增量没有写成全量上市 PRD，也没有写成纯内部能力清单。
