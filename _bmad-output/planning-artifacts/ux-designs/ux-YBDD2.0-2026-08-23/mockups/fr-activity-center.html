筛选与入口

  • Tab：全部 / 进行中 / 已结束 / 已参与。在右侧 Demo 内点切换。没有「待开始」筛选，待开始只出现在「全部」。
  • 只过滤下方卡片；置顶 Banner 不随任一筛选（含已参与）隐藏。
  • 整张列表卡片可点，与「查看」相同：一律进详情，不外跳，不记已参与。Banner 整块同样进详情。
  • 隐藏活动不进 Banner / 四个 Tab / 详情。深链打开隐藏活动时停在列表。
  • 已参与 = 显示池 ∩ 该用户已领取；活动被隐藏后从已参与消失。
  • 已参与空态：「暂无已参与的活动」；其他筛选空：「暂无符合条件的活动」。
  • 列表卡片不打已获奖/未获奖角标。

排序规则

  • 显示池内最多 1 条置顶：第 1 步「是否置顶」pinned。置顶只出 Banner，不在下方列表重复（已参与 Tab 仍可出现该活动卡片）。
  • 下方卡片顺序沿用既有列表序：与后台活动列表「排序」列一致，数值越大越靠前；同分再按稳定 id。
  • 本 FR 不新增可编辑排序字段；后台「排序」列仅展示。
  • 筛选 Tab 只过滤，不改相对顺序。

2.1 三 Tab 显示规则

  • 顺序固定：介绍 → 案例 → 榜单；缺则跳过。默认落在从左起第一个实际存在的 Tab。
  • 介绍：已下发介绍正文才出现。
  • 案例：至少 1 条完整案例（名称 + 图片或视频组成）才出现。
  • 榜单：后台「榜单」=开启才出现。空名单仍出该 Tab 内容（仅榜单一个时无 Tab 栏），空态「暂无榜单数据」；底栏 self 仍可在。
  • 未配置的 Tab 整段不渲染。实际存在不足 2 个：不展示 Tab 栏，正文仍在独立内容卡片。
  • 禁止「我的作品」。本 Demo 为三 Tab 齐全态，点 Tab 可切换。

2.2 按钮点击规则

  • 领取只在「介绍」Tab 底栏展示。案例、榜单不显示。无介绍 Tab：即使开了领取开关也无底栏。
  • 开关关或 0 个已配按钮：无底栏。最多 2 个；半填不下发。
  • 待开始 / 已结束：已配按钮可展示但不可点，不记已参与。
  • 进行中、不需跳转：点击后文案变为配置值，并记已参与；再点保持变更文案，不新增已参与行。
  • 进行中、需跳转：客户端成功调起即记（不要求落地页 200）；失败不记。Demo 地址含 fail 视为失败。
  • 去重键（用户, 活动）。两个按钮点任一都是同一条。列表/Banner「查看」不记。

2.3 奖品显示规则与样式

  • 仅第 2 步打开「显示用户获奖/未获奖信息」且已下发 awardStatus 才展示。不绑榜单开关、不绑活动是否结束。无审核中。详情内容页不配置该样式。
  • 开关开但未算出/未下发 awardStatus：不展示展位。
  • 位置：信息卡片与 Tab 区之间，独立卡片（圆角、留白、轻阴影），与上下白卡片分开。
  • awardStatus=won：浅橙底 + 橙边 + 深橙字，文案「恭喜获奖」，可带 awardPrize。
  • not_won：结构与已获奖相同，灰底 + 灰边 + 深灰字，文案「未获奖，再接再厉」。
  • 列表卡片不打获奖角标。

2.4 其他规则

  • 页头固定「活动详情」，不放活动标题。信息卡片与 Tab/正文卡片各自白底圆角。
  • 已下发封面才展示封面；浏览人数始终「x人浏览」；参加人数未下发则不展示。
  • 隐藏活动不进显示池。深链打开隐藏 activityId 停在列表，不当详情。
  • 案例图片点击放大、长按保存（Demo toast）。案例视频用 Mock 地址可播。案例卡片两列平铺。
  • 登录能力已存在，本 FR 不单开未登录分支。

2.6 闭合边界（交付）

  • 隐藏活动：深链不当详情、已参与 Tab 也不再出现。
  • 无「待开始」筛选；待开始只在「全部」。浏览人数取后台初始值，C 端不 +1。
  • 无介绍 Tab 则无领取底栏。跳转成功=客户端调起成功，不要求落地页 200。地址含 fail 视为失败。
  • 两个领取按钮去重为同一条已参与。本 FR 不单开未登录页，记账发生在已登录会话。
  • 展位只看 showUserAward+awardStatus，不看榜单、不看是否结束。
  • 奖励规则：半填整条不下发，允许 0 条仍保存。多条独立命中；同类区间重叠按配置顺序第一条命中即停。统计口径沿用现网。
  • 后台：置顶冲突拒绝保存（不自动取消对方）；榜单开且 TOP 小于 1 拒绝保存。半填介绍/案例/领取只是不下发。
  • 完整能力入参/出参见仓库 _bmad-output/specs/spec-fr006-activity-center/fe-be-contract.md。

一条主链：运营保存并显示 → 用户看 Banner/列表 → 点查看进详情（不记已参与）→ 点领取才写已参与。

FR-006 · 需求规则 · v2

1业务目标

用户只看显示池。查看进详情。领取后进入已参与。详情 Tab 为介绍/案例/榜单已配置子集。

2页面与入口

  • 筛选：全部 / 进行中 / 已结束 / 已参与。无待开始 Tab。Banner 不随筛选隐藏。
  • 隐藏活动不进列表/详情。深链隐藏 id 停在列表。已参与后再隐藏则已参与 Tab 消失该卡。
  • 详情页头固定「活动详情」。无我的作品。榜单仅后台开启时出现；空名单仍出该 Tab 内容。
  • 领取底栏最多 2 个、仅介绍 Tab。无介绍则无底栏。跳转成功=客户端调起；地址含 fail 失败。去重（用户, 活动）。

3业务流程

见前端交互 → 业务流程。点查看进详情，领取才写已参与。浏览人数不 +1。

4闭合

  • 展位：showUserAward + 已下发 awardStatus，不绑榜单、不绑是否结束。列表无获奖角标。
  • 榜单开启必带 self；隐藏不请求能力。行数 ≤ TOP。
  • 同分排序按稳定 id。能力入参/出参以 fe-be-contract.md 为准。

1业务目标

两步保存活动。第1步基础+介绍+案例，第2步领取与奖励规则。

2列表

  • 操作：编辑 / 达标用户 / 删除。
  • 已配参加人数可点进参与详情。
  • 不拆子菜单。榜单开关与 TOP 名单数配在第 1 步详情内容。

3保存与下发

  • 拒绝整单：标题空或超长、无开始时间、无活动状态、结束早于开始、显示且置顶冲突（不自动取消对方）。
  • 榜单开且 TOP 小于 1：拒绝保存。半填介绍/案例/领取/奖励：可保存但不下发。
  • 播放奖 / 全勤 / 累计收益：半填整条丢弃。多条独立命中；同类区间重叠按从上到下第一条命中即停。禁止 excludeProjects。
  • 累计收益：品牌项目、其他业务项目至少一类非空。能力契约 fe-be-contract.md。
