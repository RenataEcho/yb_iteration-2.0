FR-006 · 需求规则 · v1

1业务目标

改造现有活动中心，在不改变图1卡片布局的前提下，支持更多活动展现形式：顶部 Banner 置顶、状态筛选，以及报名类活动的已参加人数展示。

2页面与入口

  • 活动中心列表页：个人中心/首页等既有入口进入；页头标题「活动中心」。
  • 置顶 Banner：活动中心顶部以 Banner 形式展示后台配置的置顶活动（最多 1 条）；不在下方列表中重复展示。
  • 筛选 Tab：全部 / 进行中 / 已结束；切换后刷新列表，置顶 Banner 若符合当前筛选条件则仍展示在顶部。
  • 活动状态：待开始 / 进行中 / 已结束（角标展示在卡片图标左上角）。
  • 活动卡片（沿用图1）：项目标签 → 灰色内容区（状态角标 + 图标 + 标题/副标题）→ 底部信息区 +「查看」按钮。
  • 普通活动：底部展示「活动时间·起止日期」，不展示人数。
  • 报名类活动：后台配置为报名类时，底部额外展示「x人已参加」。

3交互规则

  • 活动状态枚举：待开始 / 进行中 / 已结束；筛选「进行中」仅展示状态为进行中的活动。
  • 所有活动卡片及置顶 Banner 的操作按钮统一为「查看」，跳转活动详情页（本 FR 不重做详情页）。
  • 人数展示：仅当后台配置为报名类活动时展示「x人已参加」；普通活动不展示人数。
  • 筛选切换时列表区域 loading → 刷新；置顶 Banner 不参与列表分页，固定在最上方。
  • 列表卡片布局沿用图1；置顶 Banner 参考图2 Banner 形态，色彩沿用 C 端体系。

4边界规则

  • 同时仅允许 1 条置顶活动；后台取消置顶后 Banner 立即移除。
  • 已参加人数以后端实时统计为准；前端不做本地累加；非报名类活动不返回人数字段。
  • 活动状态由后台配置的活动时间驱动（待开始 → 进行中 → 已结束）。
  • 无活动时展示空态文案「暂无符合条件的活动」。

5业务流程

前后端交互与校验逻辑见页内 Tab 「业务流程」。

1业务目标

运营可在后台配置活动类型（是否报名类）、活动时间、置顶 Banner，并查看已参加人数。

2数据表与字段

  • 活动表字段：ID、名称、副标题、所属项目、是否报名类、状态（待开始/进行中/已结束）、是否置顶 Banner、Banner 封面/图标、活动时间起止、已参加人数（报名类只读统计）、创建/更新时间。
  • 置顶 Banner 额外字段：Banner 标题、Banner 副文案（可与列表卡片字段复用或独立配置）。

3列表与筛选

  • 筛选项：活动 ID、名称、类型、状态、是否置顶。
  • 操作列：编辑 / 上下架 / 取消置顶。
  • 新增/编辑表单：勾选「报名类活动」时展示已参加人数（只读）；勾选「置顶 Banner」时展示 Banner 配置项。

4边界规则

  • 置顶活动必须处于上架状态；下架后自动取消置顶。
  • 已参加人数不可手动编辑，仅报名类活动展示。
  • 活动状态根据配置的活动时间自动流转（待开始 → 进行中 → 已结束），运营可手动提前结束。
