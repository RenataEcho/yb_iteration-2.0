FR-010 · 需求规则 · v3

1业务目标

在「代理迭代V1.0」下提供「代理认证」审核：运营审核代理提交的企业资料、对公账户与合同，通过后支撑后续线上结算与提现。

2数据表与字段

代理认证表：

  • 代理ID
  • 代理帐号
  • 代理名称
  • 企业信息（聚合展示）：企业名称、社会编码、公司电话、公司地址、营业执照
  • 对公账户信息（聚合展示）：收款帐户名称、开户行名称、支行名称、收款银行帐号、发票类型、发票税率
  • 合同信息（聚合展示）：合同附件、合同编号、快递信息（快递平台 + 快递单号）
  • 合同附件来源：系统按合同模板动态渲染生成合同，供代理下载；代理下载后加盖公章，再上传 PDF。后台「查看合同」打开的是这份代理回传的加盖公章 PDF，不是系统草稿。格式仅 PDF。
  • 合同编号生成规则（系统生成，运营/代理不可手改）：固定前缀 YB-DL + 动态后缀（年月日 + 代理编号 + 合同序数）。格式 YB-DL-{YYYYMMDD}-{代理编号}-{合同序数}。年月日取合同生成日（与申请提交日同一天，8 位）；代理编号取代理 ID 数字段（如 A-10086 → 10086）；合同序数按该代理累计合同份数 2 位补零，首次 01，驳回后重新提交递增。示例：YB-DL-20260904-10086-01
  • 审核状态：待审核 / 已通过 / 已驳回；已驳回必须展示驳回原因
  • 申请时间（代理提交时系统写入）
  • 审核时间（通过或驳回时系统写入；待审核为空）
  • 操作：通过、驳回（驳回必须填写原因）

3列表与筛选

筛选项：代理帐号、审核状态。

  • 代理帐号：模糊匹配。
  • 审核状态：全部 / 待审核 / 已通过 / 已驳回。
  • 查询：刷新列表，页码重置至第 1 页。
  • 重置：清空筛选条件，不自动触发查询，Toast 提示「筛选条件已重置」。

聚合展示：

  • 企业信息、对公账户信息、合同信息在同一单元格内分行展示全部子字段，不拆列。
  • 营业执照在企业信息内以「查看营业执照」文字链打开预览，不直接铺原图。
  • 合同附件在合同信息内以「查看合同」文字链打开预览，不直接铺原文件；预览对象为代理回传的加盖公章 PDF。同时展示按规则生成的合同编号、快递平台与快递单号。

表头统计（随当前查询结果联动）：待审核、已通过、已驳回笔数。

4审核操作

  • 仅待审核记录展示「通过 / 驳回」。已通过、已驳回不再提供审核操作。
  • 通过：二次确认后状态改为已通过，写入审核时间。通过不填原因。
  • 驳回：打开驳回弹窗，驳回原因必填；确认后状态改为已驳回，写入审核时间与原因。列表审核状态列展示「已驳回」+ 原因。
  • 驳回弹窗为危险确认：遮罩不可点击关闭，防止误关丢失已填原因。
  • 审核结论本轮不可撤回、不可改判。

5边界规则

  • 一个代理同一时间仅允许一条待审核或已通过记录。驳回后可重新提交，历史驳回行保留。
  • 已通过认证的对公账户用于后续线上结算与提现；未通过（待审核 / 已驳回）不可结算。
  • 本轮不交付代理端填写页 Demo。填写字段与后台「企业信息 / 对公账户信息 / 合同信息」聚合项对齐；合同下载（动态渲染）与盖章 PDF 回传在代理端完成。
  • 本 Demo 不做真实接口、权限与持久化。

6业务流程

见「代理认证」下 Tab 「业务流程」流程图。自动化用例见旁侧 Tab 「QA用例」。

1业务目标

在「代理迭代V1.0」下提供「代理提现」审核与打款：运营核对结算单、发票与对公账户后审核，审核通过后再执行打款，形成可追溯的结算闭环。

2数据表与字段

代理提现表：

  • 代理ID
  • 代理帐号
  • 代理名称
  • 申请结算单（结算单号，可预览结算单）
  • 申请提现金额
  • 开票信息（聚合展示）：开票金额、开票税额
  • 申请资料：均为代理端上传。结算单为代理加盖公章后的 PDF；发票为代理上传的发票文件（PDF）。运营不代传。列表以「查看结算单 / 查看发票」文字链预览，不直接铺原文件。
  • 对公账户信息（聚合展示）：收款帐户名称、开户行名称、支行名称、收款银行帐号、发票类型、发票税率
  • 审核状态：待审核 / 审核通过 / 审核驳回；审核驳回必须展示驳回原因
  • 打款状态：待打款 / 已打款 / 打款失败；打款失败必须展示失败原因
  • 打款回执（独立字段）：仅打款成功 / 已打款后展示「查看回执」文字链；待打款、打款失败、审核驳回显示「—」
  • 操作：审核通过、审核驳回、打款成功、打款失败

3列表与筛选

筛选项：代理帐号、审核状态、打款状态。

  • 代理帐号：模糊匹配。
  • 审核状态：全部 / 待审核 / 审核通过 / 审核驳回。
  • 打款状态：全部 / 待打款 / 已打款 / 打款失败。
  • 查询：刷新列表，页码重置至第 1 页。
  • 重置：清空筛选条件，不自动触发查询，Toast 提示「筛选条件已重置」。

聚合展示：开票信息、对公账户信息在同一单元格内分行展示全部子字段，不拆列。申请资料列只放代理回传的盖章结算单 PDF 与发票文件。

表头统计（随当前查询结果联动）：待审核、待打款、已打款的笔数 + 申请提现金额合计。

4审核与打款操作

  • 仅待审核记录展示「审核通过 / 审核驳回」。
  • 审核通过：二次确认后审核状态改为审核通过，打款状态保持待打款。通过不填原因。
  • 审核驳回：打开驳回弹窗，驳回原因必填；确认后审核状态改为审核驳回，不再进入打款。列表审核状态列展示「审核驳回」+ 原因。
  • 仅审核通过且打款状态为待打款或打款失败的记录展示「打款成功 / 打款失败」。
  • 打款成功：必须上传打款回执单，确认后打款状态改为已打款。列表打款回执字段出现「查看回执」，点击预览回执单。
  • 打款失败：失败原因必填；确认后打款状态改为打款失败，列表展示原因。失败后允许重新标记打款成功或再次失败。
  • 驳回、失败弹窗为危险确认：遮罩不可点击关闭。
  • 审核驳回本轮不可改判；已打款不可再次打款。

5边界规则

  • 仅认证已通过的代理可发起提现；未认证或认证驳回不可结算。
  • 审核驳回后代理按原因修订并重新提交，生成新的待审核记录，历史驳回行保留。
  • 本轮不交付代理端提现申请页 Demo。申请资料（盖章结算单 PDF + 发票文件）由代理端上传，字段与后台列表聚合项对齐。
  • 本 Demo 不做真实接口、权限、打款渠道与持久化。

6业务流程

见「代理提现」下 Tab 「业务流程」流程图。

1业务目标

在「代理迭代V1.0」下提供「代理价格」：为代理已授权项目配置结算字段级代理价格。右豹项目侧的结算字段、单价类型、原始价格、描述只读带出；运营只改代理价格。保存后，该代理在对应项目的收益按配置的代理价格计算。

2页面与入口

本轮不另做代理列表，直接复用已上线的代理授权项目列表做价格配置与结果字段。

  • 项目授权列表：ID、项目名称、服务费比例、状态、订单数、作品数、订单量（整数，非金额）、关键词数、累计金额、服务费、更新时间。
  • 服务费 = 累计金额 × 服务费比例；服务费比例变更后即时重算。
  • 操作列：价格配置、编辑、日志、删除。
  • 筛选项沿用现网：项目名称（模糊）、状态（全部 / 已授权 / 已禁用）。
  • 现网已有能力保留：批量新增授权、批量设置服务费比例、批量启用/禁用；这些操作同样写入日志。

3价格配置弹窗

点击「价格配置」打开弹窗，以可编辑表格配置该项目下全部结算字段。

列定义：

  • 结算字段：取该项目在右豹的结算字段，只读展示。
  • 单价类型：取该项目在右豹的单价类型（如固定单价 / 阶梯单价 / 按量计价），只读展示。
  • 原始价格：取该项目在右豹配置的原始单价，只读展示。
  • 代理价格：本轮唯一可编辑列。允许为空（未配置）；填写时须 ≥ 0，最多两位小数。
  • 描述：取该项目在右豹的字段说明，只读展示。

交互：

  • 打开弹窗时按当前项目拉取右豹配置；已保存过的代理价格回填。
  • 右豹侧字段增删或原始价格变更时，下次打开以右豹最新配置为准；已有代理价格按结算字段匹配保留，对不上的字段丢弃。
  • 保存时校验全部已填代理价格；任一非法则阻断并定位到第一处错误，不写库。
  • 取消不保存。普通弹窗可点遮罩 / ESC 关闭。

4操作日志

每次价格配置及其他授权操作均记一条日志，按项目维度在「日志」抽屉查看，新记录在上。

  • 价格配置：记录操作人、时间、各结算字段的代理价格变更（旧值 → 新值；空记为「未配置」）。
  • 其他操作：编辑（服务费比例 / 状态）、删除、批量新增授权、批量设置服务费比例、批量启用/禁用，均写日志。
  • 日志字段：时间、操作人、操作类型、摘要。本 Demo 操作人固定为「运营·张敏」。
  • 删除项目后历史日志随记录保留在 Demo 内存中，再次进入同一 ID 仍可查看；真实实现由后端按授权记录 ID 归档。

5收益计算

  • 代理收益按已配置的代理价格计算：字段收益 = 该字段单量 × 代理价格，项目收益为各已配置字段之和。
  • 未配置（代理价格为空）的结算字段不计入代理收益，也不回退右豹原始价格。
  • 右豹原始价格仅作对照展示，不参与代理收益。
  • 列表「累计金额」仍展示右豹原价口径，便于对账；「服务费」按 累计金额 × 服务费比例 展示；代理侧出账 / 提现以代理价格重算结果为准。

6边界规则

  • 仅已授权项目可配置价格；已禁用项目仍可查看已有配置，保存时 Toast 提示「项目已禁用，价格配置未生效于新订单」，但允许改价（历史对账用）。
  • 未授权或不存在的项目不提供「价格配置」。
  • 本轮不交付代理端价格查看页；代理端收益数字以后台按代理价格算出的结果为准。
  • 本 Demo 不做真实接口、权限与持久化。

7业务流程

见「代理价格」下 Tab 「业务流程」流程图。

1业务目标

在「代理迭代V1.0」下提供「代理通知」：把发给代理的消息按类型拆成系统提示与平台通知，支撑系统自动告知审核/账单结果，也支持运营主动群发或定向发送。

2通知类型

系统提示：功能更新、系统维护等平台侧提示，不绑定单一业务单据。

平台通知：资料审核、提现审核、账单生成、关键词批量下线等业务结果告知。

  • 一条通知只属于其中一类，后台与代理端按类型分栏展示。
  • 系统提示、平台通知都进入同一张「代理通知」表，用「通知类型」区分。

3触发方式

系统触发（运营不可手改类型与接收人）：

  • 资料审核结果：认证通过或驳回后自动生成平台通知，接收人为该代理。
  • 提现审核结果：提现审核通过或驳回后自动生成平台通知，接收人为该代理。
  • 账单生成：系统生成结算账单后自动生成平台通知，接收人为该代理。

运营主动：点击「新增通知」人工发送。关键词批量下线走主动发送（可选平台通知），不由系统代写。

4数据表与字段

代理通知表：

  • 通知ID
  • 通知类型：系统提示 / 平台通知
  • 业务分类：功能更新、系统维护（系统提示）；资料审核、提现审核、账单生成、关键词批量下线（平台通知）
  • 标题
  • 描述
  • 图片（可选；运营主动可配图，系统触发通常无图）
  • 触发方式：系统触发 / 运营主动
  • 接收范围：全部代理 / 指定代理（列出帐号与名称）
  • 发送时间
  • 操作：详情

5主动新增

「新增通知」为右侧表单抽屉（520px），分三组配置，Footer 固定「取消 / 确认发送」。不使用弹窗。

  • 通知内容：类型（卡片二选一：系统提示 / 平台通知）、标题（必填，最多 40 字）、描述（必填，最多 200 字）。
  • 配图：选填，支持 JPG / PNG / WEBP；列表以「查看图片」预览，不直接铺原图。
  • 接收范围：全部代理 / 指定代理。指定代理须至少勾选 1 个已有代理帐号。

保存后立即写入列表并视为已推送。系统触发记录不可在此抽屉编辑或补发。打开新增时关闭详情抽屉，避免双层叠加。

6列表与筛选

筛选项：标题（模糊）、通知类型、触发方式。

  • 查询：刷新列表，页码重置至第 1 页。
  • 重置：清空筛选条件，不自动触发查询，Toast 提示「筛选条件已重置」。

表头统计（随当前查询结果联动）：全部、系统提示、平台通知、运营主动笔数。

7边界规则

  • 系统触发通知的类型固定为平台通知，接收范围固定为当事代理，标题/描述由事件结果生成（通过/驳回/账单周期）。
  • 本轮不交付代理端消息中心 Demo；代理端按系统提示 / 平台通知分栏展示，字段与后台列表对齐。
  • 本 Demo 不做真实推送通道、已读态与持久化。
