代理迭代V1.0 FR-010 v6 当前

代理板块本轮交付认证审核、月结结算单、提现结算、授权项目价格配置与代理通知。认证通过后对公账户可用于线上结算；系统按订单日期自然月归集并在当月全部结算后推送结算单；提现需审核通过后再打款；已授权项目可配置代理价格；代理消息分系统提示与平台通知，支持系统触发与运营主动发送。

FR-010 · 代理迭代V1.0

先认证对公账户，再配项目价格；月结账单推送后，提现必须审核通过才能打款

本轮后台交付五件事：认证审核、月结结算单、提现结算、授权项目价格、代理通知。代理端填写页、提现申请页、价格查看页、消息中心本轮都不做 Demo，但字段和后台对齐。运营日常只在本页五个业务 Tab 里审、核、配、发。

30 秒故事

  1. 代理提交企业资料、对公账户、盖章合同 PDF → 运营在「代理认证」通过或驳回。
  2. 只有认证已通过，对公账户才能用于线上结算和提现；未通过不能结算。
  3. 已授权项目在「代理价格」配结算字段级代理价；代理收益按代理价算，不回退右豹原价。
  4. 系统按订单日期自然月归集，按代理拆单（未认证代理不跳过）。各项目都结算完成才把结算单标成已生成并推送；有项目还在结算中则未生成、不推送。
  5. 代理提交盖章结算单 + 发票 → 运营先审提现，通过后打款；打款成功必须上传回执。
  6. 认证/提现结果、账单生成会自动发平台通知；运营也可主动群发或定向发送。

五个 Tab 各管什么

代理认证

审企业、对公账户、盖章合同。通过后才具备结算资格。结论本轮不可改判。

代理结算单

系统按自然月按代理拆单。已生成才推送给代理；未生成说明还有项目在结算中。明细里看各项目结算状态。

代理提现

核对结算单、发票、对公账户后审核；通过再打款。审核驳回不可改判，打款失败可重标。

代理价格

复用已上线的授权项目列表。右豹结算字段/原价只读，运营只改代理价格。未配置字段不计入代理收益。

代理通知

系统提示（功能/维护）与平台通知（审核/账单/下线）。系统触发不可手改；运营主动用抽屉发送。

对外口径：账单已生成 ≠ 已经打款。钱要等代理自己对照结算单提现，运营审过、打款成功并上传回执，才算闭环。
代理认证

只审待审核；通过不填原因，驳回必须写原因

列表聚合看企业信息、对公账户、合同，不拆很多列。营业执照和合同都用文字链预览，不直接铺原图。「查看合同」打开的是代理回传的加盖公章 PDF，不是系统草稿。

合同从哪来

  1. 系统按模板动态渲染合同，代理下载。
  2. 代理加盖公章后上传 PDF（仅 PDF）。
  3. 合同编号系统生成，运营/代理都不能手改：YB-DL-{年月日}-{代理编号}-{合同序数}。示例 YB-DL-20260904-10086-01。
  4. 驳回后重新提交，合同序数递增（01 → 02）。

审核规则

状态列表操作运营要记住
待审核通过 / 驳回通过二次确认，不填原因；驳回弹窗原因必填，遮罩点不关
已通过已审核（无按钮）对公账户可用于结算和提现；本轮不能改判
已驳回已审核（无按钮）必须展示驳回原因；代理可重提，历史驳回行保留
一个代理同一时间只允许一条「待审核」或「已通过」。驳回后才能再交新的。筛选重置只清空条件，不自动查，避免误以为数据没了。
代理结算单

按代理拆单就能看见账单；只有已生成才会推送给代理

关账后按代理拆出每月结算单，未认证代理不跳过，后台都能对账。运营在本 Tab 看结算单状态、金额和提现进度，不在这里审核打款。「查看明细」按项目拆开，并标结算状态。

结算单状态怎么读

结算单状态项目结算状态是否推送给代理
已生成该月各项目都是「结算完成」推送；代理才能对照账单申请提现
未生成只要有一个项目还是「结算中」不推送；意味着还有项目订单未结算
未认证代理也会出结算单行，方便对账。但认证没通过仍不能提现。一个代理同一个自然月只有一张结算单。

钱怎么算

  • 收益金额：按该代理已配置的代理价格重算，不是列表里的右豹累计金额。
  • 服务费：各项目收益金额 × 服务费比例之和。
  • 可提现金额：各项目 收益金额 × (1 - 服务费比例) 之和。
  • 月结归集订单日期落在该自然月的订单；未生成账单的可提现只是预览，不推送给代理。

提现状态怎么读

状态含义和「代理提现」的关系
—结算单未生成，尚未推送没有提现行，也不能申请
未提现账单已生成并推送，代理还没申请提现列表没有对应申请行
提现中已提交盖章结算单 + 发票对应提现行处于待审核 / 待打款 / 打款失败
已提现打款成功并上传回执对应提现行打款状态=已打款
本 Tab 只读对账。审核、驳回、打款都在「代理提现」。明细抽屉里的合计必须等于列表「可提现金额」。
代理提现

两段状态：先审核，再打款。回执只在打款成功后出现

申请资料全部由代理上传：盖章结算单 PDF + 发票 PDF。运营不代传。对公账户从认证带出，聚合展示。表头统计是当前查询结果的笔数和申请提现金额合计。

状态怎么走

阶段可做什么结果
待审核 审核通过 / 审核驳回 通过 → 打款状态仍是待打款；驳回必须写原因，不再进入打款，本轮不可改判
审核通过 + 待打款/打款失败 打款成功 / 打款失败 成功必须上传回执，列表出现「查看回执」；失败必须写原因，允许再标成功或再失败
已打款 无打款按钮 不可再次打款；回执可预览
审核驳回 无审核/打款按钮 代理按原因修订后重新提交，生成新的待审核行，旧行保留
未认证或认证已驳回的代理不能提现。打款回执只在「已打款」展示；待打款、打款失败、审核驳回这一列都是「—」，不是丢了文件。
代理价格

不另做代理列表，直接在已授权项目上配价

右豹侧的结算字段、单价类型、原始价格、描述全部只读带出。运营唯一能改的是代理价格（可空，填了必须 ≥ 0，最多两位小数）。保存后，该代理在这个项目的收益按代理价算。

钱怎么算，别和列表数字搞混

  • 字段收益 = 该字段单量 × 代理价格；项目收益 = 已配置字段之和。
  • 代理价格为空的字段不计入代理收益，也不会自动改用右豹原价。
  • 列表「累计金额」是计算代理价格，方便对账；「服务费」= 累计金额 × 服务费比例。
  • 代理侧出账 / 提现以按代理价格重算的结果为准，不是累计金额。
右豹字段增删或原价变更后，下次打开弹窗以右豹最新配置为准；已有代理价按结算字段名匹配保留，对不上的字段丢掉。已禁用项目仍可改价（历史对账），但新订单不生效，会 Toast 提示。

还保留的现网能力

批量新增授权、批量设服务费比例、批量启用/禁用、编辑、删除，全部写日志。日志按项目看，新的在上面；价格变更记旧值 → 新值，空记「未配置」。

代理通知

一条通知只属于一类：系统提示或平台通知

两类进同一张表，用「通知类型」区分。后台和代理端都按类型分栏。系统触发记录不能在新增抽屉里改或补发。误发可在操作列删除，删除后代理端同步消失。

系统提示

功能更新、系统维护等平台侧提示，不绑单一业务单据。一般由运营主动发。

平台通知

资料审核、提现审核、账单生成、关键词批量下线等业务结果。前三项系统自动发给当事代理。

谁触发

  • 系统触发：认证通过/驳回、提现审核通过/驳回、账单生成。类型固定为平台通知，接收人固定为该代理，标题描述由事件结果生成。运营不能手改类型和接收人。
  • 运营主动：点「新增通知」用右侧表单抽屉（不是弹窗）。关键词批量下线走主动发送，系统不代写。
  • 主动发送：类型二选一、标题必填 ≤40 字、描述必填 ≤200 字、配图选填（JPG/PNG/WEBP）、接收范围=全部或至少勾 1 个代理。保存即视为已推送。
  • 删除：操作列提供删除，用于撤回误发。确认后后台列表移除，代理端对应消息同步删除，不可恢复。
本轮不做代理端消息中心 Demo，也不做已读态和真实推送通道。和用户说「后台已发送 / 已删除」即可，不要承诺已读回执。
客服 / 运营话术

先问卡在认证、账单、提现、价格还是消息，再对状态

代理很少说「FR-010」。他们会说「我交了资料没通过」「这个月账单怎么还没出」「钱怎么还没到账」「价格怎么和后台不一样」。

Q1. 代理说合同编号不对，能不能改？
不能手改。编号是 YB-DL-年月日-代理编号-序数，系统生成。先核对该代理 ID 数字段和合同生成日；驳回重提序数会加一，旧编号不会复用。
Q2. 「查看合同」看到的是空白草稿？
后台预览必须是代理回传的盖章 PDF。若仍是系统草稿，说明代理还没上传盖章件，应驳回并写明「请上传加盖公章的合同 PDF」。
Q3. 认证通过了，为什么还不能提现？
认证通过只是具备结算资格。还要等系统按订单日期把当月账单推送出来，代理再对照结算单提交盖章件和发票，走「待审核 → 审核通过 → 待打款 → 已打款」。没账单或没申请，提现列表都不会有行。
Q4. 提现审过了，钱还没到？
看打款状态。还是「待打款」说明运营还没标打款成功；「打款失败」会带失败原因，可以重新标记。只有「已打款」且有回执，才算打出去。已打款不能再打一次。
Q5. 审核驳回能不能改成通过？
本轮认证结论、提现审核驳回都不可改判。代理按原因改完重新提交，会多一行新的待审核，旧驳回行留着对账。
Q6. 项目已禁用，为什么还能改价？
允许改，方便历史对账；保存会提示「未生效于新订单」。未授权或不存在的项目没有价格配置入口。
Q7. 系统通知发错了能不能改？
不能改内容。误发在操作列删除，删除后代理端消息同步消失。要补充说明，另外再发一条运营主动通知。
Q8. 这个月账单为什么还没出？
先看结算单状态。有项目还是「结算中」，整张结算单就是「未生成」，不会推送给代理。等各项目都「结算完成」才变成已生成并推送。未认证代理后台也会有结算单，只是认证没过不能提现。
Q9. 重置筛选后列表怎么没变？
五个列表都是「重置只清空条件，不自动查询」。再点一次查询才会按空条件刷新。

对外不要承诺的事

  • 不能改合同编号、不能改判已审结论、不能替代理代传盖章件和发票。
  • 不能把未配置代理价的字段按右豹原价给代理结算。
  • 不能承诺代理端消息已读、真实推送到达回执。
  • 本轮没有代理端填写/提现/价格/消息中心 Demo，不要说「App 里某页可以改」。

代理消息分系统提示与平台通知。资料审核结果、提现审核结果、账单生成由系统触发，类型锁定为平台通知、接收人为当事代理。功能更新、系统维护等由运营主动新增，须选通知类型、填写标题与描述、可选配图，并指定全部代理或指定代理。后台删除误发后，代理端对应消息同步删除。菱形为校验节点。

FR-010 · 需求规则 · v6

1业务目标

在「代理迭代V1.0」下提供「代理认证」审核：运营审核代理提交的企业资料、对公账户与合同，通过后支撑后续线上结算与提现。

2数据表与字段

代理认证表：

  • 代理ID
  • 代理帐号
  • 代理名称
  • 企业信息（聚合展示）：企业名称、社会编码、公司电话、公司地址、营业执照
  • 对公账户信息（聚合展示）：收款帐户名称、开户行名称、支行名称、收款银行帐号、发票类型、发票税率
  • 合同信息（聚合展示）：合同附件、合同编号、快递信息（快递平台 + 快递单号）
  • 合同附件来源：系统按合同模板动态渲染生成合同，供代理下载；代理下载后加盖公章，再上传 PDF。后台「查看合同」打开的是这份代理回传的加盖公章 PDF，不是系统草稿。格式仅 PDF。
  • 合同编号生成规则（系统生成，运营/代理不可手改）：固定前缀 YB-DL + 动态后缀（年月日 + 代理编号 + 合同序数）。格式 YB-DL-{YYYYMMDD}-{代理编号}-{合同序数}。年月日取合同生成日（与申请提交日同一天，8 位）；代理编号取代理 ID 数字段（如 A-10086 → 10086）；合同序数按该代理累计合同份数 2 位补零，首次 01，驳回后重新提交递增。示例：YB-DL-20260904-10086-01
  • 审核状态：待审核 / 已通过 / 已驳回；已驳回必须展示驳回原因
  • 申请时间（代理提交时系统写入）
  • 审核时间（通过或驳回时系统写入；待审核为空）
  • 操作：通过、驳回（驳回必须填写原因）

3列表与筛选

筛选项：代理帐号、审核状态。

  • 代理帐号：模糊匹配。
  • 审核状态：全部 / 待审核 / 已通过 / 已驳回。
  • 查询：刷新列表，页码重置至第 1 页。
  • 重置：清空筛选条件，不自动触发查询，Toast 提示「筛选条件已重置」。

聚合展示：

  • 企业信息、对公账户信息、合同信息在同一单元格内分行展示全部子字段，不拆列。
  • 营业执照在企业信息内以「查看营业执照」文字链打开预览，不直接铺原图。
  • 合同附件在合同信息内以「查看合同」文字链打开预览，不直接铺原文件；预览对象为代理回传的加盖公章 PDF。同时展示按规则生成的合同编号、快递平台与快递单号。

表头统计（随当前查询结果联动）：待审核、已通过、已驳回笔数。

4审核操作

  • 仅待审核记录展示「通过 / 驳回」。已通过、已驳回不再提供审核操作。
  • 通过：二次确认后状态改为已通过，写入审核时间。通过不填原因。
  • 驳回：打开驳回弹窗，驳回原因必填；确认后状态改为已驳回，写入审核时间与原因。列表审核状态列展示「已驳回」+ 原因。
  • 驳回弹窗为危险确认：遮罩不可点击关闭，防止误关丢失已填原因。
  • 审核结论本轮不可撤回、不可改判。

5边界规则

  • 一个代理同一时间仅允许一条待审核或已通过记录。驳回后可重新提交，历史驳回行保留。
  • 已通过认证的对公账户用于后续线上结算与提现；未通过（待审核 / 已驳回）不可结算。
  • 本轮不交付代理端填写页 Demo。填写字段与后台「企业信息 / 对公账户信息 / 合同信息」聚合项对齐；合同下载（动态渲染）与盖章 PDF 回传在代理端完成。
  • 本 Demo 不做真实接口、权限与持久化。

6业务流程

见「代理认证」下 Tab 「业务流程」流程图。自动化用例见旁侧 Tab 「QA用例」。

1业务目标

在「代理迭代V1.0」下提供「代理结算单」：系统按订单日期自然月归集订单，按代理拆单（未认证代理不跳过）。各项目都结算完成后结算单变为已生成并推送给代理；任一项目仍结算中则结算单为未生成、不推送。供运营核对收益、服务费、可提现与提现进度。

2数据表与字段

代理结算单表：

  • 代理名称
  • 账单月份（自然月，格式 YYYY-MM）
  • 结算单（系统单号，格式 SET-{YYYYMM}-{当月序数}，示例 SET-202608-01）
  • 结算单状态：已生成 / 未生成
  • 收益金额：该月各项目按代理价格重算后的收益之和
  • 服务费：各项目 收益金额 × 服务费比例 之和
  • 可提现金额：各项目 收益金额 × (1 - 服务费比例) 之和
  • 提现状态：未提现 / 提现中 / 已提现；结算单未生成时展示「—」
  • 操作：查看明细

明细抽屉字段：项目名称、订单量、收益金额、服务费比例、结算状态（结算中 / 结算完成）；底部展示可提现金额合计与口径说明。

3列表与筛选

筛选项：代理名称、账单月份、结算单状态、提现状态。

  • 代理名称：模糊匹配。
  • 账单月份：全部 / 已出现的自然月。
  • 结算单状态：全部 / 已生成 / 未生成。
  • 提现状态：全部 / 未提现 / 提现中 / 已提现。
  • 查询：刷新列表，页码重置至第 1 页。
  • 重置：清空筛选条件，不自动触发查询，Toast 提示「筛选条件已重置」。

表头统计（随当前查询结果联动）：未生成、已生成、未提现、已提现的笔数 + 可提现金额合计。

4查看明细

  • 点击「查看明细」打开右侧抽屉，标题为 {账单月份} 账单明细。
  • 副文案：已生成写「已生成，已推送给代理」；未生成写「未生成，尚有项目订单未结算，不推送给代理」。
  • 明细表按项目分行：项目名称、订单量、收益金额、服务费比例、结算状态（结算中 / 结算完成）。
  • 底部「可提现金额合计」必须等于列表该行可提现金额。
  • 口径说明用红色强调「收益金额 × (1 - 服务费比例)」与「订单日期」。
  • 本抽屉只读，不提供编辑、下载以外的写操作。关闭用「关闭」按钮、遮罩或 ESC。

5边界规则

  • 按代理拆单时未认证代理不跳过；待审核 / 已驳回也会出结算单行，便于对账。认证未通过仍不能提现。
  • 一个代理同一个自然月只有一张结算单。
  • 任一项目结算状态为结算中，结算单状态=未生成，不推送给代理。各项目都是结算完成，结算单状态=已生成，才推送给代理。
  • 月结以订单日期归集。
  • 未配置代理价的字段不计入收益，也不回退右豹原价。
  • 提现状态只读映射「代理提现」进度：结算单未生成=「—」；已生成且无申请=未提现；待审核/待打款/打款失败=提现中；已打款=已提现。审核驳回后回到未提现，可再申请。
  • 本 Tab 不做审核、打款；本轮不交付代理端账单页 Demo。
  • 本 Demo 不做真实接口、权限与持久化。

6业务流程

见「代理结算单」下 Tab 「业务流程」流程图。

1业务目标

在「代理迭代V1.0」下提供「代理提现」审核与打款：运营核对结算单、发票与对公账户后审核，审核通过后再执行打款，形成可追溯的结算闭环。

2数据表与字段

代理提现表：

  • 代理ID
  • 代理帐号
  • 代理名称
  • 申请结算单（结算单号，可预览结算单）
  • 申请提现金额
  • 开票信息（聚合展示）：开票金额、开票税额
  • 申请资料：均为代理端上传。结算单为代理加盖公章后的 PDF；发票为代理上传的发票文件（PDF）。运营不代传。列表以「查看结算单 / 查看发票」文字链预览，不直接铺原文件。
  • 对公账户信息（聚合展示）：收款帐户名称、开户行名称、支行名称、收款银行帐号、发票类型、发票税率
  • 审核状态：待审核 / 审核通过 / 审核驳回；审核驳回必须展示驳回原因
  • 打款状态：待打款 / 已打款 / 打款失败；打款失败必须展示失败原因
  • 打款回执（独立字段）：仅打款成功 / 已打款后展示「查看回执」文字链；待打款、打款失败、审核驳回显示「—」
  • 操作：审核通过、审核驳回、打款成功、打款失败

3列表与筛选

筛选项：代理帐号、审核状态、打款状态。

  • 代理帐号：模糊匹配。
  • 审核状态：全部 / 待审核 / 审核通过 / 审核驳回。
  • 打款状态：全部 / 待打款 / 已打款 / 打款失败。
  • 查询：刷新列表，页码重置至第 1 页。
  • 重置：清空筛选条件，不自动触发查询，Toast 提示「筛选条件已重置」。

聚合展示：开票信息、对公账户信息在同一单元格内分行展示全部子字段，不拆列。申请资料列只放代理回传的盖章结算单 PDF 与发票文件。

表头统计（随当前查询结果联动）：待审核、待打款、已打款的笔数 + 申请提现金额合计。

4审核与打款操作

  • 仅待审核记录展示「审核通过 / 审核驳回」。
  • 审核通过：二次确认后审核状态改为审核通过，打款状态保持待打款。通过不填原因。
  • 审核驳回：打开驳回弹窗，驳回原因必填；确认后审核状态改为审核驳回，不再进入打款。列表审核状态列展示「审核驳回」+ 原因。
  • 仅审核通过且打款状态为待打款或打款失败的记录展示「打款成功 / 打款失败」。
  • 打款成功：必须上传打款回执单，确认后打款状态改为已打款。列表打款回执字段出现「查看回执」，点击预览回执单。
  • 打款失败：失败原因必填；确认后打款状态改为打款失败，列表展示原因。失败后允许重新标记打款成功或再次失败。
  • 驳回、失败弹窗为危险确认：遮罩不可点击关闭。
  • 审核驳回本轮不可改判；已打款不可再次打款。

5边界规则

  • 仅认证已通过的代理可发起提现；未认证或认证驳回不可结算。
  • 审核驳回后代理按原因修订并重新提交，生成新的待审核记录，历史驳回行保留。
  • 本轮不交付代理端提现申请页 Demo。申请资料（盖章结算单 PDF + 发票文件）由代理端上传，字段与后台列表聚合项对齐。
  • 本 Demo 不做真实接口、权限、打款渠道与持久化。

6业务流程

见「代理提现」下 Tab 「业务流程」流程图。

1业务目标

在「代理迭代V1.0」下提供「代理价格」：为代理已授权项目配置结算字段级代理价格。右豹项目侧的结算字段、单价类型、原始价格、描述只读带出；运营只改代理价格。保存后，该代理在对应项目的收益按配置的代理价格计算。

2页面与入口

本轮不另做代理列表，直接复用已上线的代理授权项目列表做价格配置与结果字段。

  • 项目授权列表：ID、项目名称、服务费比例、状态、订单数、作品数、订单量（整数，非金额）、关键词数、累计金额、服务费、更新时间。
  • 服务费 = 累计金额 × 服务费比例；服务费比例变更后即时重算。
  • 操作列：价格配置、编辑、日志、删除。
  • 筛选项沿用现网：项目名称（模糊）、状态（全部 / 已授权 / 已禁用）。
  • 现网已有能力保留：批量新增授权、批量设置服务费比例、批量启用/禁用；这些操作同样写入日志。

3价格配置弹窗

点击「价格配置」打开弹窗，以可编辑表格配置该项目下全部结算字段。

列定义：

  • 结算字段：取该项目在右豹的结算字段，只读展示。
  • 单价类型：取该项目在右豹的单价类型（如固定单价 / 阶梯单价 / 按量计价），只读展示。
  • 原始价格：取该项目在右豹配置的原始单价，只读展示。
  • 代理价格：本轮唯一可编辑列。允许为空（未配置）；填写时须 ≥ 0，最多两位小数。
  • 描述：取该项目在右豹的字段说明，只读展示。

交互：

  • 打开弹窗时按当前项目拉取右豹配置；已保存过的代理价格回填。
  • 右豹侧字段增删或原始价格变更时，下次打开以右豹最新配置为准；已有代理价格按结算字段匹配保留，对不上的字段丢弃。
  • 保存时校验全部已填代理价格；任一非法则阻断并定位到第一处错误，不写库。
  • 取消不保存。普通弹窗可点遮罩 / ESC 关闭。

4操作日志

每次价格配置及其他授权操作均记一条日志，按项目维度在「日志」抽屉查看，新记录在上。

  • 价格配置：记录操作人、时间、各结算字段的代理价格变更（旧值 → 新值；空记为「未配置」）。
  • 其他操作：编辑（服务费比例 / 状态）、删除、批量新增授权、批量设置服务费比例、批量启用/禁用，均写日志。
  • 日志字段：时间、操作人、操作类型、摘要。本 Demo 操作人固定为「运营·张敏」。
  • 删除项目后历史日志随记录保留在 Demo 内存中，再次进入同一 ID 仍可查看；真实实现由后端按授权记录 ID 归档。

5收益计算

  • 代理收益按已配置的代理价格计算：字段收益 = 该字段单量 × 代理价格，项目收益为各已配置字段之和。
  • 未配置（代理价格为空）的结算字段不计入代理收益，也不回退右豹原始价格。
  • 右豹原始价格仅作对照展示，不参与代理收益。
  • 列表「累计金额」仍展示右豹原价口径，便于对账；「服务费」按 累计金额 × 服务费比例 展示；代理侧出账 / 提现以代理价格重算结果为准。

6边界规则

  • 仅已授权项目可配置价格；已禁用项目仍可查看已有配置，保存时 Toast 提示「项目已禁用，价格配置未生效于新订单」，但允许改价（历史对账用）。
  • 未授权或不存在的项目不提供「价格配置」。
  • 本轮不交付代理端价格查看页；代理端收益数字以后台按代理价格算出的结果为准。
  • 本 Demo 不做真实接口、权限与持久化。

7业务流程

见「代理价格」下 Tab 「业务流程」流程图。

1业务目标

在「代理迭代V1.0」下提供「代理通知」：把发给代理的消息按类型拆成系统提示与平台通知，支撑系统自动告知审核/账单结果，也支持运营主动群发或定向发送。

2通知类型

系统提示：功能更新、系统维护等平台侧提示，不绑定单一业务单据。

平台通知：资料审核、提现审核、账单生成、关键词批量下线等业务结果告知。

  • 一条通知只属于其中一类，后台与代理端按类型分栏展示。
  • 系统提示、平台通知都进入同一张「代理通知」表，用「通知类型」区分。

3触发方式

系统触发（运营不可手改类型与接收人）：

  • 资料审核结果：认证通过或驳回后自动生成平台通知，接收人为该代理。
  • 提现审核结果：提现审核通过或驳回后自动生成平台通知，接收人为该代理。
  • 账单生成：系统生成结算账单后自动生成平台通知，接收人为该代理。

运营主动：点击「新增通知」人工发送。关键词批量下线走主动发送（可选平台通知），不由系统代写。

4数据表与字段

代理通知表：

  • 通知ID
  • 通知类型：系统提示 / 平台通知
  • 业务分类：功能更新、系统维护（系统提示）；资料审核、提现审核、账单生成、关键词批量下线（平台通知）
  • 标题
  • 描述
  • 图片（可选；运营主动可配图，系统触发通常无图）
  • 触发方式：系统触发 / 运营主动
  • 接收范围：全部代理 / 指定代理（列出帐号与名称）
  • 发送时间
  • 操作：详情、删除

5主动新增

「新增通知」为右侧表单抽屉（520px），分三组配置，Footer 固定「取消 / 确认发送」。不使用弹窗。

  • 通知内容：类型（卡片二选一：系统提示 / 平台通知）、标题（必填，最多 40 字）、描述（必填，最多 200 字）。
  • 配图：选填，支持 JPG / PNG / WEBP；列表以「查看图片」预览，不直接铺原图。
  • 接收范围：全部代理 / 指定代理。指定代理须至少勾选 1 个已有代理帐号。

保存后立即写入列表并视为已推送。系统触发记录不可在此抽屉编辑或补发。打开新增时关闭详情抽屉，避免双层叠加。

删除：操作列「删除」打开确认弹窗（标题「确认删除？」，文案含通知标题，不可撤销）。确认后从后台列表移除，并同步删除代理端对应消息。系统触发与运营主动均可删，用于撤回误发。

6列表与筛选

筛选项：标题（模糊）、通知类型、触发方式。

  • 查询：刷新列表，页码重置至第 1 页。
  • 重置：清空筛选条件，不自动触发查询，Toast 提示「筛选条件已重置」。

表头统计（随当前查询结果联动）：全部、系统提示、平台通知、运营主动笔数。

7边界规则

  • 系统触发通知的类型固定为平台通知，接收范围固定为当事代理，标题/描述由事件结果生成（通过/驳回/账单周期）。
  • 本轮不交付代理端消息中心 Demo；代理端按系统提示 / 平台通知分栏展示，字段与后台列表对齐。后台删除后代理端同一条消息同步消失。
  • 本 Demo 不做真实推送通道、已读态与持久化。
