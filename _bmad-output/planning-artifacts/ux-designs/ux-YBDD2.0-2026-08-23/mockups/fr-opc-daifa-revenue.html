FR-002 · 需求规则 · v1

1业务目标

在主子用户关系下增加「代发收益」能力：主用户可绑定多个子用户，经协议确认后按分配类型自动分配收益——「右豹ID直接分配」按比例打入子用户项目收益钱包；「以发布帐号归因分配」按关键词→发布帐号→比例归因（口径与 FR-001 一致）。

2页面与入口

  • 代发收益管理（主用户 · 通用）：个人中心入口「代发收益」；不展示顶部数据统计（无累计已分配/子用户数/关键词数/授权帐号等 hero 区，两种分配类型一致）；右上角规则 icon +「添加」；Tab = 分配信息 / 子用户信息。
  • 分配信息 Tab（两种分配类型 · 首页一致）：record-card 标题「分配金额·xxx」+ 灰底字段域，五列 = 分配金额、总金额、分配比例、分配用户（子用户右豹昵称）、分配时间。
  • 分配信息 Tab · 发布帐号归因：首页字段同上；卡片含「查看详情」入口，下钻至分配详情页。
  • 分配信息 Tab · 右豹ID直接分配：首页字段同上；无查看详情、不可下钻。
  • 分配详情 · 发布帐号归因：关键词作卡片标题；灰底字段域 = 分配金额、分配比例、发布帐号ID；支持导出。
  • 子用户信息 Tab · 发布帐号归因：头像卡片 + 协议状态/时间；三列 = 已分配金额、授权帐号、分配比例；可进入子用户详情。
  • 子用户信息 Tab · 右豹ID直接分配：头像卡片 + 协议状态/时间；两列 = 已分配金额、分配比例；不展示授权帐号；无查看详情入口，不可下钻子用户详情页。
  • 子用户详情（仅发布帐号归因 · 从子用户 Tab 下钻）：头像信息卡 + 授权帐号列表（只读）；不提供分配明细 Tab。
  • 发起协议 / 添加子用户（主用户 · 图2）：复用已实现的发起协议页——填写邀请信息（子用户 ID + 比例）+ 分配信息 + 协议内容（rev_share_agreement）+「发送协议邀请」；本 FR 不重做该页布局。
  • 协议确认（子用户 · 图3）：复用已实现的接受协议页——分配信息 + 协议内容 +「我已阅读并同意协议」/「拒绝」；所有分配类型下子用户仅此一页，同意后流程结束，不进入代发收益子页。

3交互规则

  • 主用户 C 端所有页面均不展示顶部数据统计（含代发收益首页、分配详情下钻页；无 hero 区、无汇总 stat 条）。
  • 子用户视角（所有分配类型）：系统通知 → 接受协议页（图3）→ 同意/拒绝 → 流程结束，无子用户代发收益首页。
  • 主用户添加子用户：跳转/复用发起协议页（图2），与接受协议页（图3）成对，布局与文案以 Demo 已实现页面为准。
  • 一个主用户可绑定多个子用户；每条主子关系独立维护协议状态与分配比例；同一主用户下所有关系须共用一种分配类型。
  • 右豹ID直接分配：协议已同意 + 分配状态启用即可参与分配；按约定比例将收益打入子用户项目收益钱包，不需要关键词归因，不依赖发布帐号授权。
  • 以发布帐号归因分配：协议已同意 + 发布帐号三方授权有效 + 分配状态启用；出单后按关键词→发布帐号→比例归因分配。
  • 右豹ID直接分配 · 子用户信息 Tab：列表仅展示已分配金额与分配比例；不展示授权帐号；卡片不可点击、无 › 查看详情入口。
  • 代发收益首页分配 record-card 不展示「代发」标签与「不可撤回」说明；与 FR-001 代发分配 C 端展示区分。
  • 发布帐号授权走三方 API 对接，本 FR 不重定义三方授权步骤，仅展示授权结果。
  • 子用户 C 端不提供「我的代发收益」页；收益在项目收益钱包等既有入口查看（本 FR 不重定义）。

4边界规则

  • 代发收益分配记录不可撤回。
  • 协议「已拒绝」时不可参与分配；主用户可重发协议邀请。
  • 三方授权失效后，该发布帐号新出单不参与分配；历史分配记录保留。
  • 分配明细须包含分配时间字段（主/子/export 同步）。
  • 与 FR-001 代发分配：分配引擎复用，关系模型与授权方式独立，同一发布帐号不建议同时参与两套代发（互斥规则待技术确认）。

5业务流程

前后端交互与校验逻辑见页内 Tab 「业务流程」（流程图，含校验节点）。

涉及：协议邀请确认、三方发布帐号授权、关键词出单→分配明细。

1业务目标

为代发收益提供运营/研发可查的数据面：主子分配关系、三方授权发布帐号、代发关键词收益与分配明细，支撑问题排查与对账。

2数据表与字段

主子分配关系表：ID、主用户ID、子用户ID、分配比例、分配类型（右豹ID直接分配 / 以发布帐号归因分配）、协议状态、分配状态、发布帐号数、已分配金额、创建/更新时间；操作：详情、编辑、重发协议。

分配类型说明：

  • 右豹ID直接分配：按约定比例自动将收益分配至子用户项目收益钱包，不需要关键词归因。
  • 以发布帐号归因分配：根据关键词找到发布帐号，再按约定比例进行收益分配归因。

分配类型约束：同一主用户不能同时存在两种分配类型；新增/编辑时若与已有关系类型冲突，须拦截并提示。

列表顶统计区：已分配金额、待分配金额、启用关系、待确认协议（仅 Demo 展示，口径由后端定义）。

协议内容：复用现有说明内容配置（rev_share_agreement），本 FR 不单独设计协议配置页。

主子分配关系 · 详情抽屉：Tab 切换「关系详情」「分配详情」。

  • 关系详情：关系 ID、主/子用户 ID、分配比例、分配类型、协议状态、分配状态、发布帐号数、已分配金额、创建/更新时间。
  • 分配详情（list）：日期、主帐号收益、子帐号分配金额、分配时间、分配归因（项目、关键词、发布帐号三行展示）；列宽紧凑；支持导出 CSV（字段与 list 一致）。「右豹ID直接分配」无关键词/发布帐号归因时，对应字段展示「—」。

发布帐号表：ID、帐号昵称、帐号ID、主页链接、子用户ID、授权主用户ID、三方授权状态、帐号平台、状态、授权时间；操作：日志。

发布帐号数据来源：与三方工具对接接口同步，由三方提供该右豹子帐号下的发布帐号信息数据；本 FR 仅展示与对账，不重定义三方同步协议。

代发关键词表：关键词、项目方、主用户、发布帐号、所属子用户、累计产生收益、累计分配、数据更新时间；操作：详情。

代发关键词统计口径：汇总以关键词归因的相关分配数据（出单→关键词→发布帐号→分配明细）；「右豹ID直接分配」关系不参与本表统计。

关键词详情 list（详情抽屉 · 合并 6 列）：收益金额、收益产生时间、收益结算时间、分配金额、分配时间、分配批次。

分配记录表（扩展字段 · 本需求仅定规则）：分配行为 = 系统自动；业务来源 = 代发收益。

3列表与筛选

主子分配关系筛选：关系 ID、主用户 ID、子用户 ID、协议状态、分配状态、分配类型。

发布帐号筛选：发布帐号 ID、帐号昵称、帐号 ID（平台唯一）、子用户 ID、主用户 ID、三方授权状态、帐号平台、状态、授权时间范围。

代发关键词筛选：关键词、项目方、主用户 ID、子用户 ID、发布帐号 ID/昵称、更新时间范围。

主子关系「详情」抽屉内 Tab 切换；分配详情 list 不挤压列表页宽度，横向滚动展示。

4边界规则

  • 同一主用户下所有主子关系的分配类型必须一致；后台新增/编辑时校验，冲突则拒绝保存。
  • 「右豹ID直接分配」关系不要求发布帐号三方授权；「以发布帐号归因分配」关系须授权有效方可分配。
  • 关键词累计产生收益、累计分配以数据更新时间为准展示。
  • 代发收益分配写入时 分配行为=系统自动，业务来源=代发收益。
  • 三方授权回调失败或超时时，C 端展示授权中/失败状态，不写入有效授权记录。
