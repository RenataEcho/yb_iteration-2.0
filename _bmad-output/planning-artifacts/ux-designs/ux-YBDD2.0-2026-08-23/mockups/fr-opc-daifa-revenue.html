运营手册 · 按章阅读
FR-002 · 代发收益

主用户把一部分项目收益，按约定比例自动分给绑定的子用户

这不是运营手工打款，也不是工作室内部的「代发分配」。主用户先邀请子用户签代发收益协议，子用户同意后，系统在收益已结算时按关系上的分配类型 + 分配比例自动入账：主用户钱包记一笔负数，子用户钱包记一笔正数。分出去的钱不能撤回。

30 秒故事

  1. 主用户在个人中心打开「代发收益」，添加子用户（填写右豹 ID + 分配比例 + 分配类型）。
  2. 子用户收到站内信「代发收益邀请」，在协议页同意或拒绝。拒绝后主用户可以重发。
  3. 协议已同意，且该关系「分配状态 = 启用」后，才具备分配资格。
  4. 主用户项目产生收益并完成结算后，系统自动按比例划给子用户，双方都在「项目收益明细」里看到「收益自动分配」。

三个角色各看什么

主用户（C 端）

个人中心 → 代发收益管理。看分配记录、子用户列表；可添加子用户、重走邀请。全程没有顶部汇总金额。入账/扣款看既有「项目收益明细」（金额为负）。

子用户（C 端）

只有协议确认页。同意或拒绝后流程结束，没有「我的代发收益」子页。钱到账后只在既有「项目收益明细」看正数记录，描述里没有跳转。

运营（管理后台）

查主子关系、协议状态、分配类型、已分配金额；帐号归因类型还要核对发布帐号授权和关键词归因。可新增/编辑关系、重发协议。不能替用户撤回已分配金额。

系统（自动）

出单结算后触发分配。写入分配记录时：分配行为 = 系统自动，业务来源 = 代发收益。不需要运营点确认。

运营对外口径：代发收益是「主子用户之间的自动分账」，必须先签协议；不是客服手工调账，也不是工作室岗位分润（那个叫代发分配）。
容易混 · 先记住这一页

代发收益 ≠ 代发分配

两个需求名字都带「代发」，但服务的人和钱走的路径不同。用户说「代发没分到钱」时，先问清楚是主子协议分账还是工作室成员分润，再进对应后台。

对照项 代发收益（本需求 FR-002） 代发分配（FR-001）
谁和谁分 主用户 ↔ 子用户（协议绑定，可一对多） 工作室负责人 ↔ 代发成员（岗位比例）
怎么发起 主用户邀请 + 子用户签协议 加入工作室 / 岗位配置后自动或负责人主动分
分配方式 仅系统自动。两种类型：右豹 ID 直接分配 / 发布帐号归因 系统自动（岗位比例）+ 负责人可主动分配
能不能撤回 一律不可撤回 代发自动记录不可撤回；负责人主动分配可撤回
C 端有没有「代发」标签 分配信息不展示「代发」标签和「不可撤回」说明 系统自动记录打「代发」标签
子端有没有独立页 没有。子用户只看项目收益明细 成员有分配详情 / 发布帐号等入口
后台怎么认 业务来源 = 代发收益；看「主子分配关系」 分配行为 = 系统自动 / 负责人主动；看工作室与成员
两套能力复用同一套「分配引擎」，但关系模型和授权方式是独立的。同一发布帐号不建议同时参与两套代发；互斥规则待技术确认，客诉时先两边都查一遍，不要只查一张表就下结论。
核心规则 · 必须讲清楚

同一主用户只能选一种分配类型，不能混用

主用户第一次建关系时选定类型，后续再绑子用户必须沿用。后台新增/编辑时若冲突会拦截。运营解释时先问「这个主用户是直接按右豹 ID 分，还是按发布帐号归因分」。

右豹 ID 直接分配

  • 按关系上的比例，把已结算收益打进子用户项目收益钱包。
  • 不需要关键词归因，不依赖发布帐号三方授权。
  • 生效条件：协议已同意 + 分配状态启用。
  • C 端：分配信息不能下钻详情；子用户卡片无授权帐号、不能进详情。
  • 后台：分配归因里关键词/发布帐号显示「—」；不进「代发关键词」表。

以发布帐号归因分配

  • 出单后按 关键词 → 发布帐号 → 比例 归因（口径与代发分配一致）。
  • 必须该发布帐号三方授权有效。
  • 生效条件：协议已同意 + 授权有效 + 分配状态启用。
  • C 端：可下钻分配详情（关键词、分配金额、比例、发布帐号 ID），可看子用户授权帐号（只读）。
  • 后台：走发布帐号表 + 代发关键词表对账。
怎么帮用户选：没有稳定发布帐号、只按人分钱 → 右豹 ID 直接分配。要按哪个号出的单来分、要对到关键词 → 发布帐号归因。

关系先于分钱

没同意协议，一分钱都不会分

协议页复用现有邀请/接受页，本需求不重做、也不单独做协议配置。协议正文走现有配置 rev_share_agreement。一个主用户可以绑多个子用户，每条关系自己维护协议状态和比例。

协议状态

状态含义会不会自动分钱运营可做什么
待确认 邀请已推送，子用户还没处理 不会 可重发邀请；提醒子用户看站内信
已同意 子用户确认协议 还要看「分配状态」是否启用；帐号归因还要授权有效 可编辑比例/状态（类型受主用户锁定）
已拒绝 子用户拒绝，本轮结束 不会 主用户或后台可重发，状态回到待确认
「已同意」不等于马上分钱。关系上还有「分配状态」：只有启用才参与自动分配；禁用后新出单不再分，已经分出去的记录仍保留、不可撤回。

主用户 C 端怎么看关系

  • 分配信息和子用户都为空：不展示 Tab，只出空态「暂无分配信息与子用户」，引导添加。
  • 只要一边有数据：恢复「分配信息 / 子用户信息」两个 Tab；某一边暂时没数据就空列表，不要整页空态。
  • 子用户卡片展示协议状态和时间；待确认的子用户仍会出现在列表里，已分配金额为「—」。
对账口径

结算完成才会分；分配金额 = 该笔总金额 × 关系比例

出单事件先入队，先更新关键词「累计产生收益」。只有收益已结算才触发代发分配。未结算就等待回调，不会提前划走。C 端所有代发收益页都没有顶部汇总条，不要按页面顶部数字跟用户对账。

一笔分配会写到哪里

位置主用户看到子用户看到
项目收益明细（既有页） 标题「收益自动分配」；金额为负；状态「收益分配」；描述「y-m-d产生收益自动分配 xx.xx」，可跳转代发收益管理 同样标题和状态；金额为正；描述没有跳转
代发收益 · 分配信息 卡片：分配金额 / 总金额 / 分配比例 / 分配用户（子用户昵称） / 分配时间 没有这个页面
后台 · 关系详情 · 分配详情 日期、主帐号收益、子帐号分配金额、分配时间、分配归因（项目 / 关键词 / 发布帐号）。直接分配时关键词和帐号为「—」。可导出 CSV。

数字怎么念给用户听

  • 总金额：这一笔已结算的项目收益，还没按比例切开之前的数。
  • 分配金额：按该条子用户关系比例切出去的数，也是主用户明细里那笔负数的绝对值。
  • 分配比例：关系上约定的 1%–99%，每条子用户可以不同，但类型必须相同。
  • 已分配金额（关系/子用户卡片）：该关系累计已成功分配，以数据更新时间为准。
  • 关键词表的「累计产生收益 / 累计分配」只统计帐号归因那一类；直接分配不要跑到关键词表里找。
代发收益分配记录不可撤回。用户要求「分错了退回来」，运营不能在本功能里点撤回；只能解释规则，并走另行约定的客服/财务流程（本需求不提供冲正入口）。
管理后台 · 运营操作面

先查「主子分配关系」，再按类型决定要不要查帐号和关键词

后台三张表职责不同：关系表管「能不能分、分给谁、分多少」；发布帐号表管「授权是否有效」；代发关键词表只管帐号归因的出单归因。列表顶上的已分配/待分配/启用关系/待确认是 Demo 展示，正式口径以后端定义为准。

三张表分别解决什么

表用来回答关键动作
主子分配关系 这两个人有没有绑上？协议到哪一步？哪种类型？比例多少？累计分了多少？ 筛选主/子用户 ID、协议状态、分配状态、类型；详情（关系 + 分配明细）；编辑；重发协议；新增关系
发布帐号 子用户有没有把号授权给这个主用户？授权是否失效？ 按帐号/主子用户/授权状态/平台筛；看授权日志。数据来自三方，后台只展示对账，不在本需求里改授权。
代发关键词 这笔帐号归因的单，关键词、项目、累计收益和累计分配对不对？ 详情看 6 列：收益金额、产生时间、结算时间、分配金额、分配时间、分配批次。直接分配不进本表。

建议排查顺序

  1. 用主用户 ID 或子用户 ID 打开「主子分配关系」，确认关系存在、协议已同意、分配状态启用、类型是哪一种。
  2. 点「详情 → 分配详情」，按日期/金额对那一笔。能对上就先回用户「系统已入账」；对不上再往下查。
  3. 类型是直接分配：不要查关键词表。核对项目收益明细正负是否成对即可。
  4. 类型是帐号归因：再查发布帐号授权是否有效，再查代发关键词详情里的结算时间和分配批次。
  5. 授权失效：该号新出单不再分配，历史记录保留。让用户重新走三方授权，不要承诺补分历史规则外的单。
关系详情里的分配归因三行是项目 / 关键词 / 发布帐号。直接分配缺归因时显示「—」，这是正常展示，不是数据丢失。
客服 / 运营话术

先对身份和类型，再对协议，最后对那一笔钱

用户很少说「FR-002」。他们会说「我帮别人发，怎么没分到钱」「我钱包少了一笔」。按下面清单走，可以独立闭环大部分咨询。

Q1. 子用户说：我同意了，为什么钱包没进账？
先确认他看的是项目收益明细，不是「代发收益」菜单——子用户本来就没有那个入口。再查关系：协议是否已同意、分配状态是否启用。若是帐号归因，再查对应发布帐号是否已授权且未失效。最后问出单是否已结算：未结算只累计、不分钱。
Q2. 主用户说：我钱包突然少了一笔，是不是被扣错了？
项目收益明细里标题为「收益自动分配」、状态「收益分配」、金额为负，就是代发收益划出。描述里的日期和金额应对上代发收益管理的分配信息。这是规则内自动划转，不是异常扣款。
Q3. 子用户找不到「代发收益」页面？
正常。子用户只处理协议邀请，入账只在项目收益明细。不要指导他去个人中心找代发收益管理。
Q4. 协议被拒绝了怎么办？
已拒绝不能参与分配。主用户或后台对该关系「重发协议」，子用户重新收到邀请。重发后状态回到待确认，在同意之前仍然不会分钱。
Q5. 为什么不能给同一个主用户同时建两种类型？
产品规则：一个主用户下所有子用户必须共用一种分配类型，避免同一笔收益按两套管账。后台保存时会拦截。要换类型，需要先处理掉该主用户已有关系（本需求未提供「一键切换类型」）。
Q6. 发布帐号授权失效了，以前分过的钱还在吗？新单还会分吗？
历史分配记录保留，不会因为失效被抹掉。失效之后该帐号的新出单不再参与分配。授权回调失败或超时，C 端只显示授权中/失败，不会写成有效授权。
Q7. 用户要求撤回某一笔分配？
本需求明确不可撤回。C 端也不展示「不可撤回」文案，避免刺激，但后台和客服口径必须一致：系统自动分配没有撤回按钮。分错需走额外财务流程，不要承诺能在代发收益里冲正。
Q8. 关键词表里找不到直接分配的用户？
对。代发关键词表只汇总「以发布帐号归因」的分配。直接分配请只看主子关系和项目收益明细。
Q9. 空态页是坏了吗？
分配信息和子用户都没有时，主用户看到缺省空态、不展示 Tab，这是设计。添加子用户并完成协议后才会出现两个 Tab。只有一边有数据时，另一个 Tab 可以是空列表。
Q10. 和「代发分配」搞混了怎么办？
问一句：是不是工作室里给成员按岗位分的？是 → 代发分配。是不是主号把收益按协议分给另一个右豹账号？是 → 代发收益。两套后台表不同，不要交叉承诺。

对外不要承诺的事

  • 不能撤回、不能在本页手工补发或冲正。
  • 不能把同一主用户改成同时使用两种分配类型。
  • 不能为子用户开通独立的「我的代发收益」管理页。
  • 不能把未结算的出单当成已经分账。
  • 授权失效期间的新单，不能按「以后补授权就自动补分」来承诺（本需求未定义补分）。
页面原型和流程图给研发对照；和用户沟通请只用本 Tab 的口径。规则细节以页头「需求规则」抽屉为准，若两者冲突先记下来再找产品，不要现场发明规则。

操作确认

FR-002 · 需求规则 · v1

1业务目标

在主子用户关系下增加「代发收益」：主用户可绑定多个子用户，经协议确认后按分配类型自动分配——「右豹ID直接分配」按比例打入子用户项目收益钱包；「以发布帐号归因分配」按关键词→发布帐号→比例归因（口径与 FR-001 一致）。

2页面与入口

  • 代发收益管理（主用户）：个人中心入口；全程无顶部数据统计（无 hero / 汇总条，含下钻页）。右上角规则 icon +「添加」；Tab = 分配信息 / 子用户信息。
  • 缺省空态：分配信息与子用户同时为空时不展示 Tab，展示缺省页（插画 +「暂无分配信息与子用户」+ 引导添加）；右上角「添加」与主按钮均进发起协议页。任一 Tab 有数据后恢复 Tab 首页。仅某一 Tab 为空时仍显示 Tab，对应列表为空即可。
  • 分配信息：record-card 标题「分配金额·xxx」+ 灰底五列 = 分配金额、总金额、分配比例、分配用户（子用户昵称）、分配时间。不展示「代发」标签与「不可撤回」说明。发布帐号归因可下钻分配详情；右豹ID直接分配不可下钻。
  • 分配详情（仅发布帐号归因）：关键词作标题；灰底 = 分配金额、分配比例、发布帐号ID；支持导出。
  • 子用户信息：头像卡 + 协议状态/时间。发布帐号归因：已分配金额、授权帐号、分配比例，可进子用户详情。右豹ID直接分配：已分配金额、分配比例，无授权帐号、不可下钻。
  • 子用户详情（仅发布帐号归因）：头像信息卡 + 授权帐号列表（只读）；不提供分配明细 Tab。
  • 项目收益明细（既有页新增记录）：标题「收益自动分配」；状态「收益分配」；时间=分配时间戳。主用户金额为负，描述「y-m-d产生收益自动分配 xx.xx(可前往收益分配页面查看明细)」可跳转代发收益管理。子用户金额为正，描述无跳转。
  • 协议页：发起/接受均复用已实现邀请页，本 FR 不重做。子用户仅此一页，同意/拒绝后流程结束，无「我的代发收益」子页，入账看既有项目收益明细。

3交互规则

  • 一个主用户可绑定多个子用户；每条关系独立维护协议状态与分配比例；同一主用户下所有关系须共用一种分配类型。
  • 右豹ID直接分配：协议已同意 + 分配状态启用即可；按比例打入子用户项目收益钱包，不需要关键词归因，不依赖发布帐号授权。
  • 以发布帐号归因分配：协议已同意 + 发布帐号三方授权有效 + 分配状态启用；出单后按关键词→发布帐号→比例归因。授权走三方 API，本 FR 只展示授权结果。

4边界规则

  • 代发收益分配记录不可撤回。
  • 协议「已拒绝」不可参与分配；主用户可重发邀请。
  • 三方授权失效后，该发布帐号新出单不参与分配；历史记录保留。授权回调失败或超时，C 端展示授权中/失败，不写入有效授权。
  • 与 FR-001：分配引擎复用，关系模型与授权方式独立；同一发布帐号不建议同时参与两套代发（互斥规则待技术确认）。

5业务流程

见页内 Tab 「业务流程」。

1业务目标

为代发收益提供运营/研发可查的数据面：主子分配关系、三方授权发布帐号、代发关键词收益与分配明细，支撑排查与对账。

2数据表与字段

主子分配关系表：ID、主用户ID、子用户ID、分配比例、分配类型（右豹ID直接分配 / 以发布帐号归因分配）、协议状态、分配状态、发布帐号数、已分配金额、创建/更新时间；操作：详情、编辑、重发协议。

分配类型约束：同一主用户不能同时存在两种类型；新增/编辑冲突则拦截。「右豹ID直接分配」不要求三方授权；「以发布帐号归因分配」须授权有效方可分配。

列表顶统计区：已分配金额、待分配金额、启用关系、待确认协议（仅 Demo 展示，口径由后端定义）。

协议内容：复用现有配置（rev_share_agreement），本 FR 不单独设计协议配置页。

详情抽屉：Tab「关系详情」「分配详情」。

  • 关系详情：关系 ID、主/子用户 ID、分配比例、分配类型、协议状态、分配状态、发布帐号数、已分配金额、创建/更新时间。
  • 分配详情（list）：日期、主帐号收益、子帐号分配金额、分配时间、分配归因（项目、关键词、发布帐号三行）；支持导出 CSV。「右豹ID直接分配」无归因时对应字段展示「—」。

发布帐号表：ID、帐号昵称、帐号ID、主页链接、子用户ID、授权主用户ID、三方授权状态、帐号平台、状态、授权时间；操作：日志。数据来自三方工具对接，本 FR 只展示与对账。

代发关键词表：关键词、项目方、主用户、发布帐号、所属子用户、累计产生收益、累计分配、数据更新时间；操作：详情。只汇总以关键词归因的分配；「右豹ID直接分配」不进本表。

关键词详情：收益金额、收益产生时间、收益结算时间、分配金额、分配时间、分配批次。

分配记录表（仅规则）：写入时 分配行为=系统自动，业务来源=代发收益。

3列表与筛选

主子分配关系：关系 ID、主用户 ID、子用户 ID、协议状态、分配状态、分配类型。

发布帐号：发布帐号 ID、帐号昵称、帐号 ID、子用户 ID、主用户 ID、三方授权状态、帐号平台、状态、授权时间范围。

代发关键词：关键词、项目方、主用户 ID、子用户 ID、发布帐号 ID/昵称、更新时间范围。

详情抽屉内 Tab 切换；分配详情 list 横向滚动，不挤压列表页。

4边界规则

  • 关键词累计产生收益、累计分配以数据更新时间为准。
  • 分配成功后同步写入主/子 C 端项目收益明细（主负子正，状态「收益分配」）。
