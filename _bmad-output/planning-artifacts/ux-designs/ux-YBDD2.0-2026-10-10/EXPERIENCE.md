# EXPERIENCE · 商学院优化

`DESIGN.md` 是视觉身份。本文件只写这次增量怎么工作。与 Demo 冲突时，两份 spine 优先。

主人公沿用 2.0 体验里的名字：创作者 **小周**，运营 **李姐**。

## Foundation

两面：创作者手机里的商学院（含现有消息），以及桌面上的学院管理后台。没有新的设计系统。C 端继承 2.0 手机页；后台继承现有学院管理壳。

手机上的商学院、课程详情、消息会挡住底栏。后台是全屏侧栏。

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| 商学院 | 首页标题为「商学院」的学习卡 | 页标题「商学院」。搜索、五个频道、课程或直播列表 |
| 课程详情 | 列表中的图文/视频课，或直播卡正文 | 图文走正文，视频和直播走同一套详情：标题、人数、播放器画面、底部推荐。直播不在画面里播放 |
| 消息 | 首页顶栏现有消息入口 | 开播前 1 小时的站内信 |
| 课程管理 · 知识库 | 后台侧栏「课程管理」 | 沿用知识库说明，不新建图文/视频 CRUD |
| 课程管理 · 学院直播课 | 课程管理页内切换 | 配置直播，不进知识库 |
| 学习数据 | 后台侧栏「学习数据」 | 还原基础学习统计，并计入直播预约 |
| 第三方直播间 | 查看 / 查看回放确认之后 | 飞书、抖音或企业微信，离开本产品 |

频道并列，顺序固定：项目教学、案例拆解、进阶技巧、直播课程、我的学习。直播课程不是分类管理里的一项。「我的学习」仍不是后台分类。

## Voice and Tone

| Do | Don't |
|---|---|
| 预约 | 马上提醒我 |
| 已预约 | 预约成功！ |
| 查看 | 进入直播间 |
| 查看回放 | 观看精彩回放 |
| 没有找到相关课程 | 换个词试试吧 |
| 即将离开右豹，打开飞书 | 正在为您跳转第三方平台 |
| 已预约，开播前 1 小时发送站内信 | 已为您设置提醒 |
| 查看基础学习效果，不建设复杂教务体系 | 数据大屏 |

平台名只使用：飞书、抖音、企业微信。

## Component Patterns

行为。视觉见 `DESIGN.md` 同名组件。

| Component | Use | Behavioral rules |
|---|---|---|
| 学院搜索 | 商学院顶部 | 匹配课名、项目名称、分类。范围是全部频道，包括直播课程和我的学习。输入时不锁在当前频道。清空后回到当前频道的列表。 |
| 课程数据条 | 列表行与课程详情 | 观看人数与收藏人数同时出现。直播卡也出现。收藏人数是多少人收藏了这门课，不随用户自己的收藏按钮加减。观看人数沿用学习数据里的详情 UV，收藏人数沿用学习数据里的收藏。 |
| 直播课程卡 | 直播课程频道 | 封面角标写直播状态：待开始、直播中、直播已结束。直播中的角标带一颗呼吸点。卡片上没有预约、已预约、查看、查看回放。点整张卡打开详情。 |
| 离开应用确认 | 查看、查看回放 | 先写明平台。继续才离开产品并打开该场的直播链接或回放链接。留下则留在当前页。产品内不播放。 |
| 站内信条目 | 现有消息 | 只在开播前 1 小时出现，对象是已预约的人。点开进这场直播的课程详情，不直接跳出产品。 |
| 学院直播课配置 | 课程管理内 | 字段只有课名、项目名称、开播时间、平台、直播链接、回放链接。平台是飞书、抖音、企业微信之一。 |
| 学习数据表 | 学习数据页 | 说明文案固定。列：课程、详情 UV（C 端称观看人数）、学习人数、完成率、收藏（C 端称收藏人数）、直播预约。可按课程名筛选，可按时间或完成率排序。图文完课仍是正文最后一块，视频仍是播放 ≥ 90%。 |

状态不单独配置。`[ASSUMPTION]` 开播时间未到为待开始；已到开播时间且回放链接为空为进行中；已过开播时间且回放链接已填为已结束。

## State Patterns

| State | Surface | Treatment |
|---|---|---|
| 频道默认 | 商学院 | 打开时停在项目教学。直播卡不混进其他频道。 |
| 搜索无命中 | 商学院 | 列表让出，只留「没有找到相关课程」。 |
| 搜索有命中 | 商学院 | 跨频道结果放在一起。同一课名只留一条。 |
| 待开始 | 直播课程卡 / 详情 | 封面角标「待开始」。详情沿用视频课，画面下有一颗「预约」按钮。 |
| 已预约 | 直播课程详情 | 封面仍是「待开始」。详情按钮改为「已预约」，不能再点。站内信尚未发出，除非距开播已不足规则所写的 1 小时窗口且该条已生成。 |
| 进行中 | 直播课程卡 / 详情 | 封面角标「直播中」。详情不放写着平台的按钮，点画面进入，确认层再写明平台。 |
| 已结束 | 直播课程卡 / 详情 | 封面角标「直播已结束」。详情按钮只写「查看回放」。 |
| 链接为空 | 查看 / 查看回放 | 不打开确认层。按钮不可用，文案「暂无法打开」。 |
| 冷启动消息 | 消息 | 没有到期提醒时，消息列表可以为空。不造运营推送。 |
| 学习数据空表 | 学习数据 | 筛选无课程时表体空，说明文案仍在。 |

`[OPEN]` 开播前不足 1 小时才点预约的人，这条站内信还发不发。未定之前，Demo 不补发一条即时消息。

## Interaction Primitives

- 点按完成预约、查看、查看回放、搜索和频道切换。
- 预约成功只改按钮并提示「已预约，开播前 1 小时发送站内信」。不在当时写入消息。
- 查看与查看回放必须先经过离开应用确认。
- 消息里的提醒点开后回到这场直播的课程详情。

## Accessibility Floor

行为。对比见 `DESIGN.md`。

- 搜索框有可访问名称「搜索课名、项目名称、分类」。
- 直播详情按钮只读出：预约、已预约、查看回放。按钮上不写飞书、抖音或企业微信。
- 进行中的呼吸点不作为唯一信息；封面角标写着「直播中」。系统开启减少动效时，呼吸点停住，仍保留红点。
- 频道、搜索、主按钮的点按区域保持现有学院按钮的高度，不缩成只有红点可点。

## Key Flows

### Flow 1 — 小周搜一节课

1. 小周从首页标题为「商学院」的学习卡进入商学院。
2. 在搜索框输入项目名「番茄」。
3. 项目教学和其他频道里课名、项目名称或分类命中的课出现在同一列，并看到观看人数和收藏人数。
4. 他打开「番茄小说发布完整流程」。
5. **Climax：** 详情顶部同样写着观看人数和收藏人数，和他在列表里看到的是同一对数。

失败：输入「没有的课」→ 只见「没有找到相关课程」。清空后回到进入搜索前的频道。

### Flow 2 — 小周预约直播，再从消息回来

1. 小周切到直播课程，看到一场未开始的抖音课。封面上是「待开始」，卡片上已有平台、时间和人数。
2. 他打开详情，点「预约」。按钮变为已预约，并被告知开播前 1 小时才会发站内信。
3. 另一场他早已预约、距开播 1 小时的课，出现在首页顶栏的消息里。
4. 他点开那条消息，进入该课详情。详情和视频课同一套：标题、人数、播放器画面、底部其他直播。画面不播放。
5. 他点画面。确认层写明「即将离开右豹，打开飞书」。他点继续。
6. **Climax：** 人已经到飞书那场直播。产品内的画面只是入口，不是直播间。

失败：他在确认层点留下 → 仍停在课程详情。回放链接为空时，查看回放不可用。

### Flow 3 — 李姐配置一场直播并看学习数据

1. 李姐打开学院管理后台，进入课程管理，切到学院直播课。
2. 她填写课名、项目名称、开播时间、平台、直播链接、回放链接，保存。
3. 她打开学习数据，读到「查看基础学习效果，不建设复杂教务体系」。
4. **Climax：** 同一页能看到这门课的详情 UV、收藏和直播预约，C 端列表上的观看人数、收藏人数与前两项一致。

失败：课名为空不能保存。

## Responsive & Platform

C 端是手机上的商学院。后台是宽屏侧栏；窄于 900px 时侧栏变窄，统计卡改为两列，与现有学院后台相同。直播跳转离开 WebView / 手机浏览器，落到飞书、抖音或企业微信。后台名称仍是学院管理后台，直播配置名仍是「学院直播课」。
