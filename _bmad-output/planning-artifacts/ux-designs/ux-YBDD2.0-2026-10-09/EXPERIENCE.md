# EXPERIENCE · 一键代发 3.0 · 剪辑手 PC

**冲突规则：** 本文件与 [DESIGN.md](DESIGN.md) 优先于旧演示页。旧页是行为底座。本轮口述覆盖这些旧合同：一次上传只有一个项目、一本书；站外稿不选关键词；提示语和推荐文案分成两段；关键词候选只核对书籍 ID、位置在运营模式旁。其余未点名的条款继续有效。

主人公沿用 PRD：周凯是剪辑手。`[ASSUMPTION]` 这一轮只改他的电脑交稿，不改林晓的广场领取，也不改赵敏的后台档案。

## Foundation

- **Form-factor：** 电脑浏览器。入口仍是创作者中心左侧「剪辑供稿」。手机 App 没有交稿口。
- **UI system：** 无独立组件库。控件外观用 DESIGN.md 里从现有剪辑供稿 PC 抽出的令牌。
- **两种交稿：** 「上传稿件」仍是单条任务（一个项目、一本书、一个文件夹或压缩包）。「批量上传」是新任务：先定这一批的共同条件，再用一张表填多本书。

## Information Architecture

| 界面 | 从哪进来 | 做什么 |
|---|---|---|
| 剪辑供稿首页 | 左侧「剪辑供稿」 | 身份、招募、统计；「上传稿件」与「批量上传」 |
| 单条上传 | 「上传稿件」 | 三步不变。书籍分组增加「书籍类型」。书籍链接旁边是关键词。书籍分组下有一个「剪辑师提醒」文本域 |
| 批量上传 · 条件 | 「批量上传」 | 站内或站外、稿件类型；站内再选运营模式和素材类型 |
| 批量上传 · 任务表 | 条件页的「下一步」 | 每行一本书：项目、书籍 ID、链接，链接旁边是关键词（站内帐号运营，以及全部站外行）、类型、名称、剪辑师提醒、文件夹或压缩包 |
| 上传清单 | 开始上传之后，或首页「查看全部」 | 沿用现有清单。批量产生的稿落入同一清单 |

表面闭合：口述的两个需求都落在「单条上传」和「批量上传 · 任务表」。条件页是任务表的必经步骤。清单是提交后的落点，本轮不改列。

## Voice and Tone

微文案沿用现有剪辑供稿：短句、告诉他下一步填什么。品牌语气见 DESIGN.md。

| 这样写 | 避免 |
|---|---|
| 输入后回车添加 | 请在此输入您的书籍类型！ |
| 先定这一批，再逐行填书 | 开启高效批量之旅 |
| 这个项目的这本书还没有你在右豹侧审核通过的关键词 | 关键词校验失败 |
| 先填项目和书籍 ID | 请完善必填项后再选择关键词 |
| 给领取的人留一句提醒 | 请输入提示语和推荐文案 |
| 解压中 | 正在为您处理压缩包，请稍候 |
| 填完每一行再上传 | 存在未完成项，请检查表单 |

## Component Patterns

行为规则。外观见 DESIGN.md 的书籍类型字段、批量弹窗、行内成片。

| 控件 | 用在哪 | 规则 |
|---|---|---|
| 书籍类型 | 单条上传的书籍分组；批量任务表每一行 | 单行文本。输入法上屏后的回车，把去掉首尾空格的文字收成一枚芯片，并清空输入。可连续添加。点芯片「×」去掉该枚。输入为空时回车无动作。与已有芯片完全相同的文字不再添加，提示「这个类型已经加过」。组字过程中的回车不添加 |
| 运营模式 | 单条上传（站内）；批量条件（站内） | 只有两个值：任务协作、帐号运营。候选只有周凯档案里已勾选并写了比例的模式。站内的任务协作不出现关键词。站内的帐号运营必须选一个关键词。站外不选运营模式 |
| 稿件去向 | 批量条件；单条上传沿用清单上的站内/站外切换 | 两个值：站内、站外。`[ASSUMPTION]` 「站内」写入今天清单里的「右豹」渠道。站外不进广场 |
| 关键词 | 站内帐号运营的单条上传和批量行；全部站外的单条上传和批量行。位置在书籍链接旁边，同一行 | 下拉单选，不手填，一次只能选 1 个。候选同时满足三件：当前这名剪辑师、当前所选项目、当前书籍 ID，且申词状态已通过。项目和书籍 ID 都有了才出候选。换项目或改书籍 ID 后清空重选。别人的词、未通过的词、别的项目或别的书的词，不出现。站内任务协作不出现这一格，书籍链接独占一行 |
| 剪辑师提醒 | 单条上传的书籍分组下方；批量任务表每一行 | 一个文本域，标签就是「剪辑师提醒」。不再出现「提示语」「推荐文案」两个输入。`[ASSUMPTION]` 可以空着提交。单条这一次解析出的稿共用这一段；批量该行解析出的稿共用这一段。用户侧稿件详情切到「剪辑师提醒」时，只展示这一段文字 |
| 任务表 | 批量第二步 | 一行一本书。行内项目只列已授权且启用的项目。关键词列紧挨书籍链接列。每行自己选文件夹或压缩包。解析规则与单条相同：图集一个文件夹一条，视频一个文件一条，文件名（或组文件夹名）作标题。同一行解析出的多条稿，共用该行的项目、书、书籍类型、运营模式、关键词和剪辑师提醒 |
| 行操作 | 任务表底部与行尾 | 打开时一行空行。「添加一行」再加空行。多于一行时可删行 |

`[ASSUMPTION]` 书籍类型自由文本，没有预设枚举。至少一枚才能离开当前步。输入为空时，退格删掉最后一枚芯片。不设枚数上限。粘贴进来的文字要再按一次回车才变成芯片，一次回车只收成一枚。

`[ASSUMPTION]` 站外不展示运营模式和素材类型，也不走书籍 ID / 链接 / 海外任务库的命中校验。站外要选关键词，候选仍是当前剪辑师、当前项目、当前书籍 ID 下已通过的词，放在该行书籍链接旁边。站外行仍填项目、书籍名称、书籍 ID、书籍链接、书籍类型、剪辑师提醒，并可选文件夹或压缩包。这和现有站外「只收文件夹、不要素材类型、不选词」相比，多了书籍类型、关键词和剪辑师提醒，并允许压缩包。

`[ASSUMPTION]` 站内每一行仍要过系列校验：字节系命中书籍 ID，知乎系命中书籍链接，海外系命中海外任务库。书名、书籍 ID、书籍链接、书籍类型都必填。没有系列的项目不能提交。

`[ASSUMPTION]` 批量没有第三步「确认上传」。选完包后，该行下方展开解析条数和标题。站内展开里可以改发布技巧，或对该行点一次「AI生产发布技巧」。全部行解析成功后，底栏「开始上传」才可点。

## State Patterns

| 状态 | 出现在 | 表现 |
|---|---|---|
| 未录入或已停用 | 首页两个入口 | 沿用现有拦截：不能打开上传，也不能打开批量 |
| 书籍类型为空 | 单条点下一步；批量点开始上传 | 停在原处，提示「请添加书籍类型」 |
| 项目或书籍 ID 还没填 | 关键词格 | 先不给候选。格内写「先填项目和书籍 ID」 |
| 站外或帐号运营无词可选 | 关键词格 | 格内写「这个项目的这本书还没有你在右豹侧审核通过的关键词」。该行不能参与提交 |
| 解压中 | 该行成片格 | 文案「解压中」。这一行不能改包，其它行可以继续填。解压完成前不能开始上传 |
| 有行未填完或未解析 | 点开始上传 | 整批不提交。停在第一处缺项，指出是哪一行、哪一格 |
| 上传中 / 失败 | 上传清单 | 沿用现有状态。失败只重传失败文件 |
| 条件改掉之后 | 从任务表返回条件再下一步 | 站内离开帐号运营时，各行关键词清空并收起该列。改成站外时，收起运营模式和素材类型，关键词列保留；已选词若仍在候选里就留着，不在就清空 |

`[ASSUMPTION]` 有一行不完整时，整批都不上传，不把已经填好的行先送走。

## Interaction Primitives

- 书籍类型只认回车添加，不认逗号、空格或失焦。
- 中文输入法未上屏时，回车交给输入法。
- 批量条件用「下一步」进入任务表；任务表用「上一步」回到条件，已填的行保留。
- 关闭弹窗：有未提交内容时先问「放弃这次填写？」。确认后丢弃，不产生稿件。
- 开始上传后关闭弹窗，清单里能看到这批新行，状态先是「上传中」。
- 鼠标点选是主路径。书籍类型的回车、芯片删除、表格横向滚动必须能用键盘完成。

## Accessibility Floor

- 两个弹窗保持 `role="dialog"`，标题就是步骤名称。
- 书籍类型输入有可见标签「书籍类型」。每枚芯片的删除按钮名称为「移除{类型名}」。
- 焦点环使用现有橙色描边，键盘走到输入、芯片删除、行按钮时都可见。
- 任务表用真正的表头。缺项提示除了单元格旁的短句，再在弹窗底部用一段文字复述「第 N 行，书籍类型还空着」，供读屏读到。
- 对比度沿用 DESIGN.md 的橙与墨，不在这一轮改色。

## Key Flows

### 流程 1 — 周凯给单条上传加上多个书籍类型

1. 周凯在电脑打开剪辑供稿。身份行是他的昵称、右豹 ID 和分成。他点「上传稿件」。
2. 第一步仍选项目、图集或视频，并填写书名、书籍 ID、链接和书籍类型。书籍链接旁边，站内帐号运营以及站外，再选一个词：只列出他自己、这个项目、这本书已经通过的关键词，一次一个。书籍分组下面有一个「剪辑师提醒」文本域，他写一句给领取人的话，也可以空着。
3. 在「书籍类型」里输入「都市」，回车，出现一枚芯片。再输入「重生」，回车，第二枚排在后面。
4. 他选文件夹，确认解析出的标题，点「开始上传」。
5. **高潮：** 清单里这批稿的书籍信息带着「都市」「重生」两枚类型，项目和书与他刚填的一致。
6. 他关掉弹窗去清单看上传结果。失败的文件仍只重传失败项。

失败：一枚类型都没加就点下一步，停在书籍类型，文案「请添加书籍类型」。

### 流程 2 — 周凯一批交三本帐号运营的站内书

1. 周凯点「批量上传」。条件页选站内、帐号运营、视频、一种启用中的素材类型，点下一步。
2. 表上三行。每行选各自的项目，填书籍 ID、链接、书名，并用回车加上该书的书籍类型。关键词格紧挨该行的书籍链接，只列出他自己、这一行的项目、这一行的书籍 ID 已经通过的词，每行选一个。每行还有一个「剪辑师提醒」文本域。
3. 每行选一个文件夹或一个压缩包。压缩包那一行先显示「解压中」，解完展开标题列表。
4. **高潮：** 三行都解析成功后他点「开始上传」。清单一次多出这三本书的稿，运营模式都是帐号运营，每条稿的关键词是该行选中的那一个。
5. 之后领取侧仍按帐号运营：用户不选词，用的就是周凯在这一行绑上的词。

失败：第二本书在这个项目下没有他已通过的关键词。该行不能提交，整批停住，第一行和第三行的填写还在。

### 流程 3 — 周凯改口，这批改成任务协作

1. 他在任务表点上一步，运营模式改成任务协作，再下一步。
2. 关键词列消失，刚才选的词被清掉。项目、书、书籍类型和已选的包还在。
3. **高潮：** 开始上传后，这批稿是任务协作，上面没有绑定关键词。用户领取时仍要自己选和书一致的已通过词。

失败：他的档案没开任务协作。条件下拉里没有这一项，他留在帐号运营，或关掉批量。

### 流程 4 — 周凯交一批站外稿，词用他自己在右豹通过的

1. 周凯点「批量上传」，去向选站外，稿件类型选图集。这一页没有运营模式，也没有素材类型。
2. 任务表每一行的书籍链接旁边仍要选关键词。下拉里只有他自己、该行项目、该行书籍 ID 已经通过的词，一次一个。他为两行各选一个，并各自上传文件夹。每行的剪辑师提醒可以各写一句。
3. **高潮：** 开始上传后，站外清单里这两本书的稿都带着他选中的词。稿仍不进广场，用户侧不走站内领取。
4. 他回到条件把去向改成站内、任务协作。关键词列收起，刚才选的词清掉；书和包还在。

失败：某个词只在别人名下通过，或还在右豹侧待审核。候选里没有它，这一行不能交。

## 待确认的假设

这些假设已经写进上面的规则。改口就改稿，不必先补文档。

1. 「站内」等于现有「右豹」渠道；清单页的「右豹 / 站外」文案这一轮不改。
2. 站外不选运营模式和素材类型；站外允许压缩包；站外也要书籍类型。站外要选关键词，这一条已按口述定下。
3. 关键词放在书籍链接旁边，单选，不手填，一次一个。候选是当前剪辑师、当前项目、当前书籍 ID 下已通过的词。这一条已按口述定下。
4. 书籍类型必填、自由文本、回车添加、至少一枚。
5. 一行一本书、一个包；包内仍按旧命名解析成多条稿。
6. 批量两步走完即上传；有一行不完整则整批不交。
7. 单条上传的三步、审核、占用、删除期限都不在这轮重做。
8. 剪辑师提醒可以空着提交。单条上传一段，批量每一行一段，解析出的稿共用。用户侧「剪辑师提醒」只展示这一段。若批量不需要这个字段，改这一条即可。
